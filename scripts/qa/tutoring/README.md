# Репетиция пути ученика

Локальный прогон открывает два новых потока в одноразовой LMS своего worktree. Для каждого из 56 занятий он проверяет доступ к PDF и трем видам чтения по каждому из 84 назначений, отправку ссылки, приемку и уровень доступа следующей встречи. Для первой работы каждого потока проверяются комментарий, доработка и повторная отправка. В конце ученик открывает материалы после выпуска и после архивирования потока.

Понадобятся соседний каталог bootcamp с пакетом dist-v9, методички и локальные репозитории практических работ. Сначала из корня worktree запустите штатный сервер командой `node scripts/e2e-server.mjs`. Он мигрирует и заново наполняет свою локальную тестовую базу. Дождитесь HTTP 200 на `/api/health`. Затем в другом терминале этого же worktree выполните `pnpm exec tsx scripts/qa/tutoring/journey.mjs`. При повторном полном прогоне начните со свежей тестовой базы. Учетные записи, рабочий ключ, учебный GitLab и адрес LMS этого сценария только локальные. Если в окружении вместо установленного браузера доступен Playwright из локального контейнера, задайте TUTORING_QA_BROWSER_WS с адресом ws://127.0.0.1 на его порт. На отдельно поднятом сервере слота скриншотов используйте параметр --visual-port. Путь к зафиксированной для проверки копии редакции можно передать в TUTORING_QA_EXPORT.

Браузер входит под двумя отдельными учениками и наставником. Учебный ответ исполнителя проверяет выдачу на сохраненный адрес ученика, отдельную группу программы и применение настоящих прав в LMS. Локальная карточка запроса на слияние показывает идентификаторы подготовленных коммитов, связанные с этапами встречи. Это модель GitLab: почтовая доставка, права на настоящем GitLab и результат доверенного раннера проверяются отдельно. Временная папка отчета содержит результат каждого занятия и итог по потокам.

## Прогон на рабочем портале

После личного подтверждения владельца укажите в журнале проверки два принадлежащих тестировщику адреса с доступом к входящим письмам, два новых тестовых потока, программу и время вводной. Каждый поток рассчитан ровно на одного тестового участника. Проверьте в LMS, что эти адреса свободны, а в GitLab по ним еще нет учетных записей. Реальными учениками пользоваться нельзя. У двух тестовых пользователей должен быть обычный доступ по назначению.

1. На рабочем портале создайте тестовые аккаунты и два черновика. Укажите даты бесплатных вводных. Войдите как каждый ученик до зачисления: чужой поток и прямой адрес его PDF закрыты. Добавьте принадлежащие тестировщику аккаунты и откройте потоки.
2. Дождитесь настоящего письма GitLab, задайте пароль через штатный вход и откройте личный приватный проект из карточки LMS. Запишите время, ID проекта и группу. По очереди откройте вводную, первую лекцию и ссылки на теорию, практикум и самопроверку. Для вводной отсутствуют начисление и форма сдачи.
3. Подготовительная пробная сдача проверяет доступ к личному проекту и видимость ссылки у наставника. У автоматических проверок основных работ номера от 1 до 20. Для каждой технической встречи наставник открывает очередное занятие. Ученик выполняет входящие в него задания, создает ветку по условиям практикума и отправляет изменения в свой проект. В GitLab откройте запрос на слияние в назначенную заданием целевую ветку. Запишите ID запроса и SHA фактической версии. Материалы эталонного репозитория, секреты и закрытые проверки не копируйте в учебные проекты. При двух этапах за встречу сделайте обе требуемые работы и приложите связанные ссылки и результаты к одному отправленному запросу. Отметьте по отдельности факт проверки каждого этапа.
4. Сдайте ссылку через форму ученика, дождитесь вердикта штатной проверки и отдельно сохраните решение наставника. Для первой работы каждого курса верните ее на доработку, внесите исправление в исходную ветку и повторите сдачу. В отчете храните ID потока, участника, встречи и запроса, SHA, статусы и результат повторного входа ученика. При ошибке выдачи, отсутствии письма или вердикта приведите точный наблюдаемый результат.
5. Повторите для всех 32 и 24 технических встреч. В финале сверяйте 42 назначения на каждый трек. Через кабинет наставника завершите обучение только двух тестовых участников. Архивируйте только эти два тестовых потока. После нового входа проверьте библиотеку, PDF первой и последней встречи, практикумы и отсутствие доступа к чужим потокам, PPTX и заметкам наставника. Повторно проверьте, что рабочие потоки других учеников сохранили прежние статусы и прогресс.

Снимки писем и доказательства сдач должны исключать пароли, одноразовые ссылки и персональные данные других участников. Признак «Принято» подтверждает решение наставника. Результат проверки в GitLab требует отдельной ссылки на доверенный вердикт на тот же SHA.
