## 1. Обязательный прогон

```bash
pnpm smoke     # lint + typecheck + test + build, в этом порядке
```

Порядок не случайный: линтер и типы отрабатывают за секунды, сборка — минуты. Запускать сборку первой значит долго ждать, чтобы узнать про неиспользованный импорт.

Если нужно по частям:

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

## 2. Миграции Payload

`src/payload.config.ts` передаёт `prodMigrations: migrations` — миграции применяются **на старте контейнера**. Неприменившаяся миграция роняет прод, а не откладывается до ручного запуска.

- Изменил схему коллекции — миграция создана (`pnpm payload migrate:create`) и лежит в `src/migrations/`?
- Новая миграция экспортирована из `src/migrations/index.ts`? (проверяется тестом `tests/smoke/collectionsRegistered.smoke.test.ts`, но убедись, что тест прогнан)
- Миграция совместима с уже работающим кодом? Прод переживает момент, когда новая схема уже применена, а старые контейнеры ещё отвечают — удаление колонки в один шаг ломает этот промежуток. Схема expand-contract: сначала добавить, потом переключить код, потом удалить отдельным выкатом.
- Проверил на копии прод-БД, а не на пустой локальной? (туннель — `docs/seed-production.md`)

## 3. Переменные окружения

- Появилась новая переменная — добавлена в `.env.example`, `docker-compose.yml` **и** в Dokploy UI? Пропуск любого из трёх мест даёт молчаливый дефолт в рантайме.
- `NEXT_PUBLIC_*` прокинута как `ARG` в `Dockerfile`, а не только в `environment`? Она инлайнится в клиентский бандл при сборке; переданная только в рантайме, она превращается в `undefined` в браузере.
- Значения по умолчанию в `docker-compose.yml` (`${VAR:-default}`) безопасны, если переменная не доедет?
- **Менял `DB_PASSWORD`?** Одного деплоя мало: `POSTGRES_PASSWORD` действует только при первичном
  `initdb`, на живом томе он игнорируется. Пароль роли `lms` нужно менять отдельным `ALTER ROLE`,
  иначе прод отваливается от БД и Traefik отдаёт 404 на всех страницах — процедура в
  `docs/db-password-rotation.md`.

## 4. Docker

```bash
docker build -t lms-check .
docker build -t lms-landing-check ./landing
```

Локальная сборка проходит, а докерная нет — чаще всего расходятся версии Node: в контейнере своя база, и `engines` из `package.json` её не контролирует.

## 5. Секреты

```bash
git status --short                       # нет .env, media/, случайных дампов
git diff --cached                        # в коммите только то, что нужно
grep -rniE "(password|secret|token|api[_-]?key)\s*[:=]\s*['\"]" src/ | grep -v process.env
```

Последняя команда должна возвращать пусто: любой секрет берётся из `process.env`, не из литерала.

## 6. Ресурсы прода

Сборка идёт на сервере, где уже крутятся два чужих стека. Перед выкатом:

```bash
ssh root@217.199.254.38 'free -h; df -h /'
```

Меньше ~2 ГБ свободной памяти — сборка Next+Payload рискует словить OOM (лимит heap в `Dockerfile` — 2048 МБ). Тогда собирай образ локально и выкатывай через registry.
