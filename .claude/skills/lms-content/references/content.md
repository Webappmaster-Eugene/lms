# Учебный контент и настройки

Источники: `Courses.ts`, `Sections.ts`, `Lessons.ts`, `Guides.ts`, `FaqItems.ts`, `Media.ts`
в `src/payload/collections/`, блоки `src/payload/blocks/`, global
`src/payload/globals/SiteSettings.ts`.

- Курс требует `title` и ID `roadmap`, раздел — `title` и ID `course`, урок —
  `title` и ID `course`. Необязательная `section` урока должна принадлежать
  тому же курсу: сам relationship не гарантирует соответствие двух родителей.
- `order` курса задаёт порядок в роадмапе, раздела — в курсе, урока — в разделе.
  Для вставки между записями предварительно прочитай их порядок.
- У курса, раздела, урока и роадмапа отдельные `isPublished`, по умолчанию false.
  Не публикуй цепочку из-за правки одного текста. Для публикации программы
  проверь все флаги и связи. Сам REST не объединяет записи в транзакцию.
- При переименовании явно передай старый `slug` вместе с `title`: `generateSlug`
  может сгенерировать новый slug при PATCH только названия. Изменение URL —
  отдельное поручение.
- `description` курса — Lexical JSON. `content` урока — массив блоков `text`,
  `video`, `image`, `link`, `miro`, `file`, `slides`. Текстовый блок:
  `{ blockType: 'text', content: <Lexical JSON> }`. Строка/Markdown не заменяют
  Lexical; минимальный образец — `lexical` в `tests/integration/helpers/fixtures.ts`.
- Код в тексте: отдельного блока кода в редакторе LMS нет. Абзац, целиком набранный
  форматом «код» (текстовые узлы с `format: 16`, строки через `linebreak`, отступы
  обычными пробелами), ученик видит листингом с сохранёнными отступами; код внутри
  предложения остаётся в строке. Узлы `code` и `horizontalrule` делают текстовый блок
  нередактируемым в «Управлении» — при импорте их не создавай.
- PATCH массива `content` заменяет его целиком. При добавлении блока прочитай
  старый массив и сохрани прежние элементы и ID. Так же поступай с другими
  массивами. Файл сначала загрузи в `media`, затем используй его ID в upload-поле.
- Презентация: `{ blockType: 'slides', title, description?, folderUrl?, items? }`,
  в `items` — `{ url, caption? }`. Картинки листаются как слайды, PDF —
  постранично, прочие файлы ученик скачивает. Пустой `items` с `folderUrl`
  сервер при сохранении заполняет файлами папки Диска по порядку имён (подпапки
  и видео пропускаются); чтобы перечитать папку, сохрани блок с `items: []`.
  `url` — файл Диска или `/api/media/file/<encodeURIComponent(filename)>` для
  файла, загруженного в `media`; `fileName` сервер вычисляет сам. Гайд, который
  должен открываться всегда, загружай в `media`: хранилище Диска периодически
  не отдаёт часть файлов. Адрес файла бери из ответа Диска, а не набирай: в путях встречается
  разложенная «й», и набранная строка даст 404. Подробности — `docs/slides.md`.
- Для импорта используй `/admin/import-yandex` и существующий API. Создание
  записи в `yandex-disk-imports` само по себе не импортирует курс.
- FAQ: `question`, Lexical `answer`, `order`, `isPublished`. По умолчанию он
  опубликован — для черновика явно задавай false. `/help` фильтрует публикацию,
  но REST-access коллекции разрешает публичное чтение даже черновиков;
  этот флаг не обеспечивает конфиденциальность ответа.
- Гайд (`guides`) — самостоятельная инструкция вне курсов: `title`, `summary` (до 300
  символов, видна в карточке и описании страницы), текст `markdown`, `order`,
  `isPublished` (по умолчанию false). Гайд — один `.md`-файл с необязательной шапкой:
  ```md
  ---
  title: Название
  summary: Одна-две фразы для карточки
  slug: interview      # без него — из названия; у существующего гайда адрес не меняется
  order: 7
  published: true      # без него — как было (новый гайд — черновик)
  ---
  ## Раздел            ← «##» в корне текста строят оглавление
  ```
  Хук `applyGuideFile` раскладывает шапку по полям, если `markdown` пришёл с ней, и
  убирает её из текста; первая строка `# …` у гайда без названия становится названием.
  Публиковать — `pnpm guide:publish <файл.md>` (создаёт или обновляет по slug из шапки,
  иначе по точному названию; `LMS_URL`, `LMS_ADMIN_EMAIL`, `LMS_ADMIN_PASSWORD` только из
  env) или в CMS кнопкой «Загрузить .md». Рендер — GFM без сырого HTML: таблицы, цитаты-
  врезки, код с подсветкой по языку блока. Ученик скачивает гайд на
  `/guides/<slug>/download` (тот же доступ, что у страницы) и кладёт в «Сохранённое»
  (`bookmarks.guide`). Lexical `content` остался у гайдов, созданных до Markdown: он
  используется, пока `markdown` пуст; такой гайд не скачивается.
  Доступ к обучению гайды не открывает: ученик видит
  опубликованный гайд только при `users.guidesAccessMode: 'all'` (по умолчанию
  `assigned`) или по назначению `learning-access-grants` с `target.relationTo: 'guides'`;
  `deny` закрывает гайд и в режиме «все». Выдавать удобнее в «Доступ к обучению» или
  через `PUT /api/manage/learning-access` (поле `guidesMode`, правило на гайд).
  Публикация гайда сама его никому не открывает. Черновик видит только администратор,
  в том числе на `/guides/<slug>`.
- Настройки — global `site-settings`: изменение REST через POST
  `/api/globals/site-settings`, Local API через `updateGlobal`. При правке
  одного контакта сохрани остальные поля `contacts` и не затронь `points`.
- Удаление урока очищает связанные данные. Если нужна временная недоступность,
  снятие с публикации обычно сохраняет историю лучше удаления.

Просмотр: `/courses/<slug>`, `/lessons/<slug>`, `/guides`, `/guides/<slug>`, `/guides/<slug>/download`, `/saved`, `/help`, `/contacts`.
Обычное управление учебной программой выполняется в самой LMS:
«Управление → Учебный контент → роадмап → курс → программа». Со страницы
карты — «Курсы и уроки» / «Добавить курс»; из темы — «Добавить курс в тему».
Страницы редакторов: `/manage/courses/new`, `/manage/courses/<id>`,
`/manage/courses/<id>/settings`, `/manage/lessons/new?course=<id>&section=<id>`,
`/manage/lessons/<id>`. Контент с черновиками доступен только администратору.
API редакторов — `POST /api/manage/content/<collection>` и
`PATCH /api/manage/content/<collection>/<id>`: Payload auth admin, native поля,
`expectedUpdatedAt` для обновления; при создании `Idempotency-Key` UUIDv4
обеспечивает безопасное повторение неизменённого запроса. С ключом адрес
генерируется автоматически; пользовательский slug задаётся после создания.

CMS — «Управление → CMS и настройки», расширенные коллекции в
«Настройки контента в CMS», FAQ/контакты в «Общение и настройки».
Редактирование: `/admin/collections/<collection>/<id>`.
