# Тренажёр

Источники: `src/data/trainer/`, `src/seed-trainer.ts`, коллекции `TrainerTasks.ts`
и `TrainerTopics.ts`, `src/server/trainer/sandbox.ts`, `docs/trainer.md`.

- Задачу из `TRAINER_CATALOG` меняй в соответствующем файле `src/data/trainer/`:
  следующий `pnpm seed:trainer` перезапишет её CMS-поля из каталога. Сохраняй
  slug, чтобы сидер сохранил ID и прогресс. Новую тему экспортируй в `index.ts`.
- Задача вне каталога может редактироваться через Payload, если пользователь
  выбрал такой способ. Сидер её не удаляет; в исходниках сама она не появится.
  Укажи выбранный источник изменения в отчёте.
- Условие — `descriptionMd`, шаблоны — `starterCode`/`starterCodeTs`, эталоны —
  `solutionCode`/`solutionCodeTs`. Для `unit` нужны `testCases` и/или `testCode`,
  `entryName` при вызове функции; для `types` — `typeHarness`, для `stdout` —
  `expectedOutput`. Точные поля проверяй по текущим типам и коллекции.
- Эталон должен проходить все проверки на каждом объявленном языке, шаблон —
  не проходить. Для документа используй `runSolution` из `sandbox.ts`,
  для каталога — `pnpm exec vitest run tests/unit/trainer/catalog.test.ts`.
  Тест каталога не доказывает, что изменения уже попали в БД.
- `pnpm seed:trainer` с явно выбранной БД — массовый upsert всего каталога.
  Не запускай его на проде ради демонстрации. Следуй актуальному коду и
  процедуре CLI/миграций; не удаляй `payload_migrations` автоматически по
  старому совету из документации.
- Ученик не получает эталон и скрытые данные тестов. Не расширяй access
  ради удобства скилла. Проверяй выдачу отдельным ученическим запросом.
- Прохождение подтверждает только `POST /api/trainer/submit` и серверный изолят.
  Не выставляй `user-trainer-progress.isCompleted` вручную. `runSolution`
  проверяет задачу, но не начисляет прогресс пользователю.

## SQL-темы и курс «SQL и PostgreSQL с нуля»

- SQL-задачи живут в `src/data/trainer/sql/` (темы категории `sql`, язык `sql`,
  `checkMode: 'program'`), уроки курса - в `content/sql-course/`. Формат и правила
  автора - `content/sql-course/README.md`, устройство проверки - раздел SQL в
  `docs/trainer.md`. После правки задачи: `pnpm sql:check --topic <тема>`, затем
  `pnpm trainer:sql-expected` (ожидаемые таблицы закоммичены, тест ловит расхождение).
- В LMS SQL-темы и курс попадают только скриптами, не `seed:trainer`:
  `pnpm sql:publish-trainer` (только темы категории sql и их задачи), затем
  `pnpm sql:publish-course` (курс, разделы, уроки одним markdown-блоком). Оба берут
  `LMS_URL`, `LMS_ADMIN_EMAIL`, `LMS_ADMIN_PASSWORD` из окружения, сначала запускай с
  `--dry-run`. Новое создаётся черновиком, `--publish` публикует. Повторный запуск меняет
  только изменившееся и сохраняет ID; чужие записи в SQL-темах и курсе скрипты не
  удаляют, а перечисляют. Markdown-блоки уроков в «Управлении» не правятся: правка урока -
  это правка файла в `content/sql-course/` и повторный `sql:publish-course`.
- У SQL-тем `assignedOnly` («Только по назначению»): режим тренажёра «весь
  тренажёр» и витрина каталога их не открывают, открывает только правило `allow` на
  тему или задачу. Курс тоже `assignedOnly`. Поэтому ученику курса выдай оба
  назначения: курс `sql-postgresql` и каждую SQL-тему тренажёра (или нужные задачи).
  Одно назначение курса тренажёр не открывает, и ссылки «Практика» в уроках дадут 404.
  Флажок не снимай: скрипты публикации откажутся работать с открытым курсом или темой.
- Проверка выдачи: под учеником `GET /api/trainer-topics?where[category][equals]=sql`
  возвращает только назначенные темы, `/courses/sql-postgresql` открывается, у ученика
  без назначений обе выдачи пусты.

Просмотр: `/trainer/<topic-slug>/<task-slug>`. Меню: «Управление →
Управление тренажёром → Темы / Задачи тренажёра».
