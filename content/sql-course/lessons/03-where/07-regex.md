LIKE умеет немного: «любое число символов» и «один символ». Когда нужен более сложный образец, например «буквы, потом дефис, потом ровно четыре цифры», используют регулярные выражения. Это короткий язык описания шаблонов текста, который есть в большинстве языков программирования. PostgreSQL поддерживает его через операторы сравнения.

## Четыре оператора

Операторов четыре. Два из них ищут совпадение, а два проверяют его отсутствие:

| Оператор | Значение |
|---|---|
| `~` | совпадает, регистр учитывается |
| `~*` | совпадает, регистр не учитывается |
| `!~` | не совпадает, регистр учитывается |
| `!~*` | не совпадает, регистр не учитывается |

В MySQL эту работу выполняют REGEXP и RLIKE (это синонимы). В PostgreSQL этих слов нет, зато есть операторы-значки. Результат для строки либо истина, либо ложь, либо NULL, если сама строка NULL.

```sql run=empty
SELECT code,
       code ~ 'sale' AS tilde,
       code ~* 'sale' AS tilde_star,
       code !~ 'sale' AS not_tilde,
       code !~* 'sale' AS not_tilde_star
FROM (VALUES ('sale_5'), ('SALE10'), ('welcome')) AS t(code);
```

## Совпадение в любом месте строки

Принципиальное отличие от LIKE и SIMILAR TO: регулярное выражение ищется где угодно внутри строки. `code ~ 'sale'` истинно, если слово есть в любом месте, как `LIKE '%sale%'`. Чтобы привязать совпадение к началу или концу, используют якоря: `^` означает начало строки, а `$` конец.

```sql run=empty
SELECT code,
       code ~ 'SALE' AS anywhere,
       code ~ '^SALE' AS at_start,
       code ~ 'SALE$' AS at_end
FROM (VALUES ('SALE10'), ('BIG_SALE'), ('SALES')) AS t(code);
```

## Что можно писать в выражении

Основной набор конструкций почти не отличается от других языков. Точка заменяет любой символ. Квадратные скобки задают набор: `[0-9]` любая цифра, `[A-Z]` заглавная латинская буква, `[abc]` одна из трёх букв, `[^0-9]` любой символ, кроме цифры. Повторения задаются так: `*` ноль и больше раз, `+` один и больше, `?` ноль или один, `{3}` ровно три, `{2,4}` от двух до четырёх. Вертикальная черта означает «или», круглые скобки группируют части.

```sql run=empty
SELECT code, code ~ '^[A-Z]{3}-[0-9]{4}$' AS valid
FROM (VALUES ('ABC-1234'), ('AB-1234'), ('abc-1234'), ('ABC-12345')) AS t(code);
```

Выражение читается так: от начала строки ровно три заглавные буквы, дефис, ровно четыре цифры, конец строки. Из четырёх кодов подходит только первый.

Для частых классов есть короткие записи с обратной косой чертой. `\d` цифра, `\w` буква, цифра или подчёркивание, `\s` пробельный символ (пробел, табуляция, перенос строки), а заглавные `\D`, `\W`, `\S` означают обратное. Границу слова задаёт `\y`:

```sql run=empty
SELECT phrase,
       phrase ~ '\ycat\y' AS word_cat,
       phrase ~ 'cat' AS substring_cat
FROM (VALUES ('a cat sat'), ('concatenate'), ('cat')) AS t(phrase);
```

Слово `cat` внутри `concatenate` находится простым выражением, но не находится с границами слова. В обычных строках PostgreSQL обратная косая черта хранится как есть, поэтому писать `'\d'` можно без удвоения. В MySQL приходится писать `'\\d'`.

## Регистр и отрицание

Для поиска без учёта регистра используют `~*`:

```sql run=empty
SELECT code
FROM (VALUES ('Sale-10'), ('sale-15'), ('WELCOME'), ('VIP-SALE')) AS t(code)
WHERE code ~* 'sale|vip';
```

Отрицание `!~` удобно, когда нужно исключить строки с запрещёнными символами. Например, оставить только коды без пробелов и служебных знаков:

```sql run=empty
SELECT code
FROM (VALUES ('SALE10'), ('SALE 10'), ('SALE_10'), ('SALE-10')) AS t(code)
WHERE code !~ '[ _-]';
```

Внутри квадратных скобок большинство знаков теряют особый смысл. Дефис, который стоит первым или последним в наборе, означает просто дефис, а не диапазон.

## Кириллица и экранирование

Регулярные выражения PostgreSQL работают с символами Unicode, поэтому буквы кириллицы можно использовать и в наборах:

```sql run=company
SELECT full_name
FROM employees
WHERE full_name ~ 'ова$';
```

Если нужно найти сам служебный знак, например точку, перед ней ставят обратную косую черту: `\.`. Список служебных знаков такой: `. ^ $ * + ? ( ) [ ] { } | \`. Это отличается от LIKE, где экранируют только `%` и `_`:

```sql run=company
SELECT full_name, email
FROM employees
WHERE email ~ '^[a-z]+@corp\.example$';
```

Без обратной черты точка в `corp.example` означала бы любой символ и подошло бы `corpXexample`.

## Другие функции для регулярных выражений

Операторы только отвечают на вопрос «есть совпадение или нет». Вытащить найденный кусок, заменить его или разбить строку по образцу позволяют отдельные функции: `regexp_match`, `regexp_replace`, `regexp_split_to_table` и другие. Им посвящён раздел про строки.

## Производительность и когда не нужно

Регулярное выражение читается дольше, чем LIKE, и обычный индекс для него не используется, поэтому для простых задач берите LIKE: `LIKE 'А%'` проще, чем `~ '^А'`. Регулярные выражения нужны, когда образец действительно сложный: коды, номера телефонов, проверка формата.
