Когда значение нужно сравнить сразу с несколькими вариантами, цепочка OR получается длинной:

```sql run=shop
SELECT full_name, city
FROM customers
WHERE city = 'Москва' OR city = 'Казань' OR city = 'Новосибирск';
```

Оператор IN делает то же самое короче. Справа от него в скобках через запятую перечисляют допустимые значения:

```sql run=shop
SELECT full_name, city
FROM customers
WHERE city IN ('Москва', 'Казань', 'Новосибирск');
```

Результат тот же. База проверяет, совпало ли значение хотя бы с одним элементом списка. Такая запись читается лучше и не требует повторять имя столбца.

## Типы в списке

Элементы списка - обычные значения: числа, строки, даты. Все они должны быть совместимого типа со столбцом:

```sql run=library
SELECT title, published_year
FROM books
WHERE published_year IN (1869, 1967, 1987);
```

```sql run=company
SELECT full_name, hire_date
FROM employees
WHERE hire_date IN ('2017-03-01', '2020-05-18', '2025-09-01');
```

Значения в списке не обязаны присутствовать в таблице. Если какого-то варианта в данных нет, запрос просто его не найдёт, ошибки не будет.

## NOT IN

NOT IN оставляет строки, значение которых не совпало ни с одним элементом списка:

```sql run=shop
SELECT id, status
FROM orders
WHERE status NOT IN ('cancelled', 'new');
```

Запись `status NOT IN ('cancelled', 'new')` равна `status <> 'cancelled' AND status <> 'new'`. Связка именно AND, а не OR: строка должна отличаться от каждого значения. Частая ошибка новичка: написать `status <> 'cancelled' OR status <> 'new'`. Такое условие истинно всегда, потому что любой статус отличается хотя бы от одного из двух.

## NOT IN и NULL в самих данных

Пустое значение (NULL) означает «неизвестно». Условие `city NOT IN ('Москва', 'Казань')` для строки, где город NULL, неопределённо: база не знает, равен ли неизвестный город Москве. Неопределённая строка в WHERE отбрасывается. Поэтому отдел без города в этом результате отсутствует:

```sql run=company
SELECT name, city
FROM departments
WHERE city NOT IN ('Москва', 'Казань');
```

Отдел «Аналитика», у которого город не указан, сюда не попал. Часто это ожидаемо, но если нужны и отделы без города, условие приходится дополнять явно. Проверка `IS NULL` находит строки без значения, подробно о ней говорит урок про NULL:

```sql run=company
SELECT name, city
FROM departments
WHERE city NOT IN ('Москва', 'Казань') OR city IS NULL;
```

## Ловушка: NULL в списке

Куда опаснее другой случай, когда NULL оказывается в самом списке. Это происходит почти всегда, когда список даёт подзапрос. Попробуем найти сотрудников, которые ничьи не начальники. Подзапрос в скобках возвращает столбец значений, и IN работает с ним как со списком:

```sql run=company
SELECT full_name
FROM employees
WHERE id NOT IN (SELECT manager_id FROM employees);
```

Результат пуст, хотя сотрудники без подчинённых очевидно есть. В столбце `manager_id` у части сотрудников NULL, и список получается таким: `(1, 1, 1, 5, 7, 7, 10, NULL, ...)`. Условие `id NOT IN (...)` раскрывается в цепочку `id <> 1 AND id <> 5 AND ... AND id <> NULL`. Последнее сравнение всегда неопределённо, и вся цепочка никогда не бывает истинной. Лечение - выбросить NULL из подзапроса:

```sql run=company
SELECT full_name
FROM employees
WHERE id NOT IN (SELECT manager_id FROM employees WHERE manager_id IS NOT NULL);
```

Обычный IN такой проблемы не знает: для него нашлось совпадение, и остальные NULL уже не важны. Запомните правило: если после NOT IN стоит подзапрос или список из столбца, в котором бывает NULL, фильтруйте NULL или берите оператор NOT EXISTS, с которым вы познакомитесь в разделе о подзапросах.

## IN и пустой список

Список в скобках не может быть пустым: `IN ()` синтаксическая ошибка. Если список строит программа, нужно обработать случай, когда в нём ничего нет. Подзапрос, наоборот, может вернуть ноль строк, тогда `IN` ложно для всех, а `NOT IN` истинно для всех.

## Другие способы записи

В PostgreSQL есть массивы, и с ними можно сравнивать через ANY: `city = ANY (ARRAY['Москва', 'Казань'])`. Это тот же IN в другой записи; она пригодится, когда список приходит одним параметром-массивом. Также список можно выразить через `VALUES`:

```sql run=shop
SELECT full_name, city
FROM customers
WHERE city IN (SELECT v FROM (VALUES ('Москва'), ('Казань')) AS t(v));
```

В обычных запросах хватает простого IN со списком. В MySQL и в PostgreSQL он записывается одинаково.
