В таблице не у каждой строки есть значение в каждом столбце. У сотрудника может не быть почты, у отдела города, у книги цены. В таких ячейках хранится специальная отметка NULL, которая означает «значения нет или оно неизвестно». NULL не ноль и не пустая строка: ноль это число, пустая строка это текст, а NULL это отсутствие значения.

## IS NULL и IS NOT NULL

Попытка найти пустые значения обычным сравнением ничего не вернёт:

```sql run=company
SELECT full_name FROM employees WHERE email = NULL;
```

Запрос работает без ошибки, но строк в результате нет. Объяснение в том, что NULL означает «неизвестно», а сравнение с неизвестным значением тоже неизвестно: база не может сказать, равна ли чья-то почта неизвестной величине. Поэтому для проверки есть отдельные формы:

```sql run=company
SELECT full_name FROM employees WHERE email IS NULL;
```

```sql run=company
SELECT full_name, email FROM employees WHERE email IS NOT NULL;
```

Для NULL не работают `=` и `<>`: ни `email = NULL`, ни `email <> NULL` не бывают истинными.

## Трёхзначная логика

Из-за NULL у условия не два возможных исхода, а три: истина (TRUE), ложь (FALSE) и неизвестно (UNKNOWN; в PostgreSQL результат неизвестности выводится как NULL). WHERE оставляет только строки с TRUE. Строки с FALSE и с UNKNOWN отбрасываются. Это главное правило, из которого вытекает почти всё остальное.

Посмотрим на таблицы истинности. AND даёт ложь, если хотя бы одна часть ложна, даже когда другая неизвестна, и неизвестность, если ложных частей нет, но есть неизвестная. OR наоборот: даёт истину, если хотя бы одна часть истинна:

```sql run=empty
SELECT a, b, a AND b AS "a AND b", a OR b AS "a OR b"
FROM (VALUES
  (TRUE, NULL::boolean),
  (FALSE, NULL),
  (NULL, NULL)
) AS t(a, b);
```

В колонке `a AND b` видно: `TRUE AND NULL` даёт NULL, `FALSE AND NULL` даёт FALSE. В колонке `a OR b` наоборот: `TRUE OR NULL` даёт TRUE, `FALSE OR NULL` даёт NULL. А `NOT NULL` остаётся NULL: отрицание неизвестного по-прежнему неизвестно.

Отсюда практический вывод. Условие `city <> 'Москва'` не вернёт покупателей без города. Не потому, что город «не Москва», а потому, что для них условие неизвестно:

```sql run=shop
SELECT full_name, city FROM customers WHERE city <> 'Москва';
```

В результате нет ни Льва Комарова, у которого город не указан, ни москвичей. Чтобы вернуть и его, нужно сказать это прямо:

```sql run=shop
SELECT full_name, city
FROM customers
WHERE city <> 'Москва' OR city IS NULL;
```

## IS DISTINCT FROM

Запись с `OR ... IS NULL` приходится писать так часто, что в стандарте SQL для неё есть оператор. `a IS DISTINCT FROM b` ведёт себя как «не равно», но считает NULL обычным значением: два NULL равны между собой, а NULL и любое число различаются. Результат всегда TRUE или FALSE, но никогда не NULL:

```sql run=shop
SELECT full_name, city
FROM customers
WHERE city IS DISTINCT FROM 'Москва';
```

Парный оператор `IS NOT DISTINCT FROM` соответствует «равно» с учётом NULL. Его используют для сравнения двух столбцов, в каждом из которых бывают пустые значения:

```sql run=empty
SELECT a, b,
       a = b AS equal,
       a IS NOT DISTINCT FROM b AS same
FROM (VALUES (1, 1), (1, 2), (1, NULL), (NULL::int, NULL)) AS t(a, b);
```

В MySQL похожий оператор записывается как `<=>`. В PostgreSQL его нет: нужно писать `IS NOT DISTINCT FROM`.

## NULL в других операторах

Правило «неизвестно отбрасывается» действует везде, где используется условие. С LIKE и BETWEEN пустое значение не попадает ни в само условие, ни в его отрицание:

```sql run=library
SELECT title, price FROM books WHERE price BETWEEN 500 AND 800;
```

```sql run=library
SELECT title, price FROM books WHERE price NOT BETWEEN 500 AND 800;
```

Книги «Хроники заводной птицы» нет ни в одном из результатов. Вместе они дают девять книг, а не десять, и эта пропажа обычно замечается не сразу.

Список в `NOT IN`, содержащий NULL, превращает всё условие в неопределённое. Эта ловушка описана в уроке про IN, запомните: `x NOT IN (1, NULL)` никогда не истинно.

## Работа со значениями NULL

Если вместо NULL нужно подставить значение, есть функция COALESCE: она возвращает первый аргумент, который не NULL. В MySQL ту же роль играет IFNULL, в PostgreSQL IFNULL нет:

```sql run=library
SELECT title, COALESCE(price, 0) AS price_or_zero FROM books WHERE id IN (7, 8);
```

Обратная операция, NULLIF, возвращает NULL, если два значения равны. С их помощью обычно защищаются от деления на ноль и подставляют значения по умолчанию. Подробнее о них рассказывает раздел про выражения.

## Как не ошибиться с NULL

Прежде чем писать условие для столбца, посмотрите в описании таблицы, допускает ли он NULL. В объявлении столбца NOT NULL означает, что пустого значения быть не может, и тогда обычные сравнения безопасны. В остальных случаях полезно задать себе вопрос: что должен вернуть запрос для строк без значения? Если ответ «их тоже нужно вернуть» или «их нужно отдельно исключить», это нужно написать в условии явно.
