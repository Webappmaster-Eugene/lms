Без условия SELECT возвращает все строки таблицы. Чтобы оставить только нужные, после FROM пишут слово WHERE и условие. База проверяет условие для каждой строки и отдаёт только те, для которых оно истинно:

```sql run=company
SELECT full_name, salary
FROM employees
WHERE salary > 200000;
```

Порядок частей запроса фиксирован: SELECT, FROM, WHERE, и только потом ORDER BY и LIMIT. Поэтому отобранные строки можно сразу отсортировать:

```sql run=company
SELECT full_name, salary
FROM employees
WHERE salary > 100000
ORDER BY salary DESC;
```

## Операторы сравнения

В условии сравнивают столбец со значением или два столбца между собой. Операторов шесть:

| Оператор | Значение |
|---|---|
| `=` | равно |
| `<>` | не равно |
| `<` и `>` | меньше и больше |
| `<=` и `>=` | меньше или равно и больше или равно |

Равенство записывается одним знаком `=`. Двойного `==` в SQL нет: в отличие от языков программирования, знак `=` в WHERE всегда означает сравнение, а не присваивание. Для неравенства стандарт SQL предлагает `<>`; PostgreSQL принимает и `!=`, но в чужом коде чаще встречается `<>`.

```sql run=shop
SELECT title, stock
FROM products
WHERE stock <> 0;
```

## Числа

Числа пишут без кавычек. Целые и дробные сравниваются между собой без лишних усилий: `price > 1000` работает и для столбца типа integer, и для numeric:

```sql run=shop
SELECT title, price
FROM products
WHERE price >= 39990;
```

Граница включена только в нестрогих операторах `>=` и `<=`. Забытое равенство - одна из самых частых причин «пропавшей» строки: сотрудник с зарплатой ровно 100000 не попадёт под `salary > 100000`.

## Строки

Текстовые значения берут в одинарные кавычки. Двойные кавычки в SQL означают имя столбца или таблицы, а не текст, поэтому `WHERE city = "Москва"` PostgreSQL прочитает как сравнение с несуществующим столбцом и вернёт ошибку:

```sql run=shop error
SELECT full_name FROM customers WHERE city = "Москва";
```

Корректная запись:

```sql run=shop
SELECT full_name, city
FROM customers
WHERE city = 'Москва';
```

В PostgreSQL сравнение строк учитывает регистр: `'москва'` и `'Москва'` разные значения. Если вы пришли из MySQL, где по умолчанию сравнение не различает регистр, это нужно держать в голове. Привести обе стороны к одному регистру можно функцией `lower`, о строковых функциях рассказывает отдельный раздел, а поиск без учёта регистра по шаблону описан в уроке про LIKE.

Операторы порядка работают и со строками: `<` значит «раньше по алфавиту». Точный порядок букв зависит от правил сортировки (collation), которые заданы для базы, поэтому сравнивать так строки, написанные в разном регистре или на разных языках, не стоит. Для слов в одном регистре на одном языке результат понятен:

```sql run=company
SELECT name, city
FROM departments
WHERE city < 'Му';
```

В результате Казань и Москва: «Мо» раньше «Му», а «К» раньше «М». Санкт-Петербург идёт позже по алфавиту и не попадает. Отдел без города тоже не попадает: сравнение с пустым значением неопределённо, подробнее в уроке про NULL.

## Даты и время

Даты записывают текстом в формате год-месяц-день в одинарных кавычках. PostgreSQL сам превращает такой текст в дату, когда сравнивает его со столбцом типа date:

```sql run=company
SELECT full_name, hire_date
FROM employees
WHERE hire_date >= '2022-01-01'
ORDER BY hire_date;
```

Такой формат однозначен. Запись `'03/04/2022'` PostgreSQL прочитает по настройке DateStyle, и в одной базе это третье апреля, а в другой четвёртое марта, поэтому в запросах держитесь порядка год-месяц-день. Вместо кавычек можно явно указать тип: `DATE '2022-01-01'`.

Для столбцов timestamp сравнение идёт по моменту времени. Если указать только дату, она означает полночь начала этого дня:

```sql run=shop
SELECT id, ordered_at
FROM orders
WHERE ordered_at > '2026-03-01'
ORDER BY id;
```

Заказ, оформленный 1 марта в 12:00, попадёт сюда: он позже полуночи. Заказ ровно в 00:00:00 не попал бы из-за строгого `>`. Эту особенность нужно помнить, когда вы отбираете периоды: она подробно разобрана в уроке про BETWEEN.

## Условие может быть любым выражением

Слева и справа от оператора стоит не только имя столбца. Можно сравнивать столбец со столбцом или с вычисленным значением:

```sql run=shop
SELECT title, price, stock
FROM products
WHERE price < stock * 100;
```

Одного ограничения нужно остерегаться: псевдонимы из SELECT в WHERE использовать нельзя. База сначала находит строки по WHERE и лишь потом вычисляет список SELECT, поэтому псевдонима в этот момент ещё не существует:

```sql run=shop error
SELECT title, price * stock AS total FROM products WHERE total > 100000;
```

Нужно повторить выражение: `WHERE price * stock > 100000`. Позже, на подзапросах, появится способ обойтись без повтора.
