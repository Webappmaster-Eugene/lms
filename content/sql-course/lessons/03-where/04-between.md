Чтобы отобрать значения из диапазона, можно написать два сравнения через AND. Оператор BETWEEN делает запись короче:

```sql run=company
SELECT full_name, salary
FROM employees
WHERE salary BETWEEN 100000 AND 200000;
```

Это то же самое, что `salary >= 100000 AND salary <= 200000`. Главное свойство BETWEEN: границы входят в диапазон. Сотрудник с зарплатой ровно 100000 или ровно 200000 в этот результат попал бы. Запомнить удобно так: BETWEEN работает как нестрогие `>=` и `<=`, а не как строгие.

## Порядок границ

Первой идёт меньшая граница, второй большая. Если перепутать их, диапазон окажется пустым, и запрос ничего не вернёт, а ошибки не будет:

```sql run=company
SELECT full_name, salary
FROM employees
WHERE salary BETWEEN 200000 AND 100000;
```

Это известная ловушка. Когда границы приходят из параметров запроса, их не всегда проверяют заранее. У PostgreSQL есть вариант `BETWEEN SYMMETRIC`, который сам ставит границы по порядку:

```sql run=company
SELECT full_name, salary
FROM employees
WHERE salary BETWEEN SYMMETRIC 200000 AND 100000;
```

Эта форма есть в стандарте SQL, но MySQL её не поддерживает, поэтому в переносимом коде лучше упорядочить границы заранее.

## NOT BETWEEN

С NOT условие означает «вне диапазона»: меньше нижней границы или больше верхней. Сами границы остаются внутри диапазона и в результат не попадают:

```sql run=library
SELECT title, published_year
FROM books
WHERE published_year NOT BETWEEN 1850 AND 1950;
```

Эквивалентная запись: `published_year < 1850 OR published_year > 1950`. Связка здесь OR: условие «вне диапазона» выполняется, если верна любая из двух частей.

## Строки в диапазоне

BETWEEN работает с любыми типами, которые можно упорядочить, в том числе со строками. Диапазон идёт по алфавиту, и верхняя граница тоже входит. Чем длиннее строка, тем она «позже» той, что совпадает с ней по началу, поэтому `BETWEEN 'А' AND 'К'` не включит фамилию, начинающуюся с «Кр». Для слов такой диапазон ненадёжен, зато для кодов одинаковой длины (например, `'A100' AND 'A199'`) работает хорошо.

## Даты

Для столбца типа date диапазон пишется естественно: обе границы это дни, и оба дня входят:

```sql run=shop
SELECT full_name, registered_on
FROM customers
WHERE registered_on BETWEEN '2025-01-01' AND '2025-12-31';
```

Любой год записывается так: первого января и тридцать первого декабря.

## Время и полуоткрытые периоды

Для столбца timestamp тот же приём ошибочен. Попробуем найти заказы за 1 и 2 апреля 2026 года:

```sql run=shop
SELECT id, ordered_at
FROM orders
WHERE ordered_at BETWEEN '2026-04-01' AND '2026-04-02'
ORDER BY id;
```

Результат пуст, хотя заказ 8 оформлен 2 апреля в 19:10. Дата без времени означает полночь. Правая граница `'2026-04-02'` превращается в 00:00:00 второго апреля, и всё, что произошло в этот день позже полуночи, отсекается. Правильный способ - полуоткрытый период. Нижняя граница включена, верхняя нет, и верхней границей служит начало следующего периода:

```sql run=shop
SELECT id, ordered_at
FROM orders
WHERE ordered_at >= '2026-04-01' AND ordered_at < '2026-04-03'
ORDER BY id;
```

Так записывают любой период по времени: сутки, неделю, месяц. Не нужно знать, сколько дней в месяце, а границы соседних периодов не пересекаются и не оставляют щелей. В дату можно добавлять интервал, чтобы не писать вторую границу вручную:

```sql run=shop
SELECT id, ordered_at
FROM orders
WHERE ordered_at >= DATE '2026-03-01'
  AND ordered_at < DATE '2026-03-01' + INTERVAL '1 month'
ORDER BY id;
```

Выражение `DATE '2026-03-01' + INTERVAL '1 month'` даёт `2026-04-01 00:00:00`. Подробнее о датах и интервалах рассказывает отдельный раздел.

## BETWEEN и NULL

Если в столбце есть пустые значения, строка с NULL не попадает ни в BETWEEN, ни в NOT BETWEEN: сравнение с неизвестным значением неопределённо. Посмотрите на книги с ценой от 500 до 800:

```sql run=library
SELECT title, price
FROM books
WHERE price BETWEEN 500 AND 800;
```

Книги «Хроники заводной птицы» здесь нет, у неё цена не указана. Она отсутствует и в результате `price NOT BETWEEN 500 AND 800`. Если нужно вернуть строки без цены вместе с остальными, дописывают проверку явно: `price NOT BETWEEN 500 AND 800 OR price IS NULL`.

## Когда BETWEEN не нужен

Если нужна только одна граница, пишут обычное сравнение. Если нужны строгие границы, то BETWEEN не подходит, потому что он всегда включает концы: пишите `price > 500 AND price < 800`. Для чисел с дробной частью, в том числе numeric, эти различия реальны: цена 800.00 попадёт в `BETWEEN 500 AND 800`, но не в `price > 500 AND price < 800`.
