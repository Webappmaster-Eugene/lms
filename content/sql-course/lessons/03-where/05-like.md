Равенство находит строку, которая совпадает целиком. Часто нужно другое: все имена на «А», все названия со словом «ноутбук» или все адреса почты на одном домене. Для этого есть LIKE. Справа от него стоит шаблон, а в шаблоне два служебных знака:

`%` заменяет любое число любых символов, в том числе ни одного, а `_` заменяет ровно один любой символ. Все остальные символы шаблона означают сами себя.

## Начало, конец, середина

Шаблон, который начинается с символа, а заканчивается знаком процента, ищет строки по началу:

```sql run=company
SELECT full_name
FROM employees
WHERE full_name LIKE 'А%';
```

Знак процента в начале шаблона ищет по концу, процент с двух сторон - по любому месту:

```sql run=company
SELECT full_name, position
FROM employees
WHERE position LIKE '%разработчик';
```

```sql run=company
SELECT full_name, position
FROM employees
WHERE position LIKE '%менеджер%';
```

В последнем запросе нашёлся только «SMM-менеджер». «Менеджер по продажам» с заглавной буквы не подошёл, причина в регистре.

## Регистр

LIKE в PostgreSQL различает регистр. Шаблон `'%менеджер%'` не найдёт «Менеджер по продажам», потому что «М» заглавная. В MySQL LIKE по умолчанию регистр игнорирует, и привычка оттуда может подвести. В PostgreSQL для поиска без учёта регистра есть оператор ILIKE:

```sql run=empty
SELECT word,
       word LIKE 'sale%' AS with_like,
       word ILIKE 'sale%' AS with_ilike
FROM (VALUES ('SALE10'), ('Sale-20'), ('sale_5'), ('discount')) AS t(word);
```

ILIKE - расширение PostgreSQL, в стандарте SQL его нет. Для латинских букв он работает всегда. Для кириллицы результат зависит от настроек локали (способа сортировки и сравнения), с которыми создана база. В тренажёре кириллица работает, но на другом сервере результат стоит проверить. Тот же вопрос локали относится и к функции lower, зато она проще читается: `lower(position) LIKE '%менеджер%'`.

Есть и обратные формы: `NOT LIKE` и `NOT ILIKE`. А оператор `~~` в PostgreSQL означает LIKE, `~~*` означает ILIKE, `!~~` означает NOT LIKE. Это внутренние имена; в запросах пишут слова.

## Знак подчёркивания

Подчёркивание заменяет один символ. Четыре подчёркивания означают ровно четыре любых символа:

```sql run=company
SELECT full_name, email
FROM employees
WHERE email LIKE '____@corp.example';
```

Подходят только три адреса, в которых перед `@` стоит ровно четыре буквы. В отличие от регулярных выражений, в LIKE точка и другие знаки препинания - обычные символы, экранировать их не нужно.

## Шаблон описывает всю строку

Шаблон описывает строку целиком. `LIKE 'А%'` ищет строки, которые начинаются с «А», но `LIKE 'А'` без процента совпадёт только со строкой «А». Именно поэтому для поиска по части строки процент нужно ставить с нужной стороны.

NULL в LIKE ведёт себя как везде: `NULL LIKE 'a%'` даёт неопределённость, и такая строка не попадёт ни в LIKE, ни в NOT LIKE:

```sql run=company
SELECT full_name, email
FROM employees
WHERE email NOT LIKE 'o%';
```

Сотрудников без почты в этом результате нет. Если они нужны, добавляют `OR email IS NULL`.

## ESCAPE: когда нужен сам знак % или _

Что делать, если искомая строка содержит процент или подчёркивание? Шаблон `LIKE '%_%'` бесполезен: он найдёт любую непустую строку, потому что `_` заменяет любой символ. Служебный знак нужно экранировать, то есть пометить, что он обычный. В PostgreSQL экранирующий символ по умолчанию - обратная косая черта:

```sql run=empty
SELECT code
FROM (VALUES ('SALE_10'), ('SALE10'), ('VIP%20')) AS t(code)
WHERE code LIKE '%\_%';
```

Находится только `SALE_10`. Знак `\_` в шаблоне означает настоящее подчёркивание. Аналогично `\%` означает настоящий процент, а `\\` - саму обратную черту.

Если обратная черта в ваших данных встречается часто, например в путях Windows, экранирующий символ назначают сами через ESCAPE:

```sql run=empty
SELECT code
FROM (VALUES ('SALE_10'), ('SALE10'), ('VIP%20')) AS t(code)
WHERE code LIKE '%!%%' ESCAPE '!';
```

После `!` знак процента теряет особую роль. Шаблон `'%!%%'` читается так: любое число символов, настоящий процент, любое число символов. Выбирать нужно символ, который в данных не встречается.

## SIMILAR TO

В стандарте SQL есть оператор SIMILAR TO, который стоит между LIKE и регулярными выражениями. К знакам `%` и `_` он добавляет `|` («или»), скобки для группировки и повторения `*`, `+`, `?`:

```sql run=empty
SELECT code, code SIMILAR TO '(SALE|VIP)%' AS matches
FROM (VALUES ('SALE10'), ('VIP20'), ('WELCOME')) AS t(code);
```

В отличие от `~` из урока про регулярные выражения, SIMILAR TO, как и LIKE, должен совпасть со строкой целиком. На практике его применяют редко: регулярные выражения выразительнее, и их знают больше людей. Знать, что он есть, нужно, чтобы узнать его в чужом коде.

## Производительность

Условие `LIKE 'А%'` с фиксированным началом может использовать обычный индекс по столбцу (при подходящей настройке), а `LIKE '%ноутбук%'` с процентом в начале - нет, и база прочитает всю таблицу. Для небольших таблиц это незаметно. Для полнотекстового поиска по большим объёмам в PostgreSQL есть отдельные средства (индексы триграмм и полнотекстовый поиск), но это уже тема за рамками курса.
