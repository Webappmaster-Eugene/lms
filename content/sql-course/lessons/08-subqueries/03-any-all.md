Оператор IN проверяет только равенство. Чтобы сравнить значение со списком знаком больше или меньше, нужны операторы ANY и ALL. Они ставятся сразу после знака сравнения, а список передаётся подзапросом в скобках.

ANY означает «хотя бы для одного значения списка», ALL - «для каждого значения списка». У ANY есть синоним SOME, но он встречается редко.

## ANY

Найдём товары, которые стоят меньше, чем хотя бы один ноутбук. Ноутбуки - это товары категории 1.

```sql run=shop
SELECT title, price
FROM products
WHERE price < ANY (SELECT price FROM products WHERE category_id = 1)
ORDER BY id;
```

Условие `price < ANY (...)` истинно, если цена меньше хотя бы одного значения из списка. Ноутбуков два: за 89990 и за 189990. Достаточно быть дешевле самого дорогого, поэтому в результат вошли все товары, кроме самого дорогого ноутбука. Ноутбук за 89990 тоже попал: он дешевле второго.

Значит, `< ANY` по смыслу равно `< MAX`, а `> ANY` равно `> MIN`. Если нужно именно число, проще написать скалярный подзапрос с MAX. Но ANY читается ближе к вопросу, который задают словами.

## ALL

Условие `price < ALL (...)` истинно, когда цена меньше каждого значения списка, то есть меньше минимума. Найдём товары, которые дешевле любого ноутбука:

```sql run=shop
SELECT title, price
FROM products
WHERE price < ALL (SELECT price FROM products WHERE category_id = 1)
ORDER BY id;
```

В результат попали все товары, кроме двух самых дорогих: ноутбуков за 89990 и за 189990. Ноутбук за 89990 не дешевле самого себя.

Теперь зарплаты. Найдём сотрудников, которые получают больше каждого сотрудника поддержки (отдел 4):

```sql run=company
SELECT full_name, salary
FROM employees
WHERE salary > ALL (SELECT salary FROM employees WHERE department_id = 4)
ORDER BY id;
```

Результат содержит всех, кроме самих сотрудников поддержки и стажёра, у которого зарплата ниже.

## Сводка

Для каждого знака сравнения ANY и ALL сводятся к агрегату:

- `> ANY` совпадает с `> MIN`, `> ALL` совпадает с `> MAX`;
- `< ANY` совпадает с `< MAX`, `< ALL` совпадает с `< MIN`;
- `= ANY` совпадает с IN;
- `<> ALL` совпадает с NOT IN.

Запомните две последние строки. Из них следует, что `<> ALL` страдает от той же проблемы с NULL, что и NOT IN.

## Лучший балл через ALL

Выражение `points >= ALL (...)` находит строки, у которых значение не меньше любого другого. Это ещё один способ найти максимум с учётом ничьих. Знак обязательно нестрогий: список содержит и сам балл, и строгое «больше» с ним не выполнится никогда.

```sql run=empty
WITH scores(student, points) AS (
  VALUES ('Аня', 90), ('Боря', 85), ('Вика', 90)
)
SELECT student, points
FROM scores
WHERE points >= ALL (SELECT points FROM scores)
ORDER BY student;
```

## Пустой список и NULL

У ALL есть две особенности, которые легко не заметить. Первая: если подзапрос ничего не вернул, условие ALL истинно для любой строки. Условие «больше каждого из нуля значений» выполняется само собой:

```sql run=company
SELECT COUNT(*) AS passed
FROM employees
WHERE salary > ALL (SELECT salary FROM employees WHERE department_id = 99);
```

Здесь отбор прошли все двенадцать сотрудников, хотя отдела 99 не существует. С ANY всё наоборот: на пустом списке условие ложно для каждой строки.

Вторая особенность: NULL в списке портит ALL так же, как NOT IN. Если в подзапросе хотя бы одно значение NULL, а все остальные сравнения истинны, итог остаётся неизвестным, и строка не проходит:

```sql run=empty
SELECT 5 > ALL (VALUES (1), (2), (NULL)) AS result;
```

Неизвестный результат отображается как NULL. Если значения в подзапросе могут быть пустыми, добавьте к нему `WHERE столбец IS NOT NULL`.

## Массивы

В PostgreSQL ANY и ALL работают не только с подзапросом, но и с массивом. Массив записывают как `ARRAY[...]`:

```sql run=library
SELECT title, genre
FROM books
WHERE genre = ANY (ARRAY['повесть', 'поэма', 'пьеса'])
ORDER BY id;
```

Результат тот же, что у `genre IN ('повесть', 'поэма', 'пьеса')`. Преимущество массива в приложении: можно передать весь список одним параметром запроса, а не склеивать IN из нескольких. Это одна из особенностей PostgreSQL, в MySQL массивов нет.

## ANY и ALL со знаком не равно

Выражение `x <> ANY (список)` читается как «отличается хотя бы от одного значения» и почти всегда истинно: оно ложно только когда все элементы списка равны x. Новички часто принимают его за NOT IN. Для NOT IN нужна запись `<> ALL`.

```sql run=empty
SELECT
  3 <> ANY (VALUES (1), (2), (3)) AS differs_from_some,
  3 <> ALL (VALUES (1), (2), (3)) AS differs_from_all;
```

Первое выражение истинно, потому что 3 не равно 1. Второе ложно: среди значений есть тройка.

## В MySQL

ANY и ALL в MySQL существуют, но используются реже, чем в PostgreSQL, и массивов там нет. Для списка значений в MySQL пользуются IN или функцией FIND_IN_SET; в PostgreSQL ей соответствует запись `значение = ANY (string_to_array(строка, ','))`.
