Скалярный подзапрос возвращает одно значение. Подзапрос с одним столбцом и любым числом строк возвращает список, и его можно использовать после IN. Этот приём особенно полезен, пока вы не знаете соединений таблиц: он позволяет отбирать строки одной таблицы по данным другой.

## IN с подзапросом

В таблице сотрудников нет названия города, он есть только в таблице отделов. Чтобы найти сотрудников московских отделов, сначала выберем номера этих отделов:

```sql run=company
SELECT id FROM departments WHERE city = 'Москва';
```

Теперь подставим этот запрос в скобках после IN:

```sql run=company
SELECT full_name, department_id
FROM employees
WHERE department_id IN (SELECT id FROM departments WHERE city = 'Москва')
ORDER BY id;
```

База сначала получает список номеров, затем оставляет сотрудников, чей отдел в нём есть. Из таблицы `departments` берутся только номера, сами её данные в результат не попадают. Запрос читается почти как предложение: сотрудники, чей отдел входит в список московских отделов.

Сотрудник без отдела в результате не появился: у него `department_id` равен NULL, а NULL ни с чем не совпадает.

## NOT IN

Отрицание ищет строки, которых в списке нет. Найдём отделы, в которых никто не работает. Для этого отберём отделы, чьего номера нет среди номеров отделов сотрудников:

```sql run=company
SELECT name
FROM departments
WHERE id NOT IN (SELECT department_id FROM employees)
ORDER BY id;
```

Здесь ответ должен быть: отдел «Аналитика». Но запрос вернул пустой результат. Причина в том, что у стажёра Виктора Зайцева отдела нет, и в списке подзапроса есть NULL.

## Ловушка NOT IN и NULL

Выражение `5 NOT IN (1, 2, NULL)` выглядит истинным, но по правилам SQL оно эквивалентно `5 <> 1 AND 5 <> 2 AND 5 <> NULL`. Последнее сравнение неизвестно, и всё выражение целиком неизвестно, а не истинно. WHERE пропускает только истинные значения, поэтому ни одна строка не проходит.

Достаточно одного NULL в подзапросе, чтобы NOT IN перестал находить что-либо. Исправить можно двумя способами. Первый - убрать NULL из списка:

```sql run=company
SELECT name
FROM departments
WHERE id NOT IN (SELECT department_id FROM employees WHERE department_id IS NOT NULL)
ORDER BY id;
```

Второй способ - использовать NOT EXISTS, о котором речь ниже. Для IN такой проблемы нет: если искомое значение найдено, остальные элементы списка не мешают.

## EXISTS

EXISTS проверяет только одно: вернул ли подзапрос хотя бы одну строку. Само содержимое строк не важно, поэтому внутри обычно пишут `SELECT 1`. Но чаще всего подзапрос ссылается на текущую строку внешнего запроса:

```sql run=company
SELECT d.name
FROM departments d
WHERE EXISTS (SELECT 1 FROM employees e WHERE e.department_id = d.id)
ORDER BY d.id;
```

Для каждого отдела база проверяет, есть ли хотя бы один сотрудник с таким `department_id`. Буквы `d` и `e` после названий таблиц - псевдонимы, они позволяют отличить столбцы разных таблиц с одинаковыми именами. Выражение `e.department_id = d.id` связывает внутренний запрос с внешним.

Если связь убрать, подзапрос превратится в вопрос «есть ли в компании хоть один сотрудник», и ответ будет одинаков для каждого отдела.

## NOT EXISTS

Чтобы найти отделы без сотрудников, поставьте перед EXISTS слово NOT:

```sql run=company
SELECT d.name
FROM departments d
WHERE NOT EXISTS (SELECT 1 FROM employees e WHERE e.department_id = d.id)
ORDER BY d.id;
```

Сработало, хотя у Виктора отдела нет. NOT EXISTS не сравнивает значения списком, а ищет строки по условию, и NULL ему не мешает. Поэтому NOT EXISTS надёжнее NOT IN, когда в данных могут быть пустые значения. Это тот случай, когда выбор между двумя записями определяется не вкусом, а корректностью.

## Дублей нет

Подзапрос с EXISTS не размножает строки внешней таблицы. Найдём покупателей, у которых есть хотя бы один отправленный заказ:

```sql run=shop
SELECT c.full_name
FROM customers c
WHERE EXISTS (
  SELECT 1 FROM orders o
  WHERE o.customer_id = c.id AND o.status = 'shipped'
)
ORDER BY c.id;
```

У Андрея Кравцова один отправленный заказ, у Веры Тихоновой один, у Олега Савина один. Каждый покупатель выведен один раз, сколько бы у него ни было подходящих заказов.

## Что выбрать: IN или EXISTS

Для положительного вопроса «есть ли значение в списке» оба варианта дают одинаковый результат, и современный PostgreSQL строит для них похожие планы. Ориентируйтесь на читаемость. IN удобен, когда подзапрос независим и возвращает простой список значений. EXISTS удобен, когда условие связи сложнее равенства одного столбца или когда нужно отрицание. Для отрицания по возможности берите NOT EXISTS.

## Подзапрос в IN можно вкладывать

Подзапросы внутри подзапросов допустимы без ограничения глубины, хотя чем глубже, тем труднее читать. Найдём товары, которые попали хотя бы в один действующий заказ:

```sql run=shop
SELECT title
FROM products
WHERE id IN (
  SELECT product_id FROM order_items
  WHERE order_id IN (SELECT id FROM orders WHERE status <> 'cancelled')
)
ORDER BY id;
```

Читайте такой запрос изнутри наружу: сначала номера действующих заказов, потом товары в них, потом названия.

## В MySQL

IN, NOT IN и EXISTS в MySQL работают так же, а правило про NULL в NOT IN действует в обеих базах. Разница в том, что MySQL, особенно старый, плохо оптимизирует IN с подзапросом, и там привычнее переписывать его соединением. В PostgreSQL об этом можно не думать.
