Вложенные подзапросы быстро становятся трудночитаемыми: чтобы понять запрос, приходится читать изнутри наружу. Конструкция WITH позволяет вынести подзапрос в начало запроса, дать ему имя и дальше пользоваться этим именем, как таблицей. Такое выражение называют CTE, от английского common table expression, общее табличное выражение.

## Простой WITH

Найдём отдел с самым большим фондом зарплаты. Сначала посчитаем фонд каждого отдела и назовём результат `payroll`:

```sql run=company
WITH payroll AS (
  SELECT department_id, SUM(salary) AS total
  FROM employees
  WHERE department_id IS NOT NULL
  GROUP BY department_id
)
SELECT department_id, total
FROM payroll
WHERE total = (SELECT MAX(total) FROM payroll);
```

Выражение `payroll` определено один раз, а используется дважды: в основном запросе и в подзапросе, который находит максимум. Если бы мы писали без WITH, группировку пришлось бы повторить. Сравнение с максимумом по равенству сохраняет ничьи: если два отдела имеют одинаковый фонд, оба попадут в результат.

Имя после WITH живёт только внутри одного запроса. Следующий запрос должен определить его заново.

## Несколько выражений

В одном WITH можно объявить несколько выражений через запятую, и каждое следующее видит предыдущие. Так запрос превращается в цепочку шагов. Найдём покупателей, которые потратили больше среднего. Сумма заказа нигде не хранится, поэтому шагов три: суммы заказов, суммы покупателей, сравнение.

```sql run=shop
WITH order_totals AS (
  SELECT
    o.id AS order_id,
    o.customer_id,
    (SELECT SUM(i.quantity * i.price) FROM order_items i WHERE i.order_id = o.id) AS total
  FROM orders o
  WHERE o.status <> 'cancelled'
),
customer_totals AS (
  SELECT customer_id, SUM(total) AS spent
  FROM order_totals
  GROUP BY customer_id
)
SELECT customer_id, spent
FROM customer_totals
WHERE spent > (SELECT AVG(spent) FROM customer_totals)
ORDER BY customer_id;
```

Первое выражение выбирает действующие заказы и считает сумму каждого. Второе складывает суммы по покупателям. Основной запрос сравнивает каждую сумму со средней. Каждый шаг можно проверить отдельно: временно замените основной запрос на `SELECT * FROM order_totals` и посмотрите, что получилось.

## Одно выражение, несколько значений

Если нужно несколько агрегатов, считайте их в одном выражении, а не пишите подзапрос на каждый. Книги дороже средней цены, но дешевле самой дорогой:

```sql run=library
WITH stats AS (
  SELECT AVG(price) AS avg_price, MAX(price) AS max_price
  FROM books
)
SELECT title, price
FROM books
WHERE price > (SELECT avg_price FROM stats)
  AND price < (SELECT max_price FROM stats)
ORDER BY price DESC, id;
```

Таблицу `books` база читает для статистики один раз. Выражение `stats` состоит из одной строки, поэтому из него можно брать значения как из скалярного подзапроса.

## WITH и подзапрос в FROM

Подзапрос в FROM и выражение WITH часто взаимозаменяемы. Выбирайте WITH, когда результат нужен больше одного раза, когда у запроса несколько шагов или когда имя помогает понять смысл. Для короткого одноразового вычисления достаточно подзапроса в FROM.

В PostgreSQL до версии 12 выражение WITH всегда выполнялось отдельно и не оптимизировалось вместе с остальным запросом. Начиная с 12 оно вставляется в запрос, как обычный подзапрос, если на него один раз ссылаются и в нём нет побочных эффектов. Поведением можно управлять: `WITH имя AS MATERIALIZED (...)` заставляет выполнить выражение один раз и сохранить результат, а `NOT MATERIALIZED` разрешает подставить его в запрос. Обычно ни то, ни другое не нужно.

В MySQL WITH появился в версии 8.0. В более старых версиях вместо него применяют подзапросы в FROM.

## Рекурсивный WITH

Если после WITH написать слово RECURSIVE, выражение сможет ссылаться само на себя. Рекурсивный запрос состоит из двух частей, соединённых UNION ALL. Первая часть, начальная, выполняется один раз. Вторая, шаг, берёт строки, полученные на прошлом круге, и производит новые. Так продолжается, пока шаг не перестанет возвращать строки.

Самый простой пример - числа от 1 до 5:

```sql run=empty
WITH RECURSIVE n(i) AS (
  SELECT 1
  UNION ALL
  SELECT i + 1 FROM n WHERE i < 5
)
SELECT i FROM n;
```

Начальная часть даёт строку со значением 1. Шаг берёт её и возвращает 2, затем из двойки получается тройка и так далее. На пятой строке условие `i < 5` ложно, шаг ничего не возвращает, и рекурсия заканчивается. Без условия остановки запрос будет работать бесконечно, поэтому условие нужно писать всегда.

В скобках после имени, `n(i)`, перечислены названия столбцов выражения.

## Ряд дат

Чаще всего рекурсия нужна, чтобы создать ряд значений, например дат без пропусков. Ряд дат пригодится, чтобы найти дни без событий: в таблице заказов такие дни просто отсутствуют, поэтому найти их можно, только сравнив с полным рядом.

```sql run=shop
WITH RECURSIVE days(day) AS (
  SELECT DATE '2026-03-01'
  UNION ALL
  SELECT day + 1 FROM days WHERE day < DATE '2026-03-10'
)
SELECT day
FROM days
WHERE day NOT IN (SELECT ordered_at::date FROM orders)
ORDER BY day;
```

К дате можно прибавлять целое число, и это дни. Выражение `ordered_at::date` отсекает время, оставляя только дату. Здесь NOT IN безопасен: столбец `ordered_at` объявлен как NOT NULL, и NULL в списке не будет.

Для месяцев вместо числа прибавляют интервал. Результат сложения даты и интервала имеет тип timestamp, поэтому его нужно привести обратно к дате:

```sql run=empty
WITH RECURSIVE months(month_start) AS (
  SELECT DATE '2026-01-01'
  UNION ALL
  SELECT (month_start + INTERVAL '1 month')::date FROM months WHERE month_start < DATE '2026-05-01'
)
SELECT month_start FROM months;
```

Ряд, который не зависит от данных таблицы, проще получить функцией `generate_series`. Рекурсия нужна, когда следующее значение зависит от предыдущего каким-то нетривиальным образом.

```sql run=empty
SELECT generate_series(1, 5) AS i;
```

## Ряд с подсчётом для пустых периодов

Построенный ряд можно использовать как основу и к каждой его строке приписывать данные коррелированным подзапросом. Так в отчёт попадают периоды, в которых ничего не произошло:

```sql run=shop
WITH RECURSIVE months(month_start) AS (
  SELECT DATE '2025-11-01'
  UNION ALL
  SELECT (month_start + INTERVAL '1 month')::date FROM months WHERE month_start < DATE '2026-05-01'
)
SELECT
  m.month_start,
  (SELECT COUNT(*) FROM orders o WHERE date_trunc('month', o.ordered_at)::date = m.month_start) AS orders_count
FROM months m
ORDER BY m.month_start;
```

В ноябре, декабре и мае заказов нет, но строки остались, и в них нули. Если сгруппировать сами заказы, пустых месяцев в отчёте вообще не было бы.

## Другие применения рекурсии

Рекурсия подходит для обхода иерархий: дерева руководителей по столбцу `employees.manager_id`, категорий с вложенными подкатегориями, ответов на комментарии. Начальная часть выбирает корень дерева, шаг находит всех прямых потомков уже найденных строк. Для шага нужно соединить таблицу с самой собой, поэтому такой пример появится в разделе о соединениях, а здесь мы ограничились рядами значений.

## Предупреждения

Рекурсивный запрос легко сделать бесконечным, если условие остановки неверно или данные зациклены, например сотрудник оказался собственным руководителем. Для защиты задавайте границу и следите, чтобы шаг гарантированно приближался к ней. В случае сомнений добавляйте счётчик уровней и ограничивайте его в WHERE.
