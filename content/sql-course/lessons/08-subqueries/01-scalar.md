Подзапрос - это запрос SELECT, записанный в скобках внутри другого запроса. Самый простой случай - скалярный подзапрос: он возвращает ровно одну строку с одним столбцом, то есть одно значение. Такой подзапрос можно ставить везде, где допускается число, строка или дата.

Начнём с задачи, которую без подзапроса не решить. Нужно найти сотрудников, которые получают больше средней зарплаты по компании. Сначала посмотрим, чему равна эта средняя:

```sql run=company
SELECT AVG(salary) FROM employees;
```

Можно запомнить число и подставить его в следующий запрос руками. Но данные меняются, и тогда число устареет. Лучше доверить это базе: поставим первый запрос в скобки и используем как значение.

```sql run=company
SELECT full_name, salary
FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees)
ORDER BY salary DESC, id;
```

База выполняет внутренний запрос первым, получает одно число и сравнивает с ним зарплату каждого сотрудника. Внутренний запрос выполняется один раз, а не для каждой строки.

## Почему агрегат нельзя написать прямо в WHERE

Новичок обычно пробует более короткую запись: `WHERE salary > AVG(salary)`. PostgreSQL её не принимает:

```sql run=company error
SELECT full_name FROM employees WHERE salary > AVG(salary);
```

Условие WHERE проверяется для каждой строки по отдельности, а среднее вычисляется по всем строкам сразу. Подзапрос решает эту проблему: он сначала считает среднее отдельно, и только потом результат используется как обычное число.

## Подзапрос со своим условием

Внутри скобок пишется полноценный запрос, в том числе со своим WHERE. Например, найдём сотрудников, которые получают больше, чем кто-либо в отделе продаж (отдел с `id` равным 3):

```sql run=company
SELECT full_name, salary
FROM employees
WHERE salary > (SELECT MAX(salary) FROM employees WHERE department_id = 3)
ORDER BY id;
```

Условие `department_id = 3` относится только к подзапросу. Внешний запрос продолжает смотреть на всех сотрудников.

## Скалярный подзапрос в разных местах

Раз подзапрос заменяет значение, его можно поставить в любое место, где значение уместно. Чаще всего он стоит справа от знака сравнения, но подойдут и другие позиции. Например, в списке SELECT, чтобы показать рядом с товаром среднюю цену:

```sql run=shop
SELECT title, price, (SELECT ROUND(AVG(price), 2) FROM products) AS avg_price
FROM products
ORDER BY id
LIMIT 3;
```

В третьем столбце у всех строк одно и то же число: подзапрос не зависит от текущей строки. Подзапросы, которые зависят от внешней строки, разобраны в уроке про коррелированные подзапросы.

## Сколько значений вернёт подзапрос

Скалярный подзапрос обязан вернуть не больше одной строки. Если строк окажется больше, PostgreSQL остановит запрос с ошибкой:

```sql run=company error
SELECT full_name FROM employees
WHERE salary = (SELECT salary FROM employees WHERE department_id = 1);
```

В отделе разработки четыре сотрудника, подзапрос вернул четыре зарплаты, и сравнивать с ними одно значение база отказывается. Если вам нужно сравнить с несколькими значениями, используйте IN или ANY и ALL, о них следующие уроки. А если нужно одно значение, получите его агрегатом: MAX, MIN, AVG.

Если строк нет совсем, ошибки не будет: подзапрос вернёт NULL. Сравнение с NULL никогда не бывает истинным, поэтому условие не выполнится ни для одной строки:

```sql run=company
SELECT full_name FROM employees
WHERE salary > (SELECT MAX(salary) FROM employees WHERE department_id = 99);
```

Результат пуст, и база не сообщает о причине. Такой запрос легко принять за правильный, поэтому, когда результат оказался пустым, проверьте, что подзапрос действительно что-то находит.

## Строки с крайним значением

Задача «найти самую дорогую книгу» кажется простой: отсортировать и взять первую строку.

```sql run=library
SELECT title, price FROM books ORDER BY price DESC LIMIT 1;
```

Но в этом запросе есть две проблемы. Во-первых, если несколько книг стоят одинаково, вы получите только одну из них, и какую именно, заранее неизвестно. Во-вторых, PostgreSQL ставит NULL выше всех значений при сортировке по убыванию, и первой строкой может оказаться книга с неизвестной ценой. Именно это произошло выше.

Подзапрос с MAX решает обе проблемы:

```sql run=library
SELECT title, price
FROM books
WHERE price = (SELECT MAX(price) FROM books)
ORDER BY id;
```

MAX пропускает NULL, а равенство отбирает все строки с максимальной ценой, сколько бы их ни было. Проверим на данных с ничьей:

```sql run=empty
WITH scores(student, points) AS (
  VALUES ('Аня', 90), ('Боря', 85), ('Вика', 90)
)
SELECT student, points
FROM scores
WHERE points = (SELECT MAX(points) FROM scores)
ORDER BY student;
```

Оба студента с наилучшим баллом попали в результат. Запрос с LIMIT 1 показал бы одного из них.

## Вторая по величине зарплата

Часто спрашивают «второе по величине значение». Подзапрос позволяет найти его без сортировки и OFFSET: нужно найти максимум среди значений, которые меньше общего максимума.

```sql run=company
SELECT MAX(salary) AS second_salary
FROM employees
WHERE salary < (SELECT MAX(salary) FROM employees);
```

Этот приём работает и при повторах. Если две самые высокие зарплаты равны, оба сотрудника отсекаются условием, и вторым считается следующее меньшее значение.

## В MySQL

Скалярные подзапросы в MySQL записываются так же. Отличие проявляется при изменении данных: MySQL не разрешает в UPDATE и DELETE выбирать в подзапросе из той же таблицы, которую меняют, и требует обходных путей. В PostgreSQL такого ограничения нет.
