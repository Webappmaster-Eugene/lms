До сих пор подзапросы стояли в WHERE. Но SELECT-запрос возвращает таблицу, а таблица может стоять в двух других местах: в списке столбцов, если она состоит из одной ячейки, и в FROM, если нужна целая таблица.

## Подзапрос в списке SELECT

Скалярный подзапрос в списке столбцов добавляет в результат вычисляемый столбец. Покажем зарплату каждого сотрудника и её отличие от средней по компании:

```sql run=company
SELECT
  full_name,
  salary,
  ROUND(salary - (SELECT AVG(salary) FROM employees), 2) AS diff
FROM employees
ORDER BY id;
```

Средняя зарплата считается один раз, а потом вычитается из зарплаты каждой строки. Положительные значения означают зарплату выше средней, отрицательные - ниже.

Подзапрос здесь заменил то, что без него потребовало бы двух отдельных запросов. Без подзапроса смешивать обычный столбец с агрегатом в одном SELECT нельзя:

```sql run=company error
SELECT full_name, AVG(salary) FROM employees;
```

PostgreSQL требует, чтобы столбец, не входящий в агрегат, был в GROUP BY. Подзапрос обходит это, потому что агрегат считается внутри него, отдельно от внешнего запроса.

## Доля от общей суммы

Подзапрос в SELECT часто используют для долей и процентов. Найдём, какую долю общего числа страниц библиотеки занимает каждая книга:

```sql run=library
SELECT
  title,
  pages,
  ROUND(100.0 * pages / (SELECT SUM(pages) FROM books), 1) AS share_percent
FROM books
ORDER BY id;
```

Число `100.0` с десятичной точкой нужно, чтобы деление было дробным. Если разделить целое на целое, PostgreSQL отбросит дробную часть, и округлять до десятых будет уже нечего.

## Подзапрос в FROM

Подзапрос в FROM работает как временная таблица, которая существует только на время запроса. Псевдоним у неё принято давать всегда: до PostgreSQL 16 его отсутствие было ошибкой, как и сейчас в MySQL, а ссылаться на подзапрос по имени всё равно удобнее. Здесь псевдоним - `t`:

```sql run=company
SELECT *
FROM (
  SELECT department_id, ROUND(AVG(salary), 2) AS avg_salary
  FROM employees
  GROUP BY department_id
) AS t
ORDER BY department_id;
```

Внутренний запрос строит таблицу из двух столбцов: номер отдела и средняя зарплата. Внешний запрос получает её как обычную таблицу, и столбцы доступны под теми именами, которые заданы во внутреннем: `department_id` и `avg_salary`. Поэтому внутри подзапроса полезно давать вычисляемым столбцам псевдонимы.

В последней строке результата номер отдела пуст: это группа сотрудников без отдела, и PostgreSQL ставит её в конец.

## Агрегат над агрегатом

Некоторые задачи требуют двух агрегирований подряд. Например, среднее из средних зарплат по отделам. Записать `AVG(AVG(salary))` нельзя, и именно в этом подзапрос в FROM незаменим: внутренний запрос получает значения по отделам, внешний усредняет их.

```sql run=company
SELECT ROUND(AVG(avg_salary), 2) AS avg_of_avg
FROM (
  SELECT AVG(salary) AS avg_salary
  FROM employees
  WHERE department_id IS NOT NULL
  GROUP BY department_id
) AS t;
```

Это число не равно общей средней зарплате: общая считается по сотрудникам, и большие отделы влияют на неё сильнее, а в среднем из средних каждый отдел имеет один голос.

Тот же приём отвечает на вопрос «сколько групп с таким-то свойством». Посчитаем отделы, где больше одного сотрудника:

```sql run=company
SELECT COUNT(*) AS big_departments
FROM (
  SELECT department_id
  FROM employees
  WHERE department_id IS NOT NULL
  GROUP BY department_id
  HAVING COUNT(*) > 1
) AS t;
```

Внутренний запрос оставляет по одной строке на отдел, внешний считает их количество. Без подзапроса посчитать число групп одним запросом не получилось бы: COUNT считает строки, а группы появляются только после GROUP BY.

## Сумма заказа, затем среднее

В магазине сумма заказа нигде не хранится, её нужно считать по позициям. Чтобы узнать среднюю сумму заказа, сначала получим сумму по каждому заказу, а потом усредним:

```sql run=shop
SELECT ROUND(AVG(total), 2) AS avg_order_total
FROM (
  SELECT order_id, SUM(quantity * price) AS total
  FROM order_items
  GROUP BY order_id
) AS t;
```

Если усреднить `quantity * price` сразу, получится средняя стоимость позиции, а не заказа. Подзапрос меняет единицу, по которой считается среднее: позиция или заказ.

## Отбор по результату группировки

Фильтровать сгруппированные значения можно тремя способами: HAVING, подзапросом в FROM с обычным WHERE или подзапросом в WHERE. Для простого отбора лучше HAVING, он короче. Подзапрос в FROM нужен, когда над сгруппированным результатом требуется ещё какая-то работа: ещё одна группировка, сортировка по вычисленному выражению или соединение с другой таблицей.

```sql run=shop
SELECT category_id, avg_price
FROM (
  SELECT category_id, ROUND(AVG(price), 2) AS avg_price
  FROM products
  GROUP BY category_id
) AS t
WHERE avg_price > 10000
ORDER BY category_id;
```

Запрос возвращает категории, где средняя цена больше десяти тысяч. Такой же результат дал бы HAVING с `AVG(price) > 10000`.

## Порядок выполнения

Подзапрос в FROM выполняется первым, и внешний запрос видит только его готовые столбцы, а не исходную таблицу. Например, во внешнем запросе нельзя сослаться на `salary`, если во внутреннем она не выбрана. Список столбцов внутреннего запроса - это и есть интерфейс подзапроса.

## В MySQL

В MySQL подзапрос в FROM называется производной таблицей (derived table), и псевдоним у неё обязателен. Поведение в остальном совпадает. В PostgreSQL перед таким подзапросом можно поставить LATERAL: тогда он может ссылаться на строки таблицы, стоящей левее в FROM. В MySQL это появилось только в версии 8.0.14. LATERAL пригодится после изучения соединений.
