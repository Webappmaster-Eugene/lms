Почти любое приложение хранит данные: пользователей, заказы, сообщения, платежи. Хранить их в обычных файлах неудобно. Файл трудно читать нескольким программам одновременно, в нём легко потерять запись при сбое, а найти нужную строку среди миллиона можно только перебором. Поэтому данные держат в базе данных, а работает с ней отдельная программа, система управления базами данных, или СУБД.

## Таблицы, строки и столбцы

В реляционной базе данные лежат в таблицах. Таблица похожа на лист в электронной таблице, но со строгими правилами. У неё есть имя и фиксированный набор столбцов. У каждого столбца есть имя и тип: целое число, текст, дата, денежная сумма. Строка таблицы описывает один объект, например одного сотрудника, а столбцы хранят его свойства.

Вот небольшая таблица отделов компании, с которой мы будем работать весь курс:

```tables company departments
```

В таблице четыре столбца: номер отдела, название, город и бюджет. Пятая строка показывает важную деталь: город отдела аналитики не указан. Пустое значение в базах данных называется NULL. Это не ноль и не пустая строка, а отметка «значение неизвестно». Работе с NULL в курсе посвящён отдельный урок.

## Первичный ключ

Столбец `id` хранит номер, который не повторяется. Такой столбец называют первичным ключом. По нему строку можно найти однозначно, даже если два отдела однажды получат одинаковые названия. Первичный ключ есть почти у каждой таблицы.

Таблицы связываются между собой через такие номера. У сотрудника в таблице `employees` есть столбец `department_id`, и в нём записан номер отдела из таблицы `departments`. Поэтому базу и называют реляционной: от английского relation, отношение между данными.

## SQL

С базой данных разговаривают на языке SQL. Это язык запросов: вы описываете, какие данные нужны, а СУБД сама решает, как их найти. Например, этот запрос просит показать названия отделов из Москвы:

```sql run=company
SELECT name
FROM departments
WHERE city = 'Москва';
```

Запрос читается почти как фраза: выбрать название из таблицы отделов, где город равен «Москва». Под запросом показан результат, который вернула база. Так будет во всех уроках: примеры выполнены настоящим PostgreSQL на учебных данных.

SQL делится на несколько частей. Запросы на чтение данных начинаются с SELECT, и им посвящена большая часть курса. Команды INSERT, UPDATE и DELETE добавляют, меняют и удаляют строки. Команды CREATE, ALTER и DROP описывают саму структуру: какие таблицы есть и какие у них столбцы. Отдельно стоят транзакции, которые объединяют несколько изменений в одно целое.

## Почему PostgreSQL

Основа SQL одинакова во всех популярных СУБД: PostgreSQL, MySQL, SQLite, Microsoft SQL Server, Oracle. Различаются детали, чаще всего функции для дат и строк. В курсе используется PostgreSQL. Это свободная СУБД, её выбирают для большинства новых проектов, и её же вы встретите в бэкенд-разработке на Node.js, Python и Go. Если позже придётся работать с другой СУБД, перейти будет просто: запросы из курса почти всегда переносятся с небольшими правками.

Регистр в SQL неважен: `select`, `SELECT` и `Select` означают одно и то же. В курсе ключевые слова пишутся заглавными буквами, а имена таблиц и столбцов строчными. Так запрос легче читать. Точка с запятой в конце отделяет один запрос от другого. В тренажёре её можно не ставить, если запрос один.
