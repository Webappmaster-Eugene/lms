Обычный запрос возвращает строки таблицы, по одной на строку. Агрегатная функция делает другое: она читает много строк и возвращает одно значение. Сумма зарплат, самая высокая цена, средняя длина книги - всё это агрегаты. Основных пять: COUNT считает, SUM складывает, AVG усредняет, MIN и MAX находят наименьшее и наибольшее значение. COUNT разобран в следующем уроке, здесь остальные четыре.

## Одна строка вместо многих

Если в SELECT стоит агрегат, а группировки нет, вся таблица сворачивается в одну строку:

```sql run=company
SELECT SUM(salary) AS total_salary FROM employees;
```

Агрегатов в запросе может быть несколько, и считаются они за один проход по таблице:

```sql run=company
SELECT
  MIN(salary) AS lowest,
  MAX(salary) AS highest,
  ROUND(AVG(salary), 2) AS average
FROM employees;
```

Псевдонимы здесь не прихоть. Без `AS` столбец получит имя функции, например `sum` или `max`, и работать с таким именем неудобно.

Внутри агрегата можно писать выражение, а не только имя столбца. Сначала оно считается для каждой строки, потом результаты сворачиваются:

```sql run=shop
SELECT SUM(price * stock) AS stock_value FROM products;
```

## WHERE работает до агрегата

Условие в WHERE отбирает строки ещё до того, как агрегат начнёт считать. Так получают среднюю зарплату одного отдела:

```sql run=company
SELECT ROUND(AVG(salary), 2) AS avg_salary
FROM employees
WHERE department_id = 1;
```

Сначала остаются четыре сотрудника отдела 1, потом по ним считается среднее. Условие на результат агрегата в WHERE написать нельзя: на этом этапе результата ещё нет. Для этого есть HAVING, ему посвящён отдельный урок.

## Агрегаты пропускают NULL

Самое важное свойство агрегатов: пустые значения они не учитывают. У книги "Хроники заводной птицы" цена не указана. Посмотрим, что делает AVG:

```sql run=library
SELECT
  COUNT(*) AS all_books,
  COUNT(price) AS with_price,
  SUM(price) AS total,
  ROUND(AVG(price), 2) AS average
FROM books;
```

Книг десять, а цена есть у девяти. Среднее посчитано как сумма девяти цен, делённая на девять, а не на десять. Если бы пустая цена считалась нулём, среднее оказалось бы ниже. Для MIN и MAX работает то же правило: NULL не может быть ни наименьшим, ни наибольшим.

Если нужно именно считать пустое значение нулём, это нужно сказать явно. Функция COALESCE подставляет запасное значение:

```sql run=library
SELECT ROUND(AVG(COALESCE(price, 0)), 2) AS average_with_zero FROM books;
```

Теперь делитель равен десяти, и среднее ниже. Какой вариант правильный, зависит от смысла: "средняя цена книг с известной ценой" и "средняя цена, если неизвестную считать бесплатной" - разные величины.

## Среднее от целых

В некоторых системах среднее от целых чисел тоже получается целым. В PostgreSQL это не так: AVG от integer возвращает тип numeric с дробной частью.

```sql run=library
SELECT AVG(pages) AS raw_average, ROUND(AVG(pages), 1) AS rounded FROM books;
```

Приводить столбец к дробному типу заранее не нужно. Округление - отдельный шаг, ROUND ставят снаружи агрегата. Первым аргументом ROUND с двумя параметрами должен быть numeric, а AVG как раз его и возвращает.

## MIN и MAX не только для чисел

Эти две функции работают с любым типом, который можно упорядочить: с датами и с текстом тоже.

```sql run=company
SELECT
  MIN(hire_date) AS first_hired,
  MAX(hire_date) AS last_hired,
  MIN(full_name) AS first_by_alphabet
FROM employees;
```

Для даты "меньше" значит "раньше". Для текста порядок определяет правило сортировки базы, как и в ORDER BY. MIN возвращает минимальное значение одного столбца, а не строку целиком. Узнать по нему, какой сотрудник получает минимум, нельзя: это отдельная задача, и её решают другими приёмами.

## Сумма пустого набора

Что вернёт SUM, если ни одна строка не подошла под WHERE?

```sql run=company
SELECT SUM(salary) AS total, COUNT(*) AS people FROM employees WHERE salary > 1000000;
```

COUNT вернул 0, а SUM вернул NULL. Это логично: сумма ничего не определена, как и среднее или минимум пустого набора. AVG, MIN и MAX тоже вернут NULL. Если приложению нужен ноль, оберните агрегат в COALESCE:

```sql run=company
SELECT COALESCE(SUM(salary), 0) AS total FROM employees WHERE salary > 1000000;
```

Эту ошибку легко пропустить: на тестовых данных строки находятся, а на пустой выборке отчёт вдруг показывает пустое место вместо нуля.

## Агрегат и обычный столбец вместе

Попытка вывести рядом с агрегатом обычный столбец без группировки заканчивается ошибкой:

```sql run=company error
SELECT full_name, MAX(salary) FROM employees;
```

База не знает, какое из двенадцати имён показать рядом с одним максимумом. Чтобы сочетать столбцы и агрегаты, нужна группировка, и ей посвящён урок про GROUP BY.

## В MySQL и других системах

Названия SUM, AVG, MIN и MAX одинаковы во всех популярных системах. Различается поведение среднего от целых: в PostgreSQL оно дробное, как показано выше. Работа с NULL везде одна: агрегаты пропускают пустые значения.
