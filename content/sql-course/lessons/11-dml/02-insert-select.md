Вместо списка VALUES в INSERT можно поставить запрос SELECT. Строки результата добавятся в таблицу так, будто их перечислили вручную. Это основной способ копировать данные между таблицами, заполнять сводные таблицы и генерировать тестовые наборы.

## Копирование строк

Сначала подготовим архивную таблицу прямо в примере. Столбцы в списке INSERT и в SELECT должны совпадать по числу и по порядку, а имена могут быть любыми:

```sql run=library
CREATE TABLE old_books (
  id integer PRIMARY KEY,
  title text NOT NULL,
  published_year integer
);

INSERT INTO old_books (id, title, published_year)
SELECT id, title, published_year
FROM books
WHERE published_year < 1870;

SELECT * FROM old_books ORDER BY id;
```

В SELECT работает всё, что вы уже знаете: WHERE, соединения, группировка, подзапросы. Исходная таблица при этом не меняется.

## Константы и выражения в SELECT

В списке SELECT можно писать значения, которых нет в источнике. Так копируемые строки получают дату архивации или пометку:

```sql run=library
CREATE TABLE old_books (
  id integer PRIMARY KEY,
  title text NOT NULL,
  archived_on date NOT NULL
);

INSERT INTO old_books (id, title, archived_on)
SELECT id, title, DATE '2026-05-01'
FROM books
WHERE published_year < 1850;

SELECT * FROM old_books ORDER BY id;
```

Запись `DATE '2026-05-01'` явно говорит, что текст это дата. Функции вроде `now()` здесь тоже допустимы, но в примерах курса мы их не используем: результат менялся бы с каждым днём.

## Сводные таблицы

Запрос с группировкой тоже можно вставить. Вот сводка по жанрам:

```sql run=library
CREATE TABLE genre_stats (
  genre text PRIMARY KEY,
  books_count integer NOT NULL,
  avg_pages numeric(8, 1)
);

INSERT INTO genre_stats (genre, books_count, avg_pages)
SELECT genre, count(*), round(avg(pages), 1)
FROM books
GROUP BY genre;

SELECT * FROM genre_stats ORDER BY genre;
```

Такие таблицы пересчитывают по расписанию и читают быстро, не выполняя тяжёлую группировку при каждом открытии отчёта.

## Генерация строк

Функция `generate_series` выдаёт последовательность чисел или дат. В паре с INSERT ... SELECT она создаёт нужное число строк без ручного перечисления:

```sql run=empty
CREATE TABLE slots (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  title text NOT NULL,
  capacity integer NOT NULL DEFAULT 10
);

INSERT INTO slots (title)
SELECT 'Слот ' || n FROM generate_series(1, 4) AS n;

SELECT * FROM slots ORDER BY id;
```

В MySQL у этой функции нет аналога, там используют рекурсивный запрос WITH RECURSIVE или вспомогательную таблицу чисел.

## Дублирование связанных строк

Типичная задача: повторить заказ. Сначала создаётся новый заказ, затем в него копируются позиции старого. Номер нового заказа записывается в SELECT константой:

```sql run=shop
INSERT INTO orders (id, customer_id, ordered_at, status)
VALUES (20, 1, '2026-05-01 10:00:00', 'new');

INSERT INTO order_items (order_id, product_id, quantity, price)
SELECT 20, product_id, quantity, price
FROM order_items
WHERE order_id = 8;

SELECT order_id, product_id, quantity, price
FROM order_items
WHERE order_id IN (8, 20)
ORDER BY order_id, product_id;
```

Здесь важен порядок. Сначала строка в `orders`, потому что позиции ссылаются на неё внешним ключом. Потом копирование.

## Чтение и запись одной таблицы

Источником может быть та же таблица, в которую вставляют. PostgreSQL читает данные на момент начала запроса, поэтому новые строки в чтение не попадают и запрос не уходит в бесконечность:

```sql run=shop
INSERT INTO products (id, title, category_id, price, stock, added_on)
SELECT id + 100, title || ' (уценка)', category_id, round(price * 0.9, 2), stock, added_on
FROM products
WHERE category_id = 3;

SELECT id, title, price FROM products WHERE id > 100 ORDER BY id;
```

Новые номера получены как `id + 100`, чтобы не повторить существующие ключи. Если ключ повторится, запрос закончится ошибкой, и не добавится ни одна строка. Как поступать с повторами, разберём в уроке про ON CONFLICT.

## Отличия от MySQL

Синтаксис `INSERT ... SELECT` в обеих базах одинаков. Для копирования таблицы вместе с данными в PostgreSQL есть отдельная форма `CREATE TABLE ... AS SELECT`: она создаёт новую таблицу сразу с данными, но без ограничений и без значений по умолчанию. Для рабочих таблиц лучше сначала создать структуру, а потом вставлять строки.
