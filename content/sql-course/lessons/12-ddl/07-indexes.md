Без индекса PostgreSQL ищет нужные строки, просматривая таблицу целиком. Для таблицы в десять строк это мгновенно, для таблицы в десять миллионов - долго. Индекс - это отдельная структура, которая хранит значения столбца в упорядоченном виде вместе со ссылками на строки, как предметный указатель в книге. По индексу нужную строку находят за несколько шагов, не читая остальные.

Цена индекса: он занимает место и замедляет вставку, изменение и удаление, потому что вместе со строкой нужно обновить и индекс. Поэтому индексы создают под реальные запросы, а не на каждый столбец.

## Обычный индекс

```sql run=company
CREATE INDEX idx_employees_department ON employees (department_id);
SELECT indexname, indexdef
FROM pg_indexes
WHERE tablename = 'employees'
ORDER BY indexname;
```

Команда задаёт имя индекса, таблицу и столбец в скобках. Первичный ключ уже имеет индекс: PostgreSQL создаёт его сам, и вы видите `employees_pkey` в результате. Тип индекса по умолчанию - `btree`, он подходит для сравнений и сортировки. Имя можно не писать, тогда PostgreSQL придумает его сам (`CREATE INDEX ON employees (department_id)`), но у явного имени есть преимущество: по нему индекс удобно удалять.

## Уникальный индекс

```sql run=shop
CREATE UNIQUE INDEX idx_customers_email ON customers (email);
SELECT indexdef FROM pg_indexes WHERE tablename = 'customers' ORDER BY indexname;
```

Уникальный индекс одновременно ускоряет поиск и запрещает повторы. С ограничением UNIQUE он работает одинаково: оба создают индекс, а ограничение просто удобнее объявить в описании таблицы. Если в столбце уже есть дубли, создание индекса завершится ошибкой.

## Составной индекс

Индекс может покрывать несколько столбцов:

```sql run=library
CREATE INDEX idx_books_author_year ON books (author_id, published_year);
SELECT indexdef FROM pg_indexes WHERE tablename = 'books' ORDER BY indexname;
```

Порядок столбцов здесь решает всё. Индекс упорядочен сначала по `author_id`, а внутри одного автора - по году. Он помогает запросам по `author_id` и по паре `author_id` и `published_year`. Запрос только по году индекс почти не ускорит: как в телефонной книге, где фамилии идут по алфавиту, искать по имени без фамилии неудобно. Правило: сначала столбцы с условием равенства, потом столбец с диапазоном или сортировкой.

## Индекс по выражению

Если в условии к столбцу применена функция, обычный индекс не сработает: база сравнивает не значение столбца, а результат функции. Для таких запросов индекс строят по самому выражению:

```sql run=shop
CREATE INDEX idx_customers_email_lower ON customers (lower(email));
SELECT indexdef FROM pg_indexes WHERE tablename = 'customers' ORDER BY indexname;
```

Теперь запрос `WHERE lower(email) = 'vera@mail.example'` может воспользоваться индексом. Условие в запросе должно содержать то же выражение, что и индекс.

## Частичный индекс

Если запросы касаются небольшой части строк, индекс можно построить только по ней. Условие записывают в WHERE:

```sql run=shop
CREATE INDEX idx_orders_new_customer ON orders (customer_id) WHERE status = 'new';
SELECT indexdef FROM pg_indexes WHERE tablename = 'orders' ORDER BY indexname;
```

Такой индекс меньше и обновляется только при изменении «новых» заказов. Работает он для запросов, где то же условие `status = 'new'` стоит в WHERE. Частичный уникальный индекс решает ещё одну задачу: уникальность только среди части строк, например среди неудалённых записей.

## Направление и имя

Для каждого столбца индекса можно указать направление сортировки: `ASC` (по умолчанию) или `DESC`. Это нужно запросам, которые сортируют разные столбцы в разном направлении:

```sql run=shop
CREATE INDEX idx_products_cat_price ON products (category_id, price DESC);
SELECT indexname, indexdef FROM pg_indexes WHERE tablename = 'products' AND indexname = 'idx_products_cat_price';
```

## Удаление индекса

```sql run=library
CREATE INDEX idx_books_year ON books (published_year);
DROP INDEX idx_books_year;
SELECT count(*) AS indexes_on_books FROM pg_indexes WHERE tablename = 'books';
```

DROP INDEX в PostgreSQL принимает только имя индекса. В MySQL пишут `DROP INDEX имя ON таблица`, здесь таблицу указывать не надо. Слова `IF EXISTS` убирают ошибку, если такого индекса нет. Индексы первичного ключа и ограничений UNIQUE отдельной командой не удаляются: убирают само ограничение через ALTER TABLE.

## Когда индекс не помогает

Индекс есть, а база всё равно читает всю таблицу. Бывает так по нескольким причинам.

Таблица маленькая. Просмотреть десять строк быстрее, чем идти в индекс, и планировщик справедливо выберет полный просмотр.

Условие выбирает большую часть таблицы. Если запрос возвращает половину строк, читать через индекс дороже, чем подряд.

Столбец обёрнут функцией или вычислением: `WHERE price * 2 > 100` или `WHERE lower(email) = ...` без индекса по этому выражению. Условие нужно переписать в виде `price > 50` или создать индекс по выражению.

Условие `LIKE '%слово'` с процентом в начале: упорядоченный индекс помогает искать по началу строки, а не по произвольной середине.

В составном индексе пропущен первый столбец.

Разбираться в таких случаях помогает EXPLAIN, ему посвящён отдельный раздел. А список индексов, который видит PostgreSQL, всегда доступен в `pg_indexes`: аналог `SHOW INDEX` из MySQL.

## Что запомнить

Индекс ускоряет чтение и замедляет запись. Создавайте его под запросы, которые идут часто. В составном индексе важен порядок столбцов. Для запросов с функцией нужен индекс по выражению, для узкой выборки - частичный. Лишние и дублирующие индексы удаляйте.
