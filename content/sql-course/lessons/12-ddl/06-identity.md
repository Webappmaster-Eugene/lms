Первичному ключу нужен уникальный номер. Придумывать его вручную неудобно, поэтому база умеет выдавать номера сама. В MySQL для этого служил `AUTO_INCREMENT`. В PostgreSQL есть два способа: современный `GENERATED ... AS IDENTITY` и старый `serial`.

## GENERATED ALWAYS AS IDENTITY

```sql run=empty
CREATE TABLE tickets (
  id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  title text NOT NULL
);
INSERT INTO tickets (title) VALUES ('Не работает вход'), ('Нет письма'), ('Ошибка оплаты');
SELECT * FROM tickets;
```

Столбец `id` в INSERT не указан, и база выдаёт 1, 2, 3 по порядку. Под столбцом скрыта последовательность (sequence): отдельный объект, который хранит текущее число и выдаёт следующее. Номер, который уже выдан, не возвращается: если вставку откатить или строку удалить, в нумерации остаётся пропуск. Пропуски в номерах - это нормально, и рассчитывать на то, что номера идут без пробелов, нельзя.

Вариант ALWAYS не даёт записать номер вручную, попытка вызывает ошибку:

```sql run=empty error
CREATE TABLE tickets (
  id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  title text NOT NULL
);
INSERT INTO tickets (id, title) VALUES (100, 'Свой номер');
```

## GENERATED BY DEFAULT

Вариант BY DEFAULT выдаёт номер сам, но позволяет указать свой. Он нужен при переносе данных с готовыми номерами. Здесь ловушка: последовательность ничего не знает о номерах, вставленных вручную.

```sql run=empty error
CREATE TABLE notes (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  body text
);
INSERT INTO notes (id, body) VALUES (1, 'Первая'), (2, 'Вторая');
INSERT INTO notes (body) VALUES ('Третья');
```

Счётчик ещё стоит на единице, и новая строка получает номер 1, который уже занят. Чтобы этого не случилось, после переноса передвигают последовательность функцией setval. Имя последовательности вычислять не нужно: его возвращает `pg_get_serial_sequence`.

```sql run=empty
CREATE TABLE notes (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  body text
);
INSERT INTO notes (id, body) VALUES (1, 'Первая'), (2, 'Вторая');
SELECT setval(pg_get_serial_sequence('notes', 'id'), (SELECT max(id) FROM notes));
INSERT INTO notes (body) VALUES ('Третья');
SELECT * FROM notes ORDER BY id;
```

## Параметры счётчика

В скобках после IDENTITY можно задать, с какого числа начинать и с каким шагом идти:

```sql run=empty
CREATE TABLE invoices (
  number integer GENERATED ALWAYS AS IDENTITY (START WITH 1000 INCREMENT BY 10) PRIMARY KEY,
  customer text NOT NULL
);
INSERT INTO invoices (customer) VALUES ('Вера'), ('Олег'), ('Дарья');
SELECT * FROM invoices;
```

Для столбца, в котором номеров может оказаться больше двух миллиардов, берут тип `bigint` вместо integer.

## serial

Старая запись - тип `serial`. Он не настоящий тип: PostgreSQL заменяет его на integer, создаёт последовательность и ставит значением по умолчанию вызов `nextval`:

```sql run=empty
CREATE TABLE visits (
  id serial PRIMARY KEY,
  page text NOT NULL
);
INSERT INTO visits (page) VALUES ('/'), ('/about');
SELECT column_name, data_type, column_default
FROM information_schema.columns
WHERE table_name = 'visits'
ORDER BY ordinal_position;
```

Бывают три размера: `smallserial`, `serial` и `bigserial`. В новых таблицах лучше брать IDENTITY: он стандартный, привязан к столбцу строже и не позволяет случайно записать лишнее при варианте ALWAYS. С serial вы встретитесь в старых проектах, так что его нужно уметь читать.

## Добавить IDENTITY к готовому столбцу

Если таблица уже есть, а номера нужны только теперь, столбец превращают в IDENTITY командой ALTER TABLE. Столбец должен быть NOT NULL, а старые значения остаются.

```sql run=shop
CREATE TABLE sections (
  id integer PRIMARY KEY,
  title text NOT NULL
);
INSERT INTO sections (id, title) SELECT id, title FROM categories;
ALTER TABLE sections ALTER COLUMN id ADD GENERATED BY DEFAULT AS IDENTITY (START WITH 100);
INSERT INTO sections (title) VALUES ('Новинки');
SELECT * FROM sections ORDER BY id;
```

Новый номер начинается со ста, поэтому не конфликтует с перенесёнными. Убрать автоматическую выдачу можно командой `ALTER COLUMN id DROP IDENTITY`. Передвинуть счётчик - `ALTER COLUMN id RESTART WITH 500`.

## RETURNING

Часто сразу после вставки нужно узнать выданный номер. Для этого у INSERT есть RETURNING: он возвращает указанные столбцы вставленных строк, как SELECT:

```sql run=empty
CREATE TABLE tickets (
  id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  title text NOT NULL
);
INSERT INTO tickets (title) VALUES ('Первая'), ('Вторая') RETURNING id, title;
```

RETURNING есть и у UPDATE, и у DELETE. В MySQL для этого пользовались функцией `LAST_INSERT_ID()`, но при вставке нескольких строк она возвращала номер только первой из них. В PostgreSQL вернуть можно сразу все.

## Что запомнить

Новые таблицы делают с `GENERATED ALWAYS AS IDENTITY` или `BY DEFAULT`, если планируется перенос данных. Пропуски в номерах нормальны. После вставки номеров вручную передвиньте счётчик через setval. Узнать выданный номер можно через RETURNING.
