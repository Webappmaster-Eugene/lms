Два оставшихся вида соединения встречаются реже, чем INNER и LEFT, но каждый решает свою задачу. FULL JOIN сохраняет строки обеих таблиц, а CROSS JOIN вообще не ищет пары и сочетает всё со всем.

## FULL JOIN

LEFT JOIN сохраняет строки левой таблицы, RIGHT JOIN - правой, FULL JOIN - и тех и других. Если у строки есть пара, они соединяются, как обычно. Если пары нет, строка всё равно попадает в результат, а столбцы другой стороны заполняются NULL.

```sql run=company
SELECT d.name AS department, e.full_name
FROM departments d
FULL JOIN employees e ON e.department_id = d.id
ORDER BY d.id NULLS LAST, e.id;
```

В конце списка видны две особенные строки. «Аналитика» - отдел без сотрудников: справа пусто. Виктор Зайцев - сотрудник без отдела: слева пусто. В `ORDER BY` стоит NULLS LAST: PostgreSQL по умолчанию и так ставит NULL последними при сортировке по возрастанию, но явная запись показывает намерение. В MySQL FULL JOIN отсутствует, его там заменяют объединением LEFT и RIGHT; в PostgreSQL он есть в готовом виде.

## Поиск расхождений

FULL JOIN хорошо подходит для сверки двух списков: что есть в одном и нет в другом. Оставим только строки без пары с любой стороны:

```sql run=library
SELECT a.full_name AS author, b.title
FROM authors a
FULL JOIN books b ON b.author_id = a.id
WHERE a.id IS NULL OR b.id IS NULL
ORDER BY b.id NULLS LAST, a.id;
```

Получилось две строки: книга без автора («Слово о полку Игореве») и автор без книг (Анна Ахматова). Проверяют пустоту ключа с каждой стороны, потому что неизвестно заранее, с какой стороны не будет пары. Если нужно собрать расхождения в один столбец, помогает COALESCE:

```sql run=company
SELECT COALESCE(d.name, e.full_name) AS name
FROM departments d
FULL JOIN employees e ON e.department_id = d.id
WHERE d.id IS NULL OR e.id IS NULL
ORDER BY name;
```

Такое соединение имеет смысл, когда обе стороны могут оказаться без пары. Если интересует только одна сторона, достаточно LEFT JOIN с проверкой IS NULL, он проще и понятнее.

FULL JOIN допускает только условия соединения вида «столбец равен столбцу» или другие, которые база умеет вычислять через хеширование или слияние. Если в ON окажется сложное выражение с OR, PostgreSQL ответит ошибкой, что FULL JOIN поддерживается только для условий, допускающих такие методы. Тогда задачу решают иначе, например объединением двух запросов.

## CROSS JOIN

CROSS JOIN даёт декартово произведение: каждая строка левой таблицы сочетается с каждой строкой правой. Условие соединения не нужно, поэтому ON после него писать нельзя.

```sql run=shop
SELECT c.full_name, k.title AS category
FROM customers c
CROSS JOIN categories k
WHERE c.id <= 2
ORDER BY c.id, k.id;
```

Два покупателя и четыре категории дали восемь строк. Вообще количество строк равно произведению количеств: шесть покупателей и четыре категории дадут двадцать четыре. Посчитать, сколько получится, можно заранее:

```sql run=shop
SELECT COUNT(*) AS pairs FROM customers CROSS JOIN products;
```

Шесть на десять, шестьдесят пар. Для двух таблиц по тысяче строк произведение уже миллион, а по сто тысяч - десять миллиардов, и такой запрос съест всю память и время. Поэтому перед CROSS JOIN прикидывайте размеры.

### Когда нужен CROSS JOIN

Основные применения такие: перебрать все сочетания (размеры и цвета, дни и сотрудники), построить сетку для отчёта, чтобы потом присоединить к ней факты, и найти то, чего не хватает. Допустим, нужно перечислить, в какие категории не входят дорогие товары:

```sql run=shop
SELECT p.title AS product, c.title AS category
FROM products p
CROSS JOIN categories c
WHERE p.price > 100000 AND p.category_id IS DISTINCT FROM c.id
ORDER BY p.id, c.id;
```

Только «Ноутбук Pro 16» дороже 100000, и ему достались три чужие категории. Обычное неравенство `p.category_id <> c.id` для товара без категории дало бы неизвестность и потеряло его. IS DISTINCT FROM сравнивает так, будто NULL - обычное значение: NULL отличается от любого числа.

### Сетка из generate_series

Чаще всего CROSS JOIN нужен не между таблицами, а с рядом чисел или дат, который строит функция generate_series. Пример: все пары «номер полки и номер места» без хранения таких данных:

```sql run=empty
SELECT shelf, place
FROM generate_series(1, 2) AS shelf
CROSS JOIN generate_series(1, 3) AS place
ORDER BY shelf, place;
```

Запятая между таблицами в списке FROM - это тоже CROSS JOIN. Запись `FROM a, b` означает `FROM a CROSS JOIN b`, но писать лучше явно.

## Если забыть условие

Типичная ошибка новичка выглядит как внутреннее соединение без ON, только с запятой, или как JOIN с условием, которое не связывает таблицы:

```sql run=company
SELECT COUNT(*) AS rows_count
FROM employees e
JOIN departments d ON d.budget > 0;
```

Условие `d.budget > 0` касается одной таблицы и не связывает сотрудников с отделами. Каждый сотрудник сочетается с каждым отделом, где бюджет положителен. Вместо одиннадцати строк получилось шестьдесят, то есть двенадцать сотрудников на пять отделов. Признак такой ошибки: строк намного больше, чем в любой из таблиц.

## Какое соединение выбрать

Нужны только строки с парой - INNER JOIN. Нужны все строки главной таблицы - LEFT JOIN. Нужна сверка двух таблиц в обе стороны - FULL JOIN. Нужны все сочетания - CROSS JOIN. Выбор делается по вопросу «что должно остаться, если пары нет».
