UNION складывает результаты двух запросов. Ещё две операции над множествами строк отвечают на другие вопросы. INTERSECT оставляет только строки, которые есть в обоих результатах. EXCEPT оставляет строки первого результата, которых нет во втором. Требования к частям те же, что у UNION: одинаковое число столбцов и совместимые типы.

## EXCEPT

Найдём покупателей, у которых нет ни одного заказа. Из всех номеров покупателей вычтем номера тех, кто заказывал:

```sql run=shop
SELECT id FROM customers
EXCEPT
SELECT customer_id FROM orders
ORDER BY id;
```

Результат содержит только Полину Гусеву с номером 6. EXCEPT не симметричен: порядок частей важен. Если поменять их местами, получатся покупатели из заказов, которых нет среди покупателей, и такой результат будет пуст.

EXCEPT убирает повторы в результате, как и UNION. Вариант `EXCEPT ALL` их сохраняет: если значение встречается в первой части три раза, а во второй один, в результате будет два повтора. Он нужен редко.

```sql run=empty
SELECT x FROM (VALUES (1), (1), (1), (2)) AS a(x)
EXCEPT ALL
SELECT x FROM (VALUES (1)) AS b(x)
ORDER BY x;
```

Единица в результате остаётся дважды, потому что один экземпляр вычтен. Обычный EXCEPT вернул бы 1 и 2 по одному разу.

## INTERSECT

Найдём покупателей, у которых были и отправленные, и отменённые заказы:

```sql run=shop
SELECT customer_id FROM orders WHERE status = 'shipped'
INTERSECT
SELECT customer_id FROM orders WHERE status = 'cancelled'
ORDER BY customer_id;
```

В результате остаётся покупатель с номером 1: у него есть заказ 1 в статусе shipped и заказ 3 в статусе cancelled. Такая задача решается и подзапросами с EXISTS, но INTERSECT читается короче, когда обе части однотипны.

Если нужны пересечения из трёх и более запросов, их просто пишут подряд:

```sql run=empty
SELECT x FROM generate_series(1, 10) AS a(x)
INTERSECT
SELECT x FROM generate_series(5, 15) AS b(x)
INTERSECT
SELECT x FROM generate_series(8, 20) AS c(x)
ORDER BY x;
```

Как и UNION, INTERSECT имеет вариант ALL, который учитывает число повторов: берёт наименьшее из двух.

## NULL в INTERSECT и EXCEPT

Здесь есть отличие от обычных сравнений. В WHERE два NULL не равны друг другу, а в операциях над множествами две строки с NULL в одном столбце считаются одинаковыми. Поэтому NULL ведёт себя в EXCEPT и INTERSECT как обычное значение:

```sql run=empty
SELECT x FROM (VALUES (1), (NULL)) AS a(x)
EXCEPT
SELECT x FROM (VALUES (NULL::int)) AS b(x)
ORDER BY x;
```

NULL из первого набора вычтен вторым, осталась только единица. Это одно из отличий EXCEPT от NOT IN: NOT IN из-за NULL в списке не вернул бы ничего. По этой причине EXCEPT иногда удобнее, чем NOT IN. Но следите за NULL в данных: если пустое значение есть и в первой части, и во второй, строки вычитаются или пересекаются, и это может оказаться неожиданным. Ненужные строки с NULL убирают условием `IS NOT NULL` в нужной части.

## Сравнение с подзапросами

Задачи на разность и пересечение можно решить подзапросами, и иногда выбор неочевиден.

Покупатели без заказов через NOT EXISTS:

```sql run=shop
SELECT c.id
FROM customers c
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id)
ORDER BY c.id;
```

Результат тот же. EXCEPT удобен, когда нужен только один столбец, а оба запроса уже написаны. Подзапрос с EXISTS удобнее, когда в результате нужно больше столбцов из первой таблицы. EXCEPT возвращает только столбцы, которые перечислены в его частях, и сравнивает строки целиком. Если нужно вывести имя покупателя, вычитание придётся обернуть в подзапрос и использовать его в IN.

Ещё одно отличие в том, что EXCEPT и INTERSECT убирают повторы. Если в первой части одна и та же строка встречается несколько раз, в результате она будет одна. Подзапросы строки не схлопывают.

## Симметрическая разность

Иногда нужны значения, которые есть ровно в одном из двух наборов: либо только в первом, либо только во втором. Для этого разности объединяют:

```sql run=empty
(SELECT x FROM generate_series(1, 5) AS a(x)
 EXCEPT
 SELECT x FROM generate_series(4, 8) AS b(x))
UNION
(SELECT x FROM generate_series(4, 8) AS b(x)
 EXCEPT
 SELECT x FROM generate_series(1, 5) AS a(x))
ORDER BY x;
```

Из первой разности получаются значения 1, 2, 3, из второй - 6, 7, 8. Значения 4 и 5 есть в обоих наборах, поэтому исчезли.

Таким же образом можно сравнить два периода. Какие товары покупали только до марта 2026 года, а какие только после? Состав заказов лежит в `order_items`, дата - в `orders`, поэтому периоды отбираются подзапросом по номерам заказов. Этот приём понадобится в практике.

## Приоритет операций

Если в одном запросе смешаны разные операции, INTERSECT выполняется раньше, чем UNION и EXCEPT, которые равноправны и идут слева направо. Это различие в приоритете легко забыть, поэтому в составных запросах всегда ставьте скобки. Запрос с явными скобками читается однозначно и не зависит от того, как вы помните правила.

## В MySQL

В MySQL INTERSECT и EXCEPT появились только в версии 8.0.31. В более старых версиях пересечение заменяют соединением или IN, а разность - NOT EXISTS. Версия ALL там тоже поддерживается только в новых релизах. В PostgreSQL все четыре формы (INTERSECT, INTERSECT ALL, EXCEPT, EXCEPT ALL) доступны давно. Oracle называет EXCEPT словом MINUS, но в PostgreSQL используется стандартное EXCEPT.
