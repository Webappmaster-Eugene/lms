Соединения (JOIN) добавляют к строке новые столбцы из другой таблицы. Объединение результатов работает в другую сторону: оно ставит строки одного запроса под строки другого. Столбцов остаётся столько же, а строк становится больше.

Простейший пример - два запроса с одним столбцом:

```sql run=empty
SELECT 1 AS n
UNION
SELECT 2;
```

Каждый запрос, входящий в объединение, называют его частью. Частей может быть сколько угодно.

## UNION ALL

UNION ALL просто дописывает строки второго запроса после строк первого:

```sql run=empty
SELECT 'яблоко' AS fruit
UNION ALL
SELECT 'груша'
UNION ALL
SELECT 'яблоко'
ORDER BY fruit;
```

Яблоко встретилось дважды, и в результате оно тоже дважды. Это самая дешёвая операция: база ничего не сравнивает и не ищет.

## UNION

UNION без ALL дописывает строки и убирает повторы:

```sql run=empty
SELECT 'яблоко' AS fruit
UNION
SELECT 'груша'
UNION
SELECT 'яблоко'
ORDER BY fruit;
```

Повторяющейся считается вся строка целиком, а не отдельный столбец. Два значения NULL при этом считаются одинаковыми, хотя в обычном сравнении `NULL = NULL` не истинно. Для этого база сортирует или хеширует результат, и на больших таблицах такой запрос заметно медленнее UNION ALL. Поэтому правило простое: нужны уникальные строки - пишите UNION, повторы не страшны или невозможны - пишите UNION ALL.

Различие видно на реальных данных. Выведем сотрудников, которые получают от 200000, а потом тех, кто принят до 2019 года:

```sql run=company
SELECT full_name, 'высокая зарплата' AS reason
FROM employees
WHERE salary >= 200000
UNION ALL
SELECT full_name, 'ветеран'
FROM employees
WHERE hire_date < DATE '2019-01-01'
ORDER BY full_name, reason;
```

Ольга Смирнова подходит под оба условия и встречается в результате дважды, по разу на каждую причину. Теперь оставим только имена и склеим через UNION:

```sql run=company
SELECT full_name FROM employees WHERE salary >= 200000
UNION
SELECT full_name FROM employees WHERE hire_date < DATE '2019-01-01'
ORDER BY full_name;
```

Ольга теперь одна. Тот же результат даёт обычный WHERE с OR. Объединение запросов нужно, когда части берут данные из разных таблиц или когда у каждой части свой набор вычисляемых столбцов.

## Требования к частям

У всех частей должно быть одинаковое число столбцов. Если оно разное, PostgreSQL остановит запрос:

```sql run=company error
SELECT full_name, salary FROM employees
UNION ALL
SELECT name FROM departments;
```

Типы столбцов, стоящих на одинаковых позициях, должны быть совместимы. Число с числом, текст с текстом, дата с датой. Попытка объединить текст и число приведёт к ошибке:

```sql run=company error
SELECT full_name FROM employees
UNION ALL
SELECT budget FROM departments;
```

Если типы нужно согласовать, приведите один из них явно через `::` или CAST:

```sql run=company
SELECT full_name AS name FROM employees WHERE id <= 2
UNION ALL
SELECT budget::text FROM departments WHERE id <= 2
ORDER BY name;
```

Результат бессмысленный по содержанию, зато запрос выполнился. Столбцы частей соединяются по позиции, а не по названию. Если в частях поменять порядок столбцов, значения окажутся не в тех столбцах, и база этого не заметит, если типы совместимы.

Названия столбцов результата берутся из первой части. Названия во второй и следующих частях роли не играют.

## Объединение разных таблиц

Типичная задача - собрать список из разных таблиц в одном виде. Например, общий список названий для поиска по библиотеке: книги и авторы с пометкой, что это.

```sql run=library
SELECT title AS name, 'книга' AS kind FROM books
UNION ALL
SELECT full_name, 'автор' FROM authors
ORDER BY name, kind;
```

Пометка в виде константы - обычный приём: она показывает, из какой части пришла строка. Без неё строки из разных таблиц невозможно было бы различить.

## ORDER BY и LIMIT для всего результата

ORDER BY ставится один раз в самом конце и относится ко всему объединению, а не к последней части. В нём можно использовать названия столбцов результата или их номера, но не произвольные выражения:

```sql run=company error
SELECT full_name FROM employees
UNION ALL
SELECT name FROM departments
ORDER BY length(full_name);
```

Если нужен более сложный порядок, оберните объединение в подзапрос и сортируйте уже его. Частый случай - итоговая строка, которая должна оказаться последней:

```sql run=company
SELECT label, total
FROM (
  SELECT COALESCE(department_id::text, 'без отдела') AS label, SUM(salary) AS total, 0 AS grp
  FROM employees
  GROUP BY department_id
  UNION ALL
  SELECT 'Итого', SUM(salary), 1
  FROM employees
) AS t
ORDER BY grp, label;
```

Служебный столбец `grp` отделяет обычные строки от итоговой. Номер отдела пришлось привести к тексту, чтобы он стыковался со словом «Итого» в одном столбце.

## ORDER BY и LIMIT внутри части

Если сортировка или ограничение нужны в отдельной части, запишите часть в скобках:

```sql run=company
(SELECT full_name, hire_date FROM employees ORDER BY hire_date DESC, id LIMIT 3)
UNION ALL
(SELECT full_name, hire_date FROM employees ORDER BY hire_date, id LIMIT 3)
ORDER BY hire_date, full_name;
```

Без скобок ORDER BY относился бы ко всему объединению. Здесь три самых поздно принятых сотрудника и три самых давних собраны в один список. Внутри каждой скобки порядок задан до `id`, поэтому выбор при равных датах определён, а внешний ORDER BY упорядочивает уже общий список.

## Несколько частей и приоритет

Частей может быть больше двух, операторы выполняются слева направо. Если смешивать UNION и UNION ALL в одном запросе, порядок имеет значение, и лучше расставить скобки. Один и тот же запрос с разными скобками может вернуть разное число строк.

## В MySQL

UNION и UNION ALL в MySQL работают так же. Названия столбцов там тоже берутся из первой части, а вот приведение типов мягче: MySQL чаще молча сводит текст и число к общему типу, где PostgreSQL остановится с ошибкой. Это удобно, но скрывает ошибки, поэтому в PostgreSQL приходится явно писать приведение типов.
