По умолчанию дата выводится в формате ISO: `2026-04-15`. Для отчётов и писем часто нужен другой вид, например `15.04.2026`. Функция to_char превращает дату или время в текст по шаблону. В MySQL то же делают DATE_FORMAT и TIME_FORMAT.

```sql run=empty
SELECT
  to_char(TIMESTAMP '2026-04-05 18:07:09', 'DD.MM.YYYY') AS ru_date,
  to_char(TIMESTAMP '2026-04-05 18:07:09', 'HH24:MI:SS') AS clock,
  to_char(TIMESTAMP '2026-04-05 18:07:09', 'YYYY-MM-DD"T"HH24:MI') AS iso_short;
```

Шаблон состоит из специальных слов и обычных символов. Специальные слова заменяются частями даты, остальные символы переносятся как есть.

## Основные слова шаблона

YYYY - год из четырёх цифр, YY - из двух. MM - номер месяца с ведущим нулём, DD - день с ведущим нулём. HH24 - час от 00 до 23, HH или HH12 - час от 01 до 12, MI - минуты, SS - секунды. Q - номер квартала, WW - номер недели года, D - номер дня недели (воскресенье равно 1), ID - номер дня по ISO (понедельник равен 1). Day и Month дают названия дня недели и месяца, Dy и Mon - сокращённые.

```sql run=empty
SELECT
  to_char(DATE '2026-04-05', 'Day') AS day_name,
  to_char(DATE '2026-04-05', 'Month') AS month_name,
  to_char(DATE '2026-04-05', 'ID') AS iso_day,
  to_char(DATE '2026-04-05', 'Q') AS quarter;
```

Слова Day и Month всегда дают английские названия. Приставка TM (TMDay, TMMonth) берёт язык из настройки lc_time сервера, и результат зависит от того, как настроена база, поэтому на неё нельзя полагаться. В курсе русские названия берут из массива по номеру. Для дней недели номер даёт isodow:

```sql run=shop
SELECT
  id,
  ordered_at::date AS order_date,
  (ARRAY['понедельник', 'вторник', 'среда', 'четверг', 'пятница', 'суббота', 'воскресенье'])[EXTRACT(isodow FROM ordered_at)::int] AS weekday_name
FROM orders
WHERE id <= 4;
```

Индексы массива начинаются с единицы, и это совпадает с isodow. Так же делают названия месяцев: массив из двенадцати элементов и `EXTRACT(month FROM d)`. Те же названия можно получить через CASE, но для двенадцати значений массив короче. Функции DAYNAME и MONTHNAME из MySQL заменяются либо to_char, либо массивом.

## Пробелы и нули

Слова Day и Month дополняют название пробелами до одинаковой длины (до девяти символов). Чтобы пробелы убрать, поставьте перед словом приставку FM (fill mode). Она же убирает ведущие нули:

```sql run=empty
SELECT
  '[' || to_char(DATE '2026-04-05', 'Day') || ']' AS padded,
  '[' || to_char(DATE '2026-04-05', 'FMDay') || ']' AS trimmed,
  to_char(DATE '2026-04-05', 'FMDD.FMMM.YYYY') AS no_zeros;
```

## Буквальный текст

Если в шаблон нужно вставить слово, которое содержит буквы со специальным смыслом, заключите его в двойные кавычки. Буква Q в подписи квартала без кавычек была бы понята как номер квартала:

```sql run=shop
SELECT full_name, to_char(registered_on, 'YYYY-"Q"Q') AS quarter_label
FROM customers
WHERE id <= 3;
```

В тексте SQL одинарные кавычки строки и двойные кавычки внутри шаблона не мешают друг другу.

## Результат to_char - это текст

После форматирования значение перестаёт быть датой. Сортировка и сравнение пойдут по символам: строка `15.01.2019` окажется позже `01.02.2020`, потому что сравнение идёт слева направо и первая цифра 1 больше нуля. Поэтому сортируют и фильтруют по исходному значению, а форматируют только в итоговом SELECT. Формат `YYYY-MM` исключение: порядок символов там совпадает с хронологическим, и это удобный ключ для группировки по месяцам.

## Из строки в дату

Обратная задача возникает при загрузке данных: даты лежат в тексте, например `31.12.2025`. Функция to_date принимает строку и шаблон и возвращает date. В MySQL её роль выполняет STR_TO_DATE. Для даты со временем есть to_timestamp:

```sql run=empty
SELECT
  to_date('31.12.2025', 'DD.MM.YYYY') AS parsed_date,
  to_timestamp('31.12.2025 23:15', 'DD.MM.YYYY HH24:MI')::timestamp AS parsed_ts;
```

to_timestamp возвращает timestamptz, а приведение ::timestamp оставляет часы и минуты без пояса. Шаблоны разбора те же, что у to_char. Если строка не подходит под шаблон, PostgreSQL обычно вернёт ошибку:

```sql run=empty error
SELECT to_date('2025-12-31', 'DD.MM.YYYY');
```

Для строк в формате ISO шаблон не нужен: достаточно `'2025-12-31'::date`. Разобранную дату можно сравнивать, прибавлять к ней интервалы и вычитать одну из другой.

## Дни и секунды в другой форме

В MySQL есть TO_DAYS, FROM_DAYS, SEC_TO_TIME и TIME_TO_SEC. В PostgreSQL для них не нужны отдельные функции. Число дней между датами - это вычитание дат. Секунды в время переводит interval: `make_interval(secs => 3725)` вернёт `01:02:05`. Время в секунды переводит EXTRACT:

```sql run=empty
SELECT
  make_interval(secs => 3725) AS as_time,
  EXTRACT(epoch FROM TIME '01:02:05')::int AS as_seconds,
  DATE '2026-04-15' - DATE '2026-01-01' AS days_between;
```
