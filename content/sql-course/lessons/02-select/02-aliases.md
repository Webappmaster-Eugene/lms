Названия столбцов в таблице придумывали для хранения данных: `full_name`, `hire_date`. В отчёте нужны другие подписи, а иногда столбца в таблице нет вовсе, и его значение приходится вычислять. В обоих случаях помогает псевдоним: новое имя столбца результата, которое задаётся словом AS.

```sql run=company
SELECT full_name AS employee, position AS job
FROM employees;
```

Псевдоним меняет только заголовок в результате. Таблица остаётся прежней, а в других частях запроса исходное имя по-прежнему работает.

## Слово AS можно опустить

PostgreSQL принимает псевдоним и без AS, достаточно пробела:

```sql run=company
SELECT name dept_name, city FROM departments;
```

Здесь `name` получил псевдоним `dept_name`. Читать такой запрос трудно, и ошибиться легко: пропущенная запятая между столбцами превращает второй столбец в псевдоним первого. Поэтому AS лучше писать всегда.

```sql run=company
SELECT name city FROM departments;
```

Запрос выше выглядит как два столбца, но на деле это один столбец `name` с псевдонимом `city`, и города в результате нет. Именно эту ошибку защищает привычка писать AS.

## Псевдонимы со спецсимволами

Обычный псевдоним состоит из букв, цифр и подчёркиваний. Если нужен пробел или заглавные буквы, имя берут в двойные кавычки:

```sql run=company
SELECT
  full_name AS "Сотрудник",
  salary AS "Оклад в месяц"
FROM employees;
```

Двойные кавычки означают имя, одинарные - строку. Запись `AS 'Оклад'` в PostgreSQL даст ошибку. Без кавычек PostgreSQL приводит имя к нижнему регистру, поэтому `AS Employee` и `AS employee` одно и то же. Кавычки сохраняют регистр буквально.

## Вычисляемые столбцы

В списке SELECT можно писать выражения: арифметику над числами, постоянные значения, а позже - функции. Выражение вычисляется отдельно для каждой строки.

```sql run=company
SELECT full_name, salary, salary * 12 AS annual_salary
FROM employees;
```

Без псевдонима столбец получил бы служебное имя `?column?`, с которым неудобно работать. Для вычисляемых столбцов псевдоним нужен практически всегда.

Постоянное значение тоже можно сделать столбцом. Строка берётся в одинарные кавычки:

```sql run=shop
SELECT title, 'RUB' AS currency, price FROM products;
```

Если в вычислении участвует NULL, результат тоже NULL: любая операция с неизвестным значением даёт неизвестное значение. Книга без цены остаётся без цены и после умножения:

```sql run=library
SELECT title, price, price * 2 AS price_for_two FROM books;
```

Глубже арифметика, округление и условные выражения разобраны в разделе о выражениях.

## Псевдоним в ORDER BY

В порядке выполнения запроса сортировка идёт после формирования столбцов результата, поэтому в ORDER BY псевдоним доступен. Он работает только сам по себе: внутри выражения, например `ORDER BY stock_value + 1`, PostgreSQL его не найдёт.

```sql run=shop
SELECT title, price * stock AS stock_value
FROM products
ORDER BY stock_value DESC, id;
```

Есть и обратная сторона. Псевдоним нельзя использовать в WHERE: условие отбора проверяется раньше, чем появляются псевдонимы. Об этом подробнее в разделе об условиях. Попытка сделать это приводит к ошибке:

```sql run=company error
SELECT salary * 12 AS annual_salary
FROM employees
WHERE annual_salary > 1000000;
```

## Псевдонимы таблиц

Псевдоним можно дать и таблице, записав его после имени в FROM. Для одной таблицы это не нужно, но при соединениях без коротких имён запросы становятся громоздкими:

```sql run=company
SELECT e.full_name, e.salary
FROM employees AS e;
```

Через `e.` столбец указывают вместе с таблицей. Пока таблица одна, это только удобная запись, а позже, когда таблиц станет две и больше, она станет необходимой.

## Что запомнить

AS даёт столбцу результата новое имя. Пробелы и заглавные буквы требуют двойных кавычек. Вычисляемый столбец без псевдонима получает неудобное имя. Псевдоним виден в ORDER BY, но не виден в WHERE. В MySQL допустимы одинарные кавычки вокруг псевдонима, в PostgreSQL только двойные.
