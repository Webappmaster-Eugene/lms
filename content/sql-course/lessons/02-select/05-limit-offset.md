Таблица может содержать миллионы строк, а на экране помещается двадцать. Чтобы не вытягивать из базы лишнее, число строк ограничивают словом LIMIT. Оно пишется в самом конце запроса:

```sql run=company
SELECT full_name, salary
FROM employees
ORDER BY salary DESC, id
LIMIT 3;
```

Это три самых высокооплачиваемых сотрудника. LIMIT всегда идёт вместе с ORDER BY. Без сортировки «первые три строки» ничего не означают: база вернёт любые три, и при следующем запросе они могут оказаться другими. Если строк в таблице меньше, чем указано в LIMIT, вернутся все, ошибки не будет. `LIMIT 0` вернёт пустой результат с заголовками столбцов.

## Строка с крайним значением

Самый дешёвый товар, самая ранняя запись, последний заказ - все эти задачи решаются сортировкой и `LIMIT 1`:

```sql run=shop
SELECT title, price
FROM products
ORDER BY price, id
LIMIT 1;
```

Если у нескольких товаров цена совпадает с минимальной, запрос всё равно вернёт одну строку, и вторым ключом вы выбираете, какую именно. Если нужны все товары с минимальной ценой, LIMIT не годится: придётся сравнивать цену с минимумом в подзапросе, об этом в разделе о подзапросах.

Для поиска наибольшего значения среди столбцов с пустыми значениями вспомните порядок NULL: при DESC они идут первыми.

```sql run=library
SELECT title, price
FROM books
ORDER BY price DESC NULLS LAST, id
LIMIT 1;
```

Без `NULLS LAST` результатом была бы книга без цены.

## OFFSET: пропустить строки

OFFSET отбрасывает указанное число строк с начала результата. Пара LIMIT и OFFSET берёт «окно» из отсортированного списка:

```sql run=shop
SELECT title, price
FROM products
ORDER BY title, id
LIMIT 3 OFFSET 3;
```

Первые три товара пропущены, показаны следующие три. Порядок слов в PostgreSQL свободный: `OFFSET 3 LIMIT 3` тоже работает. Вторая строка списка по зарплате получается так:

```sql run=company
SELECT full_name, salary
FROM employees
ORDER BY salary DESC, id
LIMIT 1 OFFSET 1;
```

Это именно вторая позиция в списке, а не вторая по величине зарплата. Если у двух сотрудников равные максимальные зарплаты, вторая строка покажет зарплату, такую же, как первая.

OFFSET можно писать и без LIMIT, тогда вернутся все строки, кроме пропущенных:

```sql run=library
SELECT title, pages FROM books ORDER BY pages DESC, id OFFSET 7;
```

## Постраничный вывод

Страницы нумеруются с единицы, размер страницы постоянный. Для страницы с номером N и размером S применяют формулу:

```text
LIMIT S OFFSET (N - 1) * S
```

Третья страница по четыре строки - это `LIMIT 4 OFFSET 8`:

```sql run=library
SELECT id, title, pages
FROM books
ORDER BY pages DESC, id
LIMIT 4 OFFSET 8;
```

В таблице десять книг, поэтому на третьей странице две строки. Страница за пределами таблицы будет пустой, и это нормально, приложению нужно уметь показывать «страница не найдена».

Здесь снова нужен уникальный последний ключ. Если сортировка неоднозначна, между запросами за первую и вторую страницу порядок равных строк может измениться, и одна запись окажется на обеих страницах, а другая не появится нигде.

## Другие диалекты

В MySQL смещение и число строк пишут через запятую: `LIMIT 3, 3` означает «пропустить три, взять три». В этой записи смещение стоит первым. PostgreSQL такую форму не принимает, там пишут `LIMIT 3 OFFSET 3`.

```sql run=company error
SELECT full_name FROM employees ORDER BY id LIMIT 3, 3;
```

Стандартный SQL предлагает ещё одну запись: `OFFSET 3 ROWS FETCH FIRST 3 ROWS ONLY`. PostgreSQL её понимает и ведёт себя так же, как с LIMIT. В SQL Server для этого есть TOP, а в Oracle до версии 12 использовали ROWNUM. Здесь и дальше мы пользуемся LIMIT как самой короткой записью.

## Цена больших смещений

У OFFSET есть недостаток. Чтобы пропустить миллион строк, база всё равно читает и отбрасывает их, поэтому глубокие страницы работают медленно. В больших каталогах применяют другой подход: помнят значение ключа сортировки последней показанной строки и запрашивают следующие строки с условием «больше этого значения». Для учебных объёмов LIMIT и OFFSET подходят, но об этом ограничении полезно знать заранее.

## Что запомнить

LIMIT ограничивает число строк, OFFSET пропускает строки с начала. Оба работают осмысленно только после ORDER BY с однозначной сортировкой. Страница N размера S это `LIMIT S OFFSET (N - 1) * S`. Строку с крайним значением даёт ORDER BY ... LIMIT 1, а для столбцов с NULL нужен NULLS LAST. Форма `LIMIT a, b` из MySQL в PostgreSQL не работает.
