Без указаний PostgreSQL возвращает строки в том порядке, в каком ему удобно. Сегодня это может совпадать с порядком вставки, а после обновлений таблицы поменяться. Если порядок важен для читателя или программы, его нужно задавать явно. Для этого в конце запроса пишут ORDER BY и столбец, по которому сортировать.

```sql run=company
SELECT full_name, salary
FROM employees
ORDER BY salary;
```

Числа идут от меньшего к большему: это порядок по возрастанию, он действует по умолчанию. Слово ASC можно дописать, но оно ничего не меняет. Чтобы перевернуть порядок, пишут DESC:

```sql run=company
SELECT full_name, salary
FROM employees
ORDER BY salary DESC;
```

Текст сортируется по алфавиту, даты - от ранних к поздним:

```sql run=library
SELECT title, published_year FROM books ORDER BY title;
```

```sql run=company
SELECT full_name, hire_date FROM employees ORDER BY hire_date DESC;
```

ORDER BY всегда пишется после FROM и других условий. Он выполняется последним из основных частей запроса, не считая LIMIT, поэтому ему доступны псевдонимы столбцов из SELECT.

## Несколько ключей

Если по первому столбцу значения совпали, строки можно упорядочить по второму, потом по третьему. Ключи перечисляют через запятую:

```sql run=company
SELECT department_id, full_name, salary
FROM employees
ORDER BY department_id, salary DESC;
```

Сначала строки собираются по отделам, внутри отдела идут по убыванию зарплаты. Направление задаётся для каждого ключа отдельно: DESC здесь относится только к `salary`. Чтобы отделы тоже шли по убыванию, DESC нужен и после `department_id`.

## Зачем нужен последний ключ

Когда ключи не различают строки, их порядок между собой не определён. Если у двух сотрудников одинаковая зарплата, два запроса подряд могут расположить их по-разному. Для отчёта это раздражает, а для постраничного вывода это ошибка: строка может появиться на двух страницах или не появиться ни на одной.

Привычка, которая это исключает: заканчивать список ключей уникальным столбцом, обычно `id`.

```sql run=shop
SELECT title, price
FROM products
ORDER BY price DESC, id;
```

В задачах курса, где важен порядок, второй ключ назван в условии именно поэтому.

## Сортировка по выражению

Ключом может быть не только столбец, но и любое выражение:

```sql run=shop
SELECT order_id, product_id, quantity * price AS line_total
FROM order_items
ORDER BY quantity * price DESC, order_id, product_id;
```

Вместо повторения выражения можно написать псевдоним `line_total`, результат будет тем же. Есть и третий вариант: номер столбца в списке SELECT, например `ORDER BY 3 DESC`. Он работает, но при изменении списка столбцов тихо начинает сортировать по другому, поэтому в рабочем коде номера не используют.

## NULL при сортировке

NULL означает отсутствие значения, а сортировке нужно куда-то его поставить. PostgreSQL считает NULL большим любого значения: при сортировке по возрастанию такие строки идут в конце, при убывании - в начале.

```sql run=library
SELECT title, price FROM books ORDER BY price DESC;
```

Книга без цены оказалась первой, хотя для читателя это самая неинтересная строка. Положение NULL задают явно, добавив NULLS FIRST или NULLS LAST после направления:

```sql run=library
SELECT title, price FROM books ORDER BY price DESC NULLS LAST;
```

```sql run=company
SELECT name, city FROM departments ORDER BY city NULLS FIRST, id;
```

Эта особенность отличает PostgreSQL от MySQL, где NULL считается меньшим любого значения и конструкции NULLS FIRST и NULLS LAST нет. Перенося запросы из MySQL, проверьте порядок строк с пустыми значениями.

## Регистр и язык

Порядок текстовых строк зависит от правил сравнения (collation), заданных в базе. В одних базах буквы упорядочиваются по кодам символов, и тогда все заглавные идут раньше строчных, а в других по правилам языка, и порядок привычный. Проверьте результат на своих данных. Если нужна сортировка без учёта регистра, ключом делают `lower(title)`, функции строк мы разберём позже.

## Крайнее значение

Сортировка с ограничением числа строк отвечает на вопрос «кто самый...». Например, самый молодой сотрудник - тот, у кого самая поздняя дата рождения:

```sql run=company
SELECT full_name, birth_date
FROM employees
ORDER BY birth_date DESC, id
LIMIT 1;
```

Оператор LIMIT разбирается в следующем уроке. Второй ключ `id` важен и здесь: если у двух людей одна дата рождения, запрос всё равно вернёт ровно одного и одного и того же.

## Что запомнить

ORDER BY по умолчанию сортирует по возрастанию, DESC переворачивает порядок отдельного ключа. Ключей может быть несколько, и каждый имеет своё направление. Без ORDER BY порядок строк не гарантирован. Список ключей лучше закончить уникальным столбцом. NULL по умолчанию считается большим любого значения, а NULLS FIRST и NULLS LAST ставят его в нужное место.
