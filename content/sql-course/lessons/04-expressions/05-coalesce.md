NULL означает, что значение неизвестно или не задано. С ним нельзя считать, его не получится склеить с текстом, и в готовом отчёте он выглядит как пустая клетка. Функция `COALESCE` подставляет вместо NULL нужное значение. Она принимает любое число аргументов и возвращает первый из них, который не NULL.

```sql run=shop
SELECT full_name, city, COALESCE(city, 'не указан') AS city_shown
FROM customers
ORDER BY id;
```

У Льва Комарова город не указан, и в последнем столбце появляется заглушка. Исходные данные при этом не меняются: подмена происходит только в результате запроса.

В MySQL для двух аргументов есть `IFNULL(a, b)`, в Oracle - `NVL`, в SQL Server - `ISNULL`. В PostgreSQL ничего из этого нет, а `COALESCE` входит в стандарт SQL и работает везде, поэтому его удобно выучить один раз.

## Несколько аргументов

Аргументов может быть сколько угодно: функция проверяет их по порядку и останавливается на первом непустом. Так выбирают контакт по приоритету:

```sql run=shop
SELECT
  full_name,
  email,
  city,
  COALESCE(email, city, 'нет данных') AS contact
FROM customers
ORDER BY id;
```

Последним аргументом принято ставить значение, которое точно не NULL: тогда и результат гарантированно не будет NULL. Остальные аргументы после первого непустого не вычисляются, это можно использовать для защиты от ошибок.

Типы аргументов должны быть совместимы: в одном COALESCE нельзя смешивать текст и число.

```sql run=empty error
SELECT COALESCE(NULL, 'нет', 0);
```

## Арифметика и NULL

Результат арифметики с NULL тоже NULL. Если пропуск нужно считать нулём, его заменяют до вычисления, а не после:

```sql run=library
SELECT
  title,
  price,
  price + 100 AS wrong,
  COALESCE(price, 0) + 100 AS right_sum
FROM books
ORDER BY id;
```

У книги «Хроники заводной птицы» цена пуста. В столбце `wrong` получился NULL, а в `right_sum` честные 100. Заменять на ноль нужно осознанно: в одних расчётах пропуск действительно означает ноль, в других - что данных нет, и ноль исказит итог.

Чаще всего COALESCE оборачивают столбец, но он принимает и целое выражение. Это защита от пропусков в сумме нескольких столбцов:

```sql run=empty
SELECT
  id,
  COALESCE(base, 0) + COALESCE(bonus, 0) AS total
FROM (VALUES (1, 100, 20), (2, 80, NULL), (3, NULL, 15)) AS t(id, base, bonus)
ORDER BY id;
```

## COALESCE в сортировке

NULL сортируется как самое большое значение: при `ORDER BY price DESC` пустые цены окажутся вверху, при `ASC` - внизу. Когда нужен другой порядок, можно подменить NULL прямо в ключе сортировки:

```sql run=library
SELECT id, title, price
FROM books
ORDER BY COALESCE(price, 0) DESC, id;
```

Выводимое значение остаётся прежним, меняется только то, как строка сравнивается с остальными. Для цен подойдёт ноль, для других данных нужно выбирать подмену, которая не пересекается с настоящими значениями. Самому решать, куда поставить пустые значения, можно ещё и фразой `NULLS FIRST` или `NULLS LAST` в ORDER BY, она короче и есть в PostgreSQL:

```sql run=library
SELECT id, title, price
FROM books
ORDER BY price DESC NULLS LAST, id;
```

## NULLIF

`NULLIF(a, b)` делает обратное: возвращает NULL, если `a` равно `b`, и `a` в остальных случаях. Это способ превратить «заглушку» в настоящий пропуск. Главное применение уже встречалось в арифметике: нулевой делитель превращают в NULL, и деление не падает.

```sql run=empty
SELECT
  planned,
  actual,
  actual * 100 / NULLIF(planned, 0) AS percent,
  COALESCE(actual * 100 / NULLIF(planned, 0), 0) AS percent_or_zero
FROM (VALUES (200, 50), (0, 30), (40, 40)) AS t(planned, actual);
```

Вторая строка показывает связку двух функций: `NULLIF` защищает от деления на ноль, а `COALESCE` заменяет получившийся NULL нулём. Если процент при нулевом плане нужно скрыть, второй функции не будет, и клетка останется пустой.

Вторая типичная работа NULLIF - убрать пустые строки, которые пришли из внешних систем. Пустая строка в PostgreSQL не равна NULL, поэтому `COALESCE(note, 'нет')` её не заменит. Сначала пустую строку превращают в NULL:

```sql run=empty
SELECT
  note,
  COALESCE(note, 'нет') AS plain,
  COALESCE(NULLIF(note, ''), 'нет') AS cleaned
FROM (VALUES ('срочно'), (''), (NULL)) AS t(note);
```

Во второй строке `plain` остаётся пустым, а `cleaned` содержит «нет». Эта разница объясняет, почему данные из файлов и форм стоит проверять на оба вида пустоты.

## Не путайте с проверкой NULL

COALESCE подменяет значение в результате, но не отбирает строки. Чтобы найти строки с пропуском, нужен `WHERE столбец IS NULL`. Сравнение `столбец = NULL` не работает: оно всегда неизвестно. Подмена в WHERE тоже возможна: `WHERE COALESCE(city, '') = ''` найдёт и NULL, и пустые строки, но такая запись не использует индекс по столбцу, поэтому на больших таблицах лучше написать два условия: `city IS NULL OR city = ''`.
