Список столбцов после SELECT может содержать не только имена столбцов, но и выражения: значения, которые база вычисляет для каждой строки. Самые простые из них - арифметические. В PostgreSQL работают привычные операторы: `+`, `-`, `*`, `/`, а также `%` для остатка от деления. Скобки меняют порядок действий так же, как в школьной математике.

```sql run=shop
SELECT title, price, stock, price * stock AS stock_value
FROM products
ORDER BY id
LIMIT 5;
```

Столбец `stock_value` в таблице не существует, он вычисляется на лету, а псевдоним даёт ему имя. Сами данные при этом не меняются. Без псевдонима столбец получил бы служебное имя `?column?`, и обращаться к нему было бы неудобно.

Выражение можно писать и без таблицы, достаточно одного SELECT. Это удобный способ проверить, как работает оператор:

```sql run=empty
SELECT 2 + 3 * 4 AS no_parens, (2 + 3) * 4 AS with_parens;
```

Умножение выполняется раньше сложения, скобки это порядок меняют. Если сомневаетесь в приоритете, ставьте скобки: они ничего не стоят и делают запрос понятнее.

## Выражения в WHERE и ORDER BY

Выражение можно написать везде, где ожидается значение: в условии отбора и в сортировке. Здесь мы отбираем товары, у которых запас на складе стоит больше 100 тысяч, и сортируем по этой стоимости.

```sql run=shop
SELECT title, price * stock AS stock_value
FROM products
WHERE price * stock > 100000
ORDER BY price * stock DESC, id;
```

Псевдоним из SELECT в WHERE использовать нельзя: условие проверяется раньше, чем вычисляется список столбцов. Поэтому выражение приходится повторять. В ORDER BY псевдоним допустим, но только сам по себе, а не внутри выражения.

## Целочисленное деление

В PostgreSQL деление двух целых чисел даёт целое число, дробная часть отбрасывается. Это неожиданно для тех, кто привык к калькулятору или к JavaScript:

```sql run=empty
SELECT 7 / 2 AS integer_division, 7 % 2 AS remainder, -7 / 2 AS negative;
```

Результат 3 получается не округлением, а отбрасыванием дроби к нулю: -7 / 2 даёт -3, а не -4. Остаток хранится отдельно: 7 = 3 * 2 + 1. Пара «частное и остаток» удобна для таких задач, как разбиение секунд на минуты или товаров на коробки.

Чтобы получить дробный результат, хотя бы один из операндов должен иметь дробный тип. Самый простой способ - записать число с десятичной точкой:

```sql run=empty
SELECT 7 / 2.0 AS exact, 7.0 / 2 AS also_exact, 7::numeric / 2 AS cast_first;
```

Литерал `2.0` имеет тип numeric, поэтому деление становится точным десятичным. Про приведение через `::` подробнее в последнем уроке раздела. Если же делить два столбца типа integer, написать `.0` негде, и приведение придётся делать явно: `pages::numeric / 100`.

## Какой тип у результата

Тип результата зависит от типов операндов. Целое с целым даёт целое, целое с numeric даёт numeric, а если в выражении есть double precision, результат тоже становится double precision. Тип numeric хранит десятичные дроби точно и подходит для денег. Тип double precision - двоичная дробь, быстрая, но неточная в последних знаках. Например, сумма `0.1 + 0.2` для numeric ровно равна `0.3`, а для double precision не равна: в двоичной записи у обоих слагаемых бесконечная дробь.

```sql run=empty
SELECT
  0.1 + 0.2 = 0.3 AS numeric_equal,
  0.1::double precision + 0.2::double precision = 0.3::double precision AS double_equal;
```

Поэтому суммы, цены и проценты в учебных базах курса хранятся как numeric. Подробнее про типы ниже, в уроке о приведении.

## Остаток от деления

Остаток вычисляется оператором `%` или функцией `MOD(a, b)`, это одно и то же. Он часто нужен для проверки кратности: чётные номера, каждая третья строка, нерабочие дни.

```sql run=company
SELECT id, full_name
FROM employees
WHERE id % 2 = 0
ORDER BY id;
```

Знак остатка повторяет знак делимого: -7 % 3 равно -1. Для положительных чисел это не мешает.

## Деление на ноль и NULLIF

Деление на ноль в PostgreSQL - ошибка, запрос не возвращает ни одной строки:

```sql run=empty error
SELECT 10 / 0;
```

В MySQL деление на ноль даёт NULL, и тот, кто переходит оттуда, ждёт того же. В PostgreSQL защищаться нужно самому. Функция `NULLIF(a, b)` возвращает NULL, если `a` равно `b`, иначе возвращает `a`. Если поставить её в знаменатель, нулевой делитель превратится в NULL, а любая арифметика с NULL даёт NULL.

```sql run=empty
SELECT
  value,
  total,
  value * 100 / NULLIF(total, 0) AS percent
FROM (VALUES (30, 200), (50, 0), (10, 40)) AS t(value, total);
```

В строке, где итог равен нулю, процент не определён, и запрос честно возвращает NULL, а не падает. Если нужен ноль вместо NULL, оберните выражение в `COALESCE`: эта функция разобрана в уроке о пустых значениях.

Умножение на 100 здесь стоит до деления, и это не случайно. Для целых чисел выражение `value / total * 100` дало бы 0 в строках, где `value` меньше `total`, потому что дробь отбросилась бы раньше умножения.

## Арифметика и NULL

Любое действие с NULL даёт NULL: `price * NULL` и `NULL + 1` тоже NULL. Это логично, ведь неизвестное число, умноженное на два, остаётся неизвестным. Если пропуск нужно трактовать как ноль, его заменяют явно, и этому будет посвящён урок о COALESCE.

```sql run=library
SELECT title, price, price * 2 AS doubled
FROM books
ORDER BY id;
```

У книги «Хроники заводной птицы» цена не указана, и в `doubled` стоит NULL.
