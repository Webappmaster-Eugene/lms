Регулярное выражение - это шаблон, который описывает множество строк: «три цифры», «буквы до собаки», «один или несколько пробелов». Когда фиксированных функций не хватает, шаблон справляется с нерегулярными данными. В PostgreSQL используется диалект POSIX, он близок к тому, что знают из других языков. Для запросов достаточно небольшого набора конструкций.

## Основы шаблона

Подробно конструкции разобраны в уроке про регулярные выражения в WHERE. Здесь краткое напоминание:

```text
.        любой символ
\d       цифра              \D  не цифра
\s       пробельный символ  \S  не пробельный
\w       буква, цифра или _
[abc]    один из символов a, b, c
[^abc]   любой символ, кроме a, b, c
a|b      a или b
*  +  ?  ноль и больше, один и больше, ноль или один повторов
{3}      ровно три повтора
^   $    начало и конец строки
( )      группа
```

В обычной строке SQL обратный слеш не требует удвоения: '\d+' работает как есть при настройках по умолчанию. Спецсимволы (точка, скобки, плюс), которые нужно искать как обычные знаки, экранируются слешем: \. и \( .

## Операторы ~, ~* и !~

Операторы ~, ~*, !~ и !~* проверяют строку по шаблону, как в WHERE. В MySQL их роль играет REGEXP. Результат удобно выводить прямо в списке столбцов:

```sql run=empty
SELECT phone,
       phone ~ '^\+7 \(\d{3}\) \d{3}-\d{2}-\d{2}$' AS strict_format,
       phone ~ '^\+?\d' AS starts_ok
FROM (VALUES ('+7 (916) 123-45-67'), ('8-903-555-01-02'), ('+7(905)444-55-66')) AS t(phone);
```

Без якорей ^ и $ шаблон может совпасть с любой частью строки. Для проверки формата ставят оба якоря: тогда совпадать должна вся строка.

## regexp_replace

regexp_replace(строка, шаблон, замена, флаги) заменяет совпадения. Без флагов заменяется только первое. Флаг g заменяет все, флаг i отключает учёт регистра:

```sql run=empty
SELECT regexp_replace('+7 (916) 123-45-67', '\D', '', 'g') AS digits,
       regexp_replace('2026-04-15', '\d', '#') AS first_only,
       regexp_replace('Привет ПРИВЕТ', 'привет', 'Пока', 'gi') AS ignore_case;
```

В замене можно ссылаться на группы шаблона через \1, \2:

```sql run=empty
SELECT regexp_replace('Иванов Иван', '(\S+) (\S+)', '\2 \1') AS swapped;
```

Распространённая очистка имён: убрать пробелы по краям и сжать серии пробелов внутри.

```sql run=empty
SELECT regexp_replace(trim('  Борис   Громов '), '\s+', ' ', 'g') AS name_clean;
```

## Извлечение: substring и regexp_match

Если передать substring шаблон, она вернёт совпавший фрагмент. Когда в шаблоне есть скобки, возвращается только содержимое первой группы:

```sql run=empty
SELECT substring('Скидка 15% на ноутбуки' FROM '\d+') AS number,
       substring('Скидка 15% на ноутбуки' FROM '(\d+)%') AS percent;
```

Для нескольких групп сразу подходит regexp_match. Она возвращает массив групп первого совпадения или NULL, если совпадения нет. Элемент берут в квадратных скобках, нумерация с единицы:

```sql run=empty
SELECT m[1] AS category, m[2]::integer AS number, m[3] AS country
FROM (SELECT regexp_match('LT-0042-RU', '^([A-Z]+)-(\d+)-([A-Z]+)$') AS m) AS t;
```

Функция regexp_matches похожа, но с флагом g возвращает все совпадения, по одному массиву на строку результата. Все числа из текста можно получить так:

```sql run=empty
SELECT m[1]::integer AS number
FROM regexp_matches('На 3 полки, 12 коробок и 7 ящиков', '(\d+)', 'g') AS m;
```

## regexp_count

regexp_count(строка, шаблон) возвращает число непересекающихся совпадений (функция появилась в PostgreSQL 15). С её помощью считают слова, не заботясь о двойных пробелах:

```sql run=empty
SELECT regexp_count('Пять  новых моделей   в продаже', '\S+') AS words,
       regexp_count('2026-04-15', '\d') AS digits;
```

## Разбиение на строки

regexp_split_to_table разрезает строку по шаблону и возвращает каждую часть отдельной строкой. Её используют, чтобы разбить текст на слова или развернуть список в строки:

```sql run=empty
SELECT regexp_split_to_table('сравниваем камеры, батарею и цену', '[ ,]+') AS word;
```

Версия regexp_split_to_array возвращает те же части одним массивом. Для простого разделителя без шаблона есть string_to_array и string_to_table (последняя с PostgreSQL 14):

```sql run=empty
SELECT string_to_array('обзор,ноутбуки,советы', ',') AS tags;
```

### Списки через запятую

В таблицах иногда лежат списки значений в одной ячейке: теги через запятую. Правильнее хранить такие данные отдельными строками, но с готовыми приходится работать. Развернуть список в строки можно так:

```sql run=empty
SELECT p.id, tag
FROM (VALUES (1, 'обзор,ноутбуки,советы'), (2, 'новинки'), (3, NULL)) AS p(id, tags)
CROSS JOIN LATERAL regexp_split_to_table(p.tags, ',') AS tag;
```

Запись CROSS JOIN LATERAL нужна, когда функция вызывается для каждой строки таблицы. Подробно соединения разобраны в отдельном разделе, пока достаточно скопировать форму. Если функцию поставить прямо в список столбцов, как в задаче ниже, получится тот же результат короче. Строка с NULL даст ноль строк результата, а пустая строка '' даст одну пустую.

Чтобы проверить, есть ли в списке нужное значение, превращают список в массив и ищут через ANY. В MySQL для этого служит FIND_IN_SET:

```sql run=empty
SELECT id, tags
FROM (VALUES (1, 'обзор,ноутбуки,советы'), (2, 'советы дня'), (3, 'акции')) AS p(id, tags)
WHERE 'советы' = ANY(string_to_array(tags, ','));
```

Запись tags LIKE '%советы%' нашла бы и «советы дня». Сравнение с элементом массива ищет только точное совпадение. Номер элемента в списке (то, что в MySQL возвращает FIND_IN_SET) даёт array_position:

```sql run=empty
SELECT array_position(string_to_array('обзор,ноутбуки,советы', ','), 'советы') AS pos;
```

Функция ELT из MySQL, которая выбирает элемент списка по номеру, в PostgreSQL заменяется индексом массива: (ARRAY['a', 'b', 'c'])[2] вернёт 'b'. Для выбора по условию чаще подходит CASE.

## Когда нужны регулярные выражения

Они мощнее обычных функций и медленнее, а читать их сложнее. Если задачу решает split_part, left или replace, пользуйтесь ими. К регулярным выражениям переходят, когда нужно описать форму значения: формат телефона, число перед знаком процента, любую серию пробелов. Всегда проверяйте шаблон на пограничных значениях: пустой строке, NULL, строке без совпадений.
