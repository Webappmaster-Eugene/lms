# Курс «SQL и PostgreSQL с нуля»

Текстовый курс LMS и SQL-задачи тренажёра живут в этом репозитории вместе: у них общие
наборы данных, а проверки курса знают все слаги задач. Курс закрыт по назначению, SQL-темы
тренажёра тоже (`assignedOnly`), поэтому ученику нужно выдать оба назначения.

Охват тем повторяет справочник и задачник SQL на code.mu, но текст, примеры, данные и
формулировки задач свои. Диалект PostgreSQL: функции, которых нет в PostgreSQL (DATE_FORMAT,
IFNULL, GROUP_CONCAT, LIMIT a, b), заменены аналогами (to_char, COALESCE, string_agg, LIMIT
и OFFSET).

## Урок

Шапка строгая, ключи только эти, задачи через запятую:

```text
---
title: Сортировка: ORDER BY
slug: sql-select-order-by
minutes: 15
description: Как упорядочить строки по одному и нескольким столбцам, по возрастанию и убыванию.
tasks: sql-select-order-by-salary, sql-select-order-by-two-keys
---
```

Текст начинается сразу с абзаца: заголовок урока показывает LMS. Внутри урока заголовки
`##` и `###`. В конце сборка сама добавляет раздел «Практика» со ссылками на задачи из `tasks`.

Пример, который нужно выполнить, пишется блоком `sql run=<набор>`: `company`, `shop`,
`library` или `empty` (пустая база). Под блоком появится настоящий результат. Пример,
который должен упасть с ошибкой, помечается `sql run=<набор> error`, и под ним появится
текст ошибки PostgreSQL. Каждый блок выполняется на свежих данных набора, поэтому изменение
данных и проверочный SELECT пишутся в одном блоке. Блок без `run` просто показывается.

Таблицы набора вставляются блоком `tables <набор> [таблица ...]`.

## Задача

Задача объявляется через `sqlTask()` в файле своей темы. Условие пишется без таблиц: таблицы
добавляются из набора. Кроме открытых данных, решение проверяется на скрытом варианте набора,
поэтому в эталоне нельзя подставлять значения из таблицы.

Что проверяет тест каталога и что нужно учитывать в условии:

- результат сравнивается вместе с названиями столбцов, поэтому для вычисляемых столбцов
  условие называет псевдоним;
- порядок строк проверяется, только если `ordered: true`, и тогда сортировка должна быть
  однозначной: при равных значениях условие называет второй ключ;
- LIMIT среди равных значений тоже даёт неоднозначный ответ, тест это ловит;
- ответ на скрытом наборе должен отличаться от открытого;
- `now()`, `current_date`, `random()` в эталоне запрещены: «сегодня» задаётся в условии датой;
- задачи на изменение данных и структуры задают `check`: запрос после решения, его результат
  и сравнивается. Перед ним выполняется ROLLBACK, поэтому решение с BEGIN без COMMIT не
  засчитывается, а эталон транзакции обязан закончиться COMMIT или ROLLBACK;
- код ученика уходит одним запросом: без BEGIN он выполняется одной неявной транзакцией, а
  BEGIN втягивает в транзакцию и команды перед ним (урок о транзакциях объясняет это ученику).

## Правила текста

Только короткий дефис, никаких длинных тире, эмодзи и бейджей. Без жирного и списков ради
вида: обычные предложения, список только там, где действительно перечисление. Простой русский
без калек и канцелярита, без штампов вроде «стоит отметить» и «важно понимать». Тон деловой и
уважительный. Термин объясняется при первом появлении.

## Проверки

```sh
pnpm sql:check --topic sql-where --section sql-where --out /tmp/sql-preview
pnpm trainer:sql-expected
pnpm exec vitest run tests/unit/trainer/sqlCatalog.test.ts tests/unit/trainer/sqlEngine.test.ts tests/unit/content/sqlCourse.test.ts
```

`sql:check` проверяет выбранные темы и разделы (флаги повторяются) и ничего не записывает. `--out` сохраняет
собранные уроки для вычитки. После изменения задач нужен `pnpm trainer:sql-expected`, иначе
тест каталога упадёт на устаревших ожиданиях.

## Публикация

Задачи и курс уходят в LMS скриптами под админом, по slug, сначала черновиком:

```sh
LMS_URL=… LMS_ADMIN_EMAIL=… LMS_ADMIN_PASSWORD=… pnpm sql:publish-trainer --dry-run
LMS_URL=… LMS_ADMIN_EMAIL=… LMS_ADMIN_PASSWORD=… pnpm sql:publish-course --dry-run
```

`pnpm seed:trainer` для прода не годится: он перезаписывает весь каталог и снова публикует
все темы.
