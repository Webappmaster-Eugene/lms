# Записи собеседований

`/interviews`: направления редактируются в CMS (включая новые языки), внутри каждого
«Собесы ментора», «Чужие собесы», «Мои собесы». Начальные React/Node.js создаются
идемпотентно без сетевых запросов на старте. Общие записи доступны вошедшим ученикам,
личные — только владельцу, в том числе через стандартный Payload API. Администратор
управляет общими записями; прямые CRUD личных записей закрыты и для администратора.

Кнопка «Обновить библиотеку» доступна администратору и импортирует две указанные
владельцем папки Яндекс Диска. Синхронизация идемпотентна по hash(publicKey,path),
не удаляет вручную добавленный контент. При изменении направления достаточно создать
его в CMS; общие записи можно добавлять через CMS с publicKey/publicPath.

## Настройка

Источник настроек прода — Dokploy Environment приложения lms-mentor:

- YANDEX_DISK_TOKEN: OAuth владельца Диска с разрешением читать/записывать файлы.
- YANDEX_INTERVIEWS_ROOT: по умолчанию `disk:/LMS interviews`. Папка приватная.
- OPENROUTER_API_KEY: ключ аккаунта для распознавания и оценки (можно использовать
  тот же аккаунт, что у Советника). Платные запросы идут только после кнопки ученика.
- MEETING_STT_MODEL / INTERVIEW_EVAL_MODEL: модели как в Советнике, при необходимости
  переопределяются. FFmpeg/FFprobe установлены в production Dockerfile.

Без токена Диска загрузка отключена с понятным пояснением. Без OpenRouter отключён
анализ, просмотр общих записей продолжает работать. Секреты никогда не передаются
клиенту; signed download/upload ссылки не публикуются и не сохраняются в Redis.

## Личная загрузка и очередь

POST `/api/interviews/upload` резервирует запись и проверяет квоты/формат. PUT
`/api/interviews/:id/upload` потоково передаёт файл Диску с ограничением фактических
байт; POST `finish` независимо проверяет размер/тип через API Диска. Предел: 2 ГБ
на запись, 20 записей/10 ГБ на ученика. Плеер GET/HEAD `stream` поддерживает Range.
Прерванные резервирования старше суток очищает scheduler, только после успешного
удаления зарезервированного пути. DELETE сохраняет DB row, если Диск не подтвердил
удаление. Активные загрузки и анализы удалить нельзя.

POST `analyze` разрешён только владельцу готовой личной записи. Долговечная очередь
в PostgreSQL переживает рестарт; один анализ на приложение, heartbeat и claim
не допускают двух воркеров. При потере claim обработка отменяется. Прерванная задача
становится failed, повторного платного анализа автоматически не происходит.
Отдельный закрытый счётчик ограничивает три запуска на ученика в сутки (UTC),
удаление видео квоту не сбрасывает. Три попытки на запись; completed не повторяется.

Модуль анализа перенесён из проекта Советника: точный источник и SHA —
`src/lib/interviews/analysis/provenance.md`. Сохранены шкала, расчёт балла, проверка
цитат/спикеров, структура полного отчёта. Анализируется звук и расшифровка; код на
экране и изображение не анализируются. Неполные фрагменты не выдаются за полный
разбор. Максимум четыре часа, chunks около десяти минут, приватные временные файлы
обязательно удаляются. У модели нет инструментов, содержимое записи недоверенное.

## Проверки

Unit: streaming/SSRF/Range/expiredhref, parser/evidence/scoring/FFmpeg boundaries;
components: explicit consent/owner-onlyreport, polling cleanup, upload failures;
integration: actual PostgreSQL migration/access/CSRF/quota/concurrentclaims.
Реальная загрузка требует действующего OAuth, платный анализ — настроенного ключа.
Запрос модели с тестовой личной записью не запускается автоматически в тестах.

Первичные API: [Яндекс Диск](https://yandex.com/dev/disk/rest/),
[OpenRouter audio](https://openrouter.ai/blog/tutorials/transcription-on-openrouter/).
