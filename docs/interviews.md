# Записи собеседований

`/interviews`: расширяемые направления из CMS, категории «Собесы ментора», «Чужие
собесы», «Мои собесы». Личные записи, результаты и выдача отчёта доступны только
владельцу, включая стандартный Payload API. Общая библиотека доступна вошедшим
ученикам. Администратор редактирует общие записи; чужие личные записи закрыты.

## Настройка в Dokploy Environment приложения lms-mentor

- `YANDEX_DISK_TOKEN`: OAuth аккаунта Диска, права cloud_api:disk.read и cloud_api:disk.write.
- `YANDEX_INTERVIEWS_ROOT`: приватная папка, по умолчанию `disk:/LMS interviews`.
- `CHECKFROD_API_URL`: по умолчанию https://checkfrod.nadtocheev.ru.
- `CHECKFROD_API_KEY`: серверный ключ интеграции Checkfrod, как в Советнике.

OpenRouter, отдельные языковые модели и FFmpeg в LMS для анализа не нужны.
Всю обработку выполняет существующий Checkfrod. LMS принимает запрос владельца,
передаёт защищённый источник видео, получает прогресс и готовый отчёт.

OAuth: создайте [приложение для API](https://yandex.ru/dev/id/doc/ru/register-api),
выберите права чтения/записи Диска и получите [токен вручную](https://yandex.ru/dev/id/doc/ru/tokens/debug-token)
по адресу `https://oauth.yandex.ru/authorize?response_type=token&client_id=CLIENT_ID`.
Секрет добавляется только в Dokploy Environment, не в Git/чат/логи.

## Хранилище и приватность

POST upload резервирует личную запись, PUT потоково передаёт файл на Диск,
POST finish независимо проверяет фактический размер и MIME. Максимум 2 ГБ,
20 записей и 10 ГБ на ученика. GET/HEAD stream поддерживают Range/private no-store.
Прерванные резервирования старше суток чистит scheduler с проверкой текущего
владельца, статуса и lease. При отказе внешнего удаления DB row сохраняется.

## Checkfrod

Запуск только по явному согласию владельца личной готовой записи. Область кандидата
ROI: auto/none или x,y,w,h, минимум16px. Checkfrod проверяет видео и показывает
эпизоды/моменты/качество наблюдения; LMS не выдумывает оценки технических ответов.
Сводка берётся из report.json по тем же правилам, что в боте; полный оригинальный
отчёт открывается после owner-check по новой подписанной ссылке сервиса.
Подсказки и движения глаз не объявляются доказанным фактом списывания.

Checkfrod получает HTTPS capability URL LMS на одну запись/владельца/попытку
с HMAC и сроком24h. Endpoint заново разрешает временную ссылку Диска при скачивании,
поэтому ожидание во внешней очереди не зависит от срока жизни старой CDN-ссылки.
Источник отзывается при завершении/ошибке/удалении и не передаётся браузеру ученика.

Состояние хранится в PostgreSQL. Короткие шаги scheduler создают remotejob и далее
только опрашивают его; lease исключает одновременную обработку одной записи.
RemoteID сохраняется и повторно используется после рестарта. Если ответ POST потерян,
задача восстанавливается по уникальному имени источника через scoped GET/api/jobs;
POST автоматически не повторяется. Отдельная квота ограничивает3 запуска в сутки UTC,
удаление видео квоту не сбрасывает. Старые AI-поля сохранены только для совместимости
с прежней схемой; прежний AI pipeline удалён.

Сервис принимает числовой X-ICheck-User. Зарезервирован диапазон
9000000000000000 + SQL user ID LMS; он выше максимального52-битного
[Telegram user ID](https://core.telegram.org/bots/api#user) и исключает пересечение
с работами пользователей бота. ID всегда вычисляет сервер, клиент его не задаёт.
Источник контракта: 105.sovetnik/src/checkfrod/client.ts и действующие web/app.py,
web/auth.py сервиса (только чтение). API создания не поддерживает idempotency key.
