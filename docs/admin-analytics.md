# Аналитика пользователей

Проверено по исходникам 2026-10-09. Раздел доступен только администратору:
`/admin/student-analytics`. Он показывает учеников и администраторов, включая
собственный аккаунт администратора.

## Как открыть карточку

1. В меню администратора выберите «Аналитика пользователей».
2. Найдите человека по имени или email и нажмите на его имя. В списке есть
   постраничная навигация; email видны только администратору.
3. Для прямого перехода используйте `/admin/student-analytics?user=<ID>`.
4. Кнопка «Карточка пользователя» открывает обычную карточку CMS.
   «Назначить обучение» доступна для ученика и ведёт в редактор назначений.

Сведения обновляются раз в минуту, пока вкладка видна. Для немедленной
проверки нажмите «Обновить». Список устройств и история имеют отдельные страницы.
После ошибки загрузки доступна повторная попытка; данные другого выбранного
пользователя не подставляются в карточку.

## Как читать сведения о входах

- **Активность за последние 5 минут** — недавно поступил сигнал открытой
  вкладки. Это не подтверждение, что человек непрерывно смотрит экран.
- **Вход сохранён** — сессия действительна, но недавнего сигнала нет.
  Пользователь мог закрыть сайт; новый вход обычно сохраняется на 30 дней.
- **Срок входа истёк** — закончился срок сессии.
- **Вход завершён** — сессия больше не действительна, например после выхода.

Устройство, браузер и ОС определяются приблизительно по данным браузера;
это категория устройства, а не его точная модель. Режим «Приложение» означает
запуск в отдельном окне установленной PWA. Часовой пояс сообщает устройство.

Входы, созданные до начала сбора этих сведений, показываются как неизвестные
устройства. Неизвестные браузер, IP и география не восстанавливаются задним числом.

IP-адрес относится к сетевому подключению. Страна, регион и город определяются
приблизительно по локальной базе [DB-IP Lite](https://db-ip.com/db/lite.php),
распространяемой по [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).
VPN, мобильный оператор и корпоративная сеть могут показывать другое место.
Если база не содержит адрес или сведения недоступны, отображается
«Не определено»; точные координаты браузера не запрашиваются.

## Обучение и история

«Последнее место обучения» показывает сохранённый урок, курс и позицию видео.
Она относится к аккаунту пользователя, поэтому переносится между устройствами.
В верхней строке находятся число пройденных уроков, задачи с серверной проверкой,
баллы, достижения и сертификаты. Просмотр аналитики не меняет эти результаты.

История различает два источника:

- **Зафиксировано платформой** — вход/выход, сохранённое прохождение,
  успешная серверная проверка задачи, выдача достижения или сертификата.
- **Сообщено устройством** — открытие страницы или урока. Это наблюдение,
  а не доказательство просмотра видео целиком.

История начинается с новых действий после включения сбора. Общие результаты
обучения читаются из существующих коллекций, поэтому прежние баллы и прохождения
сохраняются, даже если подробных событий за прошлое время нет.

## Скорость сайта у конкретного пользователя

Раскройте «Скорость сайта у пользователя за 30 дней». В ней показаны
измерения, которые сообщают поддерживаемые браузеры:

| Показатель | Что показывает | Единица |
|---|---|---|
| LCP | Загрузка основного содержимого | секунды |
| INP | Отзывчивость на действия | миллисекунды |
| CLS | Стабильность расположения элементов | безразмерное значение |

Рядом приведены количество наблюдений и p75: для 75% наблюдений значение
не выше показанного. Отсутствующие измерения обозначаются «Нет данных»,
а не нулём. При малой выборке показано пояснение; положительный рейтинг
не выставляется. Порог 30 наблюдений для пояснения — осторожный ориентир
интерфейса, а не официальный критерий Core Web Vitals.

Общие ориентиры и методика описаны в [документации Core Web Vitals](https://web.dev/articles/vitals).
Эти показатели отражают браузерный опыт; сами по себе они не заменяют
серверные логи и трассировки при поиске причины проблемы.
Значения сообщает устройство; сервер не может доказать, что пользователь
не изменил сообщение вручную. Метрики используются для диагностики,
не влияют на прогресс и не предоставляют доступ к учебным материалам.

## Доступ и хранение

Страница и API проверяют действительный вход и актуальную серверную роль
администратора. Ученик не может читать даже собственную административную
аналитику или перечислять других пользователей через этот API.

Ответ не содержит JWT, cookie, исходные SID, хеши сессий, полный User-Agent,
тексты уроков или подписанные ссылки на видео. События не сохраняют query/hash;
административные пути и коды комнат собеседований сокращаются до общего пути.

Подробные события и неактивные записи устройств очищаются после 90 дней
ограниченными пакетами. IP перестаёт выдаваться после своего 30-дневного срока
и затем удаляется очисткой. Новое сетевое наблюдение обновляет этот срок.
Для производительности карточка агрегирует последние 30 дней; старые записи
также очищаются после 90 дней. Удаление пользователя очищает связанные записи.

`src/server/web-vitals.ts`, `src/components/analytics/StudentActivityBridge.tsx`,
`src/components/student-analytics/`, `src/app/api/manage/student-analytics/route.ts`.
