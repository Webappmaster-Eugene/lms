# Видео уроков и задержки воспроизведения

Видео Яндекс Диска проходит через `/api/yandex-disk/stream` или `/proxy`.
Каждый запрос, включая Range и HEAD, сначала проверяет сессию, публикацию
урока и текущий учебный доступ. Браузер получает байты файла, а не публичную
ссылку папки или временный CDN href. Ответы имеют `private, no-store`; PWA
не кеширует видео и приватный API.

## Оптимизации

- Видимое нативное видео заранее получает `preload=auto`. Видео ниже экрана
  остаётся с `preload=none`, поэтому несколько записей не конкурируют за сеть
  и шесть допустимых активных потоков пользователя. При Save-Data или 2G
  используется только metadata; без IntersectionObserver — совместимый
  metadata fallback. Preload является подсказкой: браузер может её игнорировать.
  Скрытые вкладки начинают подготовку только после показа. Уже запущенное
  видео при уходе в фон не прерывается.
- Временные href кешируются пять минут в памяти процесса, общей для разных
  Next route bundles. Параллельные запросы одного файла объединяются в один
  вызов download API. TTL отсчитывается от получения ссылки. Отмена одного
  читателя не прерывает другой Range; отмена всех читателей прекращает API-запрос.
- Отказ CDN 403/410 сбрасывает именно отклонённый href и перевыпускает его
  один раз. Сохраняются Range, HEAD, проверка каждого redirect и общий дедлайн
  заголовков 15 секунд. Постоянный отказ не запускает бесконечные повторы.
- `Server-Timing: disk_href;dur=…, disk_headers;dur=…` разделяет ожидание ссылки
  и заголовков CDN. Это только длительности, без URL, путей, токенов и user ID.
  Полное время декодирования/буферизации нужно смотреть отдельно в браузере.

Href — возможность доступа к исходнику. Его нельзя помещать в общий кеш
учебного каталога Redis, клиентский state, persistent логи или отчёты.
Это также не повод кешировать авторизацию: отзыв назначения действует на
следующий запрос видео.

## Проверка реального файла 2026-10-10

Для урока 78 «Методы исследований: CustDev, JTBD, MVP» в startup-marketing
проверены только чтение контента и короткие Range, без изменения прогресса.
Файл — MP4, 120754153 байта. Индекс moov размером 315533 байта уже находится
в начале, после ftyp на смещении 32: этот файл уже подготовлен для fast start.

Три запроса 64 КиБ через существующий прод дали 206: первый ответ с
заголовками за 964 мс, следующие за 109 и 113 мс. Независимый download API
ответил за 290 мс, прямой CDN — с заголовками за 374 мс. Это отдельная
выборка из серверной сети, а не обещание таких же цифр на телефоне. Во время
проверки остановка на пять секунд не воспроизвелась. Подписанные ссылки
не сохранены.

## Что остаётся ограничением источника

Объединение запросов и preload уменьшают ожидание старта, но не повышают
пропускную способность Яндекс Диска или мобильной сети. Download API отдаёт
файл, а не адаптивный HLS/DASH-поток с несколькими качествами. Публичные
скачивания также могут ограничиваться тарифом источника.

MPEG-TS сейчас transmuxed на клиенте и перематывается только внутри
подготовленного буфера. Возврат далеко вперёд требует скачать поток от начала:
пропорциональный прыжок по байтам без индекса ненадёжен. Для таких записей
следующий содержательный шаг — подготовить MP4 с индексом впереди либо
адаптивные HLS/DASH версии с keyframe index и защищённой выдачей сегментов.
Это отдельная обработка медиа, а не смена HTTP Cache-Control. Исходники и
связи уроков при такой обработке должны сохраняться.

Если обычный MP4 имеет moov в конце, копию без перекодирования можно
подготовить `ffmpeg -i input.mp4 -c copy -movflags +faststart output.mp4`.
Для уже проверенного урока 78 эта операция не нужна. Новые варианты не должны
выдавать исходные CDN href ученику или обходить проверку назначений.
