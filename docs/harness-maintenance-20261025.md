# Обслуживание харнесса LMS — 25 октября 2026

Первый локальный проход по [гайду](guides/harness-maintenance.md). Рабочая копия:
`wt-public-guides`, ветка `chore/harness-maintenance`. Production и контент LMS
в этом проходе не менялись. Slash-скиллы Claude Code здесь не запускались:
использованы проектный Codex-harness и непосредственное ревью.

## Что нашли и исправили

| Проблема | Подтверждение | Изменение |
| --- | --- | --- |
| `sync` из соседнего worktree перезаписывал общий конфиг | Воспроизведено в одноразовом checkout: изменялся родительский config, затем возникал конфликт AGENTS.md | Общие источники отделены от конфигов, которыми владеет checkout; исправлены sync, doctor, launcher, trust и native-check |
| Память загружалась с историческими дублями и обрезалась посреди текста | 25 318 символов в проектном MEMORY.md, лимит загрузки 16 000; 35 тематических файлов Claude читались вместе с индексом | История сохранена в архиве; короткий активный индекс; из Claude читается живой MEMORY.md, темы — по ссылкам |
| Старая память отрицала блокировку отключённого пользователя | Код learningAccessPolicy.ts и contentWorkflows.test.ts подтверждают 401 при isActive=false | Активная запись исправлена, архив явно помечен историческим и снабжён поправкой |
| Self-review требовал минимум три улучшения при любом состоянии кода | Противоречил собственной Codex-адаптации «не выдумывай улучшения ради числа» | Квота заменена проверкой подтверждённых проблем с явным отчётом об объёме ревью |
| Python пробовал создавать кеш вне разрешённого проекта | В предыдущей сессии py_compile получил отказ записи в пользовательский кеш | PYTHONPYCACHEPREFIX добавлен в проектный shell environment рядом с кешами npm/pnpm |
| Ошибка запуска app-server скрывала причину отказа | codex:trust завершался только сообщением «app-server exited»; диагностика выявила отказ инициализации SQLite в пользовательском CODEX_HOME | Безопасное сообщение об ограничении, без вывода приватного stderr |
| Для браузера выбирался Chrome вместо Яндекса | Предыдущий browser MCP искал Google Chrome; у пользователя профиль Яндекса | В локальном игнорируемом override выбран существующий профиль через штатные --autoConnect и --userDataDir |

`configRoots` — единый источник области конфигурации для пяти операций.
Проверка локальных ссылок переиспользуется для скиллов и индекса памяти.
Широкий рефакторинг продуктового кода не понадобился: основная подтверждённая
архитектурная проблема была в смешении общего workspace и конкретного checkout.

## Как применили пункты гайда

- `/doctor`: `pnpm codex:doctor`, inventory скиллов/ролей/MCP, замеры hooks,
  проверка источников и зависимостей. Установлены зависимости отдельного landing
  по его npm lockfile; синхронизирован актуальный общий CLAUDE.md.
- `/fewer-permission-prompts`: просмотрены действующие разрешения и deny-правила.
  `approval_policy=never` уже действует; расширять allowlist оснований не было.
  Проблема обычного Python-кеша решена локальным путём кеширования.
- `/run-skill-generator`: проверен рецепт запуска и quality gate ниже;
  актуализировано docs/CODEX.md. Новый дублирующий скилл запуска не создавался.
- `/retro`: разобрана предыдущая сессия публичных гайдов. Неполадки worktree и
  браузера получили конкретные изменения и проверки, вместо новых общих правил.
- `/simplify`: общий configRoots, общий проход ссылок и чтение индекса памяти
  устранили повторение и лишнюю загрузку истории.
- `/code-review`: проверены scripts/codex, инструкции и наиболее активная за
  неделю подсистема гайдов — политика доступа, публикация, гостевые страницы
  и связанные media. Новых подтверждённых дефектов продуктового кода не найдено;
  это ограниченный проход, а не утверждение о полном ревью всех изменений недели.
- `/improve-codebase-architecture`: разделены источники workspace и владение
  конфигурацией checkout. Регрессии проверяют sibling, canonical и standalone.

Все четыре настроенных MCP прошли handshake/tools-list: webstorm (43), context7
(2), playwright (25), chrome-devtools (32). Этот результат не подтверждает
операции сервисов. Доказательств неиспользуемости, достаточных для удаления
одного из подключений или скиллов, не найдено.

## Воспроизводимый запуск

Из корня выбранного checkout:

```sh
pnpm install --frozen-lockfile
cd landing
npm ci
cd ..
pnpm codex:sync
pnpm codex:doctor
pnpm codex:test
```

После настройки локального окружения `DATABASE_URL` и `PAYLOAD_SECRET`:

```sh
pnpm dev
# В отдельном терминале, после правок:
pnpm codex:verify
```

Для одноразовой БД и предсказуемого сида использовать
`scripts/e2e-server.mjs` и [инструкцию тестирования](testing.md). Секреты в рецепт
не записываются. Публичный гайд и прочие production-данные для проверки не нужны.

## Проверки и ограничения

`pnpm codex:verify` прошёл полностью: 21 тест харнесса, lint, typecheck,
3997 тестов приложения (3 skipped), production build и отдельный Astro build.
`pnpm codex:doctor` и `pnpm codex:mcp-check` прошли.

`codex:trust` в текущей управляемой среде не выполнен: установленный Codex CLI
0.164.0 не может инициализировать SQLite-состояние в `~/.codex`. Поэтому
фактическая native-проверка загрузки и доверия hooks остаётся непроверенной.
Нужны обычный терминал пользователя и команды из этого checkout:

```sh
pnpm codex:trust
pnpm codex:native-check
```

`codex:browser-check` не подтвердил чтение страниц Яндекса. Профиль выбран,
но подключение требует проверки удалённой отладки/согласия в самом браузере.
Новые профили/вкладки не открывались, браузер не перезапускался, cookies не
извлекались. После ручного восстановления: `pnpm codex:browser-check`.

Механика слоёв и доверия сверена с официальной документацией OpenAI:
[project config](https://learn.chatgpt.com/docs/config-file/config-advanced),
[hooks](https://learn.chatgpt.com/docs/hooks),
[app-server](https://learn.chatgpt.com/docs/app-server). Изменение файлов не
снимает ограничения управляющей среды и не заменяет доверие пользователя.

## Следующее обслуживание

Еженедельно: посмотреть изменения активных каталогов и конкретные повторения.
Ежемесячно: doctor, тесты харнесса, чтение индекса памяти и MCP inventory.
После изменения запуска: проверить полный codex:verify. После трудной сессии:
зафиксировать наблюдаемый сбой и минимальную проверку, которая не даст ему
повториться. Расписание автоматических заданий этим проходом не создавалось.

Self-review: проверены владение конфигами, сохранность исходной памяти, fallback
без Claude-индекса, границы усечения и приватность диагностик. Локальные правки
готовы к коммиту; native-проверка и браузерная интеграция сохраняют ограничения,
описанные выше.
