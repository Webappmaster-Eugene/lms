# Репетиторство в LMS

Наставник работает в «Управление → Репетиторство». Он создаёт поток Node.js
на 32 встречи или React + Next.js на 24, выбирает первый вторник и указывает
время МСК. Карточки строят календарь на вторник и четверг каждой недели.
Ссылка на созвон задаётся в настройках потока и открывается у участника
из карточки занятия.

Поток создаётся черновиком. После загрузки материалов откройте поток
ученикам и добавьте участников по адресу их активных аккаунтов LMS.
При добавлении подтвердите получение оплаты за репетиторство.
Дату подтверждения хранит карточка участника.

В потоке сохранены две отметки. «Текущая встреча потока» открывает материалы
группе до указанного номера включительно. «Текущая встреча ученика» выбирает
стартовую карточку этого ученика и позволяет двигаться вперёд индивидуально.
Архивация скрывает поток от его учеников. Наставник по-прежнему видит журнал.

Ученик на странице репетиторства листает PDF, читает условие, отправляет
HTTPS-ссылку на работу и видит статус и комментарий. После доработки
можно отправить ссылку повторно. В журнале наставника видны текущая встреча,
число принятых работ и число работ на проверке. Прогресс хранится отдельно
для каждой пары «ученик и поток».

Комплект включает постановки домашних работ и полные проектные задания
из пакета методичек. Заметки для проведения и ответы видны наставнику.
Назначение в поток репетиторства не выдаёт доступ к отдельному курсу
методичек буткемпа. Зачисление и оплата буткемпа работают по их правилам.

## Переносы и Google Calendar

В «Календарь и настройки потока» выберите предстоящую встречу и нажмите
«Перенести». Новое время по Москве видно всем участникам потока. Если исходная
дата ещё впереди, действие «Вернуть по расписанию» отменяет перенос. Переносы
не меняют порядок материалов и сдач.

Чтобы видеть занятия в Google, откройте «Админка → Репетиторство → Google Calendar»,
подключите свой аккаунт и добавьте нужные потоки в календарь через их настройки.
LMS создаёт календарь MentorCareer и отправляет туда будущие встречи открытых
потоков. Для изменения времени используйте LMS. Архивация и удаление потока или
действие «Убрать поток из календаря» очищают его будущие события. После полного
отключения аккаунта уже созданные события остаются в Google.

Для включения интеграции создайте веб-клиент OAuth в Google Cloud и включите
Calendar API. Зарегистрируйте адрес обратного вызова
`<NEXT_PUBLIC_SERVER_URL>/api/manage/tutoring/google-calendar/callback`.
В окружении приложения (для Dokploy — Environment) задайте
`GOOGLE_CALENDAR_CLIENT_ID`, `GOOGLE_CALENDAR_CLIENT_SECRET` и постоянный
`GOOGLE_CALENDAR_ENCRYPTION_KEY` (32 случайных байта в base64). Используйте
отдельный OAuth-клиент для тестов. У внешнего приложения в режиме Testing
токен с доступом к календарю истекает через семь дней.

Синхронизацию запускает существующий планировщик уведомлений. Статус и время
последней успешной выгрузки видно в админке. При временном сбое Google LMS
продолжает сохранять переносы и повторяет попытки автоматически.

## Загрузка материалов

После применения миграции запустите импорт из репозитория LMS. Папка экспорта
содержит `meetings.json`, PDF и заметки ведущего. Два каталога `lessons` берутся
из пакетов методичек. Сначала проверьте локальные файлы.

```sh
node scripts/import-tutoring-meetings.mjs ../bootcamp/live-lessons/lms-import \
  --node-practice ../bootcamp/content/dist/package/mentorcareer/lessons \
  --react-practice ../bootcamp/frontend/journey-content-work/.runtime/package/mentorcareer/lessons
```

Для сверки с выбранной LMS передайте через окружение `LMS_URL`,
`LMS_ADMIN_EMAIL` и `LMS_ADMIN_PASSWORD`. Режим по умолчанию покажет изменения,
`--apply` сохранит их. Идентификатор занятия в CMS определяется по программе
и номеру. Повторный импорт одинаковых исходников пропускает все 56 встреч.

PDF хранятся в отдельной коллекции внутри тома `media/tutoring`. Прямой запрос
на файл проверяет членство и открытые номера, как и страница встречи. Пакеты
презентаций и закрытые заметки в публичном репозитории отсутствуют.
