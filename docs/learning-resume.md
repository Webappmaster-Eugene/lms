# Авторизация и продолжение обучения

Новые входы в Payload используют постоянную HttpOnly cookie, JWT и сессию
на 30 дней. HTTPS использует Secure cookie; HTTP локальной разработки
поддерживается через существующий `NEXT_PUBLIC_SERVER_URL`. Пароли и JWT
не сохраняются в localStorage. Logout отзывает сессию.
Ранее выпущенные JWT сохраняют старый срок до refresh или нового входа.
Приглашения и сброс пароля имеют отдельные сроки, их настройка не изменена.

`lesson-learning-states` хранит одну запись на пару урок/пользователь:
фактический последний просмотр, выбранное видео и JSON позиций клипов.
Коллекция читается владельцем/администратором; прямые записи через REST
закрыты. Изменения выполняет `/api/learning-state` после авторизации,
проверки публикации урока и родителей, владельца и реального video ID.
Запись в транзакции с advisory lock предотвращает потерю параллельных клипов.
Event timestamps позволяют игнорировать запоздалую отправку старой вкладки.
Просмотр не завершает урок, не начисляет XP и не вызывает хуки достижений.

Идентификатор клипа включает block ID и fingerprint источника: замена ролика
не перематывает новую запись на время старой. Provider отмечает открытие
после mount/видимости; RSC-prefetch не создаёт историю. Клиент сохраняет
позицию периодически, при паузе, перемотке и уходе со страницы. Локальный
fallback разделён по user/lesson/video, отправка повторяется при online.
Старые общие локальные позиции не импортируются в другой аккаунт.

Дашборд показывает последние доступные места остановки отдельных курсов,
а `/learning-history` — историю посещённых уроков с фильтром по курсу и пагинацией.
Повторный просмотр перемещает урок вверх: это одна запись на урок, а не
журнал каждого открытия. Метка «Пройден» берётся из явного завершения урока;
сам просмотр не меняет прогресс. Скрытые материалы и отозванные назначения
исключаются перед пагинацией. Возврат доступа сохраняет прежнюю историю.

Страница урока передаёт авторизованное место остановки сразу при серверном
рендеринге, без отдельного GET после загрузки интерфейса. GET/POST используют
один Payload request с уже проверенным доступом конкретного урока и выборку
по владельцу/уроку через существующий unique index. История сортируется с
добавочным индексом user/lastViewedAt; метаданные уроков, курсов и завершения
выбираются пакетно, а политика доступа переиспользуется в пределах запроса,
включая уже рассчитанные Payload при авторизации CMS permissions.
Последний урок каждого курса находится постранично без скрытого лимита
первых 20/50 записей. При поиске мест остановки дашборд сканирует только
связи урок/курс; контент, метаданные загруженных видео и завершение подгружаются
пакетно лишь для выбранных карточек (до шести). Видео в file-блоках получают
минимальные метаданные Media после проверки доступа урока, без общего populate.
Приватные позиции и пользовательские права не кладутся
в общий Redis: он по-прежнему хранит только учебные метаданные. Native-плеер восстанавливает
точную секунду, TS ждёт загрузки нужного буфера и показывает подготовку.
Для позиции дальше 30 минут бюджет загрузки увеличивается до позиции плюс
60 секунд и сохраняется после перемотки, чтобы плеер не пересоздавался.
Внешние iframe/YouTube и просмотр вне платформы позиции не сообщают.

Схема добавляется штатной миграцией `20261008_095919_lesson_learning_states`.
Это только новая таблица, индексы и FK; старые таблицы и записи сохраняются.
Новая миграция проверена up/down/up на локальной копии только схемы прода,
без переноса данных пользователей, и на одноразовой БД с тестовыми данными.
Исторический down `20261005_213201_interview_rooms_and_contacts` повторно
удаляет constraint после CASCADE; этот прежний дефект не относится к накату
новой схемы и не исправлялся ручным изменением миграции.

Проверки: `authSession.test.ts`, `learningState.test.ts`,
`LearningVideoMemory.test.tsx`, `TransportStreamResume.test.tsx`,
`authCookie.test.ts`, `auth.spec.ts`, `learning-resume.spec.ts`.
Browser test использует собственный 15-минутный WebM: desktop play/pause на
12:34, независимый телефон с пустым localStorage, восстановление настоящего
`video.currentTime`, новая вкладка, чужой пользователь и текстовый урок.

Для добавления ученика без почты администратор открывает
`/admin/collections/users/create`, задаёт имя, фамилию, email, роль student
и пароль, сохраняет и передаёт данные напрямую. Ошибка приглашения не
отменяет создание аккаунта; пароль хешируется Payload. Пользовательские
пароли, ссылки с токенами и ключи не сохраняются в документации и отчётах.
