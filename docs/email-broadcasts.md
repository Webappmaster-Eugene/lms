# Email-рассылки

Администратор пишет письмо ученикам из раздела «Email-рассылки» (`/manage/broadcasts`,
ссылка есть в «Учебном контенте» и в меню админки «Общение и настройки»). Письмо
уходит через тот же SMTP, что и служебные письма (`src/payload/email/transport.ts`).

## Как отправить

1. «Новая рассылка»: тема, текст, при желании кнопка, получатели — все активные
   ученики или выбранные из поиска. Сохраняется черновик.
2. На странице рассылки — предпросмотр настоящего письма. «Отправить тест себе»
   шлёт его на адрес текущего администратора с пометкой `[Тест]` и в статистику
   не попадает.
3. «Запустить рассылку» фиксирует список получателей и ставит письма в очередь.
   Пока идёт отправка, страница обновляет счётчики сама; «Остановить» отменяет
   ещё не отправленные письма.

Разметка текста: пустая строка — новый абзац, перевод строки сохраняется,
`**жирный**`, `[текст](https://…)` и голые `https://…` становятся ссылками.
HTML не пропускается — всё остальное выводится как текст. Приветствие по имени,
подпись и подвал с отпиской добавляются автоматически. Ссылка кнопки — `https://…`
или путь платформы (`/courses`).

## Кто получит

- «Все активные ученики» — роль `student`, аккаунт не отключён.
- В обоих режимах исключаются аккаунты без адреса, отключённые и отписавшиеся.
  Исключённые считаются при запуске и видны в сводке.
- За один запуск — не больше 5000 писем.

## Отправка

Очередь — коллекции `email-broadcasts` и `email-broadcast-deliveries` (скрыты из
CMS, права закрыты; менять их можно только через `/api/manage/broadcasts/**`).
Отправляет `runEmailBroadcastJobs` (`src/server/broadcasts/service.ts`), её вызывает
планировщик уведомлений (`lms-mentor-notifications`) раз в минуту через
`/api/internal/notifications/run`.

- За прогон — до 20 писем, по одному, то есть около 1000 писем в час. Лимиты
  почтового ящика VK WorkSpace проверяйте до больших рассылок.
- Перед каждым письмом заново проверяются статус рассылки, активность аккаунта,
  адрес и согласие. Отписавшийся после запуска письмо не получит (`skipped`).
- Отказ адреса (SMTP 550–554) — окончательный `failed`. Временные отказы, сеть,
  авторизация SMTP — повтор через 5, 15, 45 и 135 минут, после пятой попытки
  `failed`. При недоступном сервере прогон останавливается, чтобы не тратить
  попытки остальных писем.
- Без настроенного SMTP письма ждут в очереди и не считаются отправленными.
- Аренда в `notification-job-state` (`email-broadcasts`) и захват письма до
  отправки не дают двум прогонам отправить одно письмо дважды.

## Отписка

В каждом письме — ссылка «Отписаться от рассылок» и заголовки `List-Unsubscribe`
и `List-Unsubscribe-Post` (RFC 8058): почтовые клиенты показывают свою кнопку
отписки. Ссылка подписана `PAYLOAD_SECRET` и работает без входа.

- `/unsubscribe?token=…` — публичная страница подтверждения (`PUBLIC_PATHS`
  в middleware), можно вернуть подписку.
- `POST /api/email/unsubscribe` — форма страницы и one-click клиентов. `GET`
  только ведёт на страницу: почтовые сканеры открывают ссылки сами.
- В кабинете — «Уведомления → Почта → Письма-рассылки».

Согласие хранится в `notification-preferences.emailBroadcastsEnabled`; нет записи —
рассылки разрешены. Письма об аккаунте (приглашение, восстановление пароля)
от отписки не зависят.

Ответ на письмо уходит на адрес из «Настройки платформы → Контакты → Email»
(`Reply-To`). Если он не задан, подвал честно пишет, что ответы не обрабатываются.

## Проверки

```sh
pnpm exec vitest run tests/unit/emailBroadcasts.test.ts
pnpm test:integration tests/integration/api/emailBroadcasts.test.ts
```

Интеграционный тест проходит путь «черновик → запуск → задача → письмо» на
настоящем Postgres с перехваченным `payload.sendEmail`: исключения, заголовки
отписки, Reply-To, отказ и повтор, остановку, двойной прогон, отписку по ссылке.
Доставку в реальные ящики после выката проверяйте тестовой отправкой себе.
