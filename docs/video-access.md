# Доступ к учебным файлам и видео

## Серверная граница

Клиент получает только идентификаторы урока, блока и материала. Исходные URL
Яндекс.Диска и временные CDN-ссылки доступны серверу и администратору CMS.
Текст, Lexical, описания и ссылочные ZIP/PDF-блоки очищаются вместе с видео.
Каталоги Диска заменяются пояснением; они не выдаются в виде ZIP всей папки.

`/api/yandex-disk/stream`, `/api/yandex-disk/proxy` и `/api/learning-assets`
проверяют действительную сессию и центральное назначение урока до доступа
к источнику. Проверяются публикация и согласованность родителей. Произвольный
`url` разрешён только администратору. Подбор asset ID не даёт права доступа.
GET и HEAD возвращают байты, а не редирект на внешний CDN. Range, 200, 206,
Content-Length, Content-Range и 416 сохраняются. Все ответы, включая ошибки,
получают `private, no-store`. Cookie и Authorization не отправляются upstream.

HTTPS-адреса CDN и каждый редирект проверяются по доменам Яндекса. Исходящий
запрос получает дедлайн 15 секунд на resolver и заголовки; успешный длинный
видеопоток не обрывается по этому таймеру. Отмена браузера отменяет запрос
к источнику. Нет raw URL, путей Диска, cookie и подписанных query в telemetry.
События отказа и ошибок имеют фиксированные reason и ID пользователя.

Native MP4 и MPEG-TS идут через общую границу. MPEG-TS остаётся доступен как
fallback для записей, ошибочно названных `.mp4`; проверка расширения не решает
авторизацию. Позиции урока и видео остаются привязаны к текущим lesson/block IDs.

## Локальная медиатека

`Media.access.read` всегда возвращает ограничивающий Where, включая для
администратора: Payload должен найти документ filename, прежде чем читать диск.
Чужой физический файл без документа или неизвестный orphan не открывается.
Specific `/api/media/file/[filename]` поддерживает GET/HEAD/Range и те же права.
И оригинал, и thumbnail/card alias проверяются по одному Media документу.

Публичны только raster-обложки опубликованных курсов/роадмапов и назначенные
аватары, у которых нет ссылки из урока. Публичная ссылка не переопределяет
защиту учебного материала: для обложки нужен отдельный файл. Студент может
назначить новым аватаром только собственную raster-загрузку до 2 MiB;
подбор чужого Media ID отклоняется до изменения профиля.
Изображения уроков, PDF, ZIP и видео требуют хотя бы одной ссылки из
доступного опубликованного урока. Повторное использование файла в закрытом и
открытом уроке разрешено при доступе хотя бы к одному из них. Новый raster-аватар
до 2 MiB доступен загрузившему ученику для preview до сохранения профиля;
`uploadedBy` принудительно задаётся сервером и не принимается от студента.

`Lessons.mediaReferences` — производный индекс связей Media. Hook вычисляет его
по image/file relations, Lexical uploads, URL блоков и описанию. Клиент не может
задать ссылки или отметить индекс готовым. Row lock и перечитывание текущего
материала защищают от гонки изменения урока с backfill. Индекс читается через
параметризованный SQL по индексированному junction; политика уроков применяется
затем через Payload. Кеш существует только внутри запроса и не задерживает отзыв.
Отзыв проверяется при следующем GET/HEAD/Range. Уже начавшийся поток и буфер
браузера не отзываются этой проверкой; немедленное прерывание активных потоков
потребует контроллеров с уведомлением после commit либо периодической проверки.

До backfill старые строки с `mediaReferencesResolved=false` используют SQL
fallback по реальным relations/URL/text. Он сохраняет права, но медленнее индексного
пути. Не оставлять этот переходный режим для большого каталога.

Административный POST `/api/manage/media-references` принимает
`{ "cursor": 0, "limit": 25 }` для dry-run и тот же запрос с `"apply": true`
для записи. Максимум 50 уроков, admin session и same-origin обязательны. Ответ
содержит scanned/resolved/nextCursor, без материалов. Повторять запросы с
nextCursor до null; повтор после ошибки безопасен. Материал не передаётся обратно
в update: серверный hook берёт originalDoc и обновляет производные поля.
Создание и изменение уроков обновляют индекс штатно.

## Нагрузка и пределы защиты

На одном Node-процессе действуют 6 активных потоков и 120 запросов в минуту на
пользователя. Состояние разделено между route bundles и ограничено 10000 viewer
records. EOF, ошибка, cancel и abort освобождают квоту. При нескольких инстансах
эти лимиты действуют отдельно: перед масштабированием нужен общий rate/concurrency
limiter или лимит на edge, связанный с действительной серверной identity.

Весь трафик теперь проходит через LMS. Например, 100 зрителей × 6 Мбит/с —
600 Мбит/с входящего и 600 Мбит/с исходящего трафика; это расчёт, не измерение.
Нужно наблюдать latency, stream errors, rate limits и ресурсы сервера.

Назначения закрывают несанкционированную выдачу из LMS. Авторизованный ученик
получает байты и технически может сохранить их; скрытая кнопка скачивания этого
не предотвращает. Старые публичные ссылки Диска работают вне LMS. Ранее скачанные
копии и записанный экран отозвать нельзя. После переноса исходников в приватный
origin владелец должен отключить прежние публикации. DRM, упаковка HLS/DASH и
персональная маркировка — отдельная инфраструктура; текущий выкат её не обещает.

## Проверки

Unit-проверки покрывают stream quotas и их освобождение, Range, безопасные
redirects, deadline заголовков без timeout тела, source resolution и redaction.
Integration-проверки используют настоящие Payload/БД: чужое назначение, отзыв,
скрытый родитель, orphan, public covers/avatars, avatar preview, asset reuse,
aliases, metadata, GET/HEAD и реальный Range. После выката эти сценарии проверяются
на HTTP сервера; настоящий видеохостинг не заменяется ответом тестового CDN.
