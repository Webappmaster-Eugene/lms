# Уведомления и напоминания ученикам

Преподаватель отправляет сообщение через `/admin/collections/notifications`, выбирая ученика, заголовок, текст и внутреннюю ссылку. Ученик видит только свои сообщения и может изменить только `isRead`. Получатель, текст, тип и ссылка доступны для изменения только администратору. Пуш — дополнительный канал того же сообщения, а не отдельное письмо: SMTP для него не нужен.

## Согласие и устройства

`GET /api/push/settings` возвращает настройки аккаунта, публичный ключ VAPID, доступность пушей и число подписок. Приватные ключи, endpoints и browser auth keys через API коллекций недоступны даже администратору; операции выполняют закрытые серверные сервисы.

`PATCH /api/push/settings` меняет `remindersEnabled`, `pushEnabled`, `timezone` и `reminderHour`. Настройки действуют на аккаунт. Пуши изначально выключены; разрешение запрашивается интерфейсом только после действия пользователя. `POST /api/push/subscriptions` привязывает `PushSubscription.toJSON()` к текущему авторизованному ученику. `DELETE` с `{ endpoint }` отключает только это устройство, не другие устройства аккаунта. `POST /api/push/test` по явному нажатию ставит пробное уведомление в очередь; максимум одно в минуту, включая параллельные запросы.

Подписка связана с SHA-256 текущего SID. Перед каждой отправкой сервер проверяет свежую сессию пользователя, её срок, отзыв, активность пользователя и согласие на пуши. Выход, истечение входа и сброс пароля прекращают доставки в старую сессию. Чужой аккаунт не может переназначить уже зарегистрированный endpoint. Отключение прежней browser-подписки и её создание заново требует действия пользователя.

## Автоматические напоминания

In-app напоминания включены по умолчанию и отключаются в настройках. Первое приходит через 3 дня без учебной активности, следующее после 7 дней, последнее после 14 дней. Это настраиваемая продуктовая политика, а не обещание научно оптимального интервала. Не более трёх сообщений до возобновления обучения; между пропущенными этапами выдерживаются минимум три дня. Текст спокойный, без угроз потерей серии или наказаний.

Сервер учитывает сохранённое изменение видео-позиции и подтверждённое выполнение урока/задачи. Вход, открытие настроек и простое открытие страницы не сбрасывают таймер. При первом создании настроек сервер восстанавливает дату из существующего учебного прогресса и видео-позиций. Ученики без доступных опубликованных уроков и ученики, завершившие все доступные уроки, не получают такие напоминания.

Согласованный час — с 08:00 до 21:00 в выбранном часовом поясе, по умолчанию 18:00 Europe/Moscow. Повторная доставка напоминания тоже ждёт этого локального часа; после возобновления обучения, отключения напоминаний или истечения 24 часов ожидающий пуш отменяется. Уже созданное in-app сообщение остаётся в истории.

## Надёжность и защита

Создание уведомления и записей `notification-deliveries` происходит в общей транзакции исходного события. Хуки не отправляют HTTP. Отдельный scheduler раз в минуту вызывает `POST /api/internal/notifications/run`; ключ вычисляется как HMAC-SHA256 от `PAYLOAD_SECRET` и строки `lms-notifications-scheduler-v1`. Этот ключ отсутствует в браузере. У задачи есть долговечная lease на 5 минут; захват доставки фиксируется до внешнего HTTP.

Переподключение к push-provider ограничено пятью попытками с увеличением интервала. HTTP 404/410 отключают подписку; другие ошибки 4xx и редиректы не повторяются. 429, 5xx и сетевые ошибки повторяются ограниченно. Незавершённая последняя попытка после истечения lease становится `failed`, а не зависает навсегда. Доставка — at-least-once: сбой после принятия provider и до записи результата может повторить отправку. Одинаковый notification tag заменяет такое сообщение на устройстве.

Используется стандартное шифрование Web Push `aes128gcm` и VAPID через библиотеку [web-push](https://github.com/web-push-libs/web-push). HTTPS разрешён только известным browser-provider: Google FCM, Mozilla, Apple и Windows Notify. Проверенные публичные DNS-адреса закрепляются при HTTPS-подключении; локальные/частные адреса и редиректы запрещены. Пуш содержит ограниченные заголовок/текст и внутреннюю ссылку. На экране блокировки телефона текст может отображаться в соответствии с настройками ОС.

Для работы нужны `PUSH_VAPID_PUBLIC_KEY`, `PUSH_VAPID_PRIVATE_KEY` и `PUSH_VAPID_SUBJECT` (mailto администратора либо HTTPS-сайт). Пара ключей генерируется один раз и хранится в Dokploy Environment; менять её без необходимости нельзя — существующие подписки используют прежний публичный ключ. Без корректной конфигурации in-app продолжает работать, а интерфейс сообщает о недоступности пушей.

## Проверки

`tests/unit/pushTransport.test.ts` проверяет настоящий шифротекст, расшифровку ключом получателя, отказ чужому ключу, VAPID, публичные адреса и коды provider. `tests/unit/notificationPolicy.test.ts` проверяет интервалы, тихие часы, сроки и ссылки. `tests/integration/api/notifications.test.ts` использует настоящую PostgreSQL и HTTP/Payload API: доступы, администраторское сообщение, неизменяемый текст для ученика, атомарную очередь/откат, параллельную квоту, 410, retry, opt-out, lease, сброс по активности и запрет после выхода. Provider в интеграционных тестах заменён контролируемым транспортом; сообщения реальным ученикам не отправляются.

Нативную доставку на конкретный Android/iPhone нужно подтвердить на установленном PWA с выданным пользователем разрешением. На iOS Web Push требует добавленного на домашний экран web app и поддерживаемой версии ОС; серверные/браузерные тесты сами по себе не подтверждают показ на физическом телефоне.
