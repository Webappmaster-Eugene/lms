# Хранилище записей собеседований

Личные записи хранятся на Яндекс Диске без публикации. `YANDEX_DISK_TOKEN`
используется только сервером; токен должен разрешать чтение и запись файлов.
`YANDEX_INTERVIEWS_ROOT` задаёт отдельную папку, по умолчанию `disk:/LMS interviews`.
После загрузки записей менять корень без переноса файлов и обновления их путей
нельзя. При отсутствии токена загрузка завершается понятной ошибкой настройки.

Личный путь строится сервером:
`<root>/<owner-id>/<recording-id>-<uuid>.mp4` (также WebM, MOV, MKV).
Произвольные имена и пути от ученика не используются. Чтение, проверка и удаление
в storage helper разрешены только для точного формата зарезервированного файла
в этой папке. Авторизацию и проверку владельца документа выполняет вызывающий
API до обращения к хранилищу; проверка пути их не заменяет.

Создание сессии загрузки резервирует документ LMS и путь файла. Сам файл
передаётся raw PUT на собственный API LMS и потоково отправляется в Яндекс Диск.
Это сохраняет `connect-src 'self'` и не требует поддержки CORS внешним uploader.
Подписанный адрес загрузки выпускается заново непосредственно перед передачей;
OAuth, адрес uploader и адрес скачивания не попадают в клиентский ответ.

Лимит — 2 ГиБ на запись. Сервер проверяет заявленный и фактически полученный
размер без буферизации видео целиком. После передачи сервер сверяет размер и
MIME через метаданные Диска. Только успешная проверка переводит запись в ready.
Файл с ошибкой загрузки должен быть удалён вызывающим workflow перед удалением
документа либо сохранён для повторной очистки. Внешнюю запись на Диск нельзя
объединить в транзакцию PostgreSQL: workflow отвечает за компенсацию ошибок.

Просмотр проходит через защищённый API LMS, включая GET, HEAD и один Range.
Ответы имеют `private, no-store`, `nosniff`, sandbox CSP и не раскрывают временную
ссылку. Все переходы CDN проверяются по HTTPS и разрешённым доменам Яндекса.
При 403/410 адрес обновляется один раз с сохранением Range. Подписанные ссылки
скачивания кешируются на пять минут только в памяти серверного процесса.
Ограничения параллельных потоков общие с уроками; таймаут получения заголовков —
15 секунд. Максимальное время передачи загружаемого файла — 30 минут.
При асинхронном удалении (HTTP 202) сервер проверяет operation до подтверждения
success, не более 20 секунд. Неудачная или незавершённая операция вызывает
ошибку, чтобы workflow сохранил документ и мог повторить очистку файла.

Встроенный импорт читает две публичные папки, указанные владельцем платформы:

- `GnyK5icpAuUnnQ` («Мои собесы») — записи ментора.
- `OExQrM0fLW1APQ` («Все чужие собесы») — чужие записи.

Категория «Мои собесы» ученика к первой публичной папке отношения не имеет.
Направления React и Node.js определяются по соответствующим папкам источника.
Импорт сохраняет публичный ключ и путь, а не временный адрес CDN; обходит
вложенные папки постранично и игнорирует остальные типы файлов. Лимиты обхода:
500 записей по умолчанию, 500 папок, глубина 8, четыре параллельные папки,
общее ожидание 120 секунд.
Достижение лимита вызывает ошибку, чтобы неполный импорт не выглядел успешным.

MOV/MKV принимаются как исходные записи, но воспроизведение их кодеков зависит
от браузера. Загрузка не выполняет перекодирование; совместимость конкретного
файла и готовность аналитики проверяются отдельно от хранилища.

Первичный источник протокола: [REST API Яндекс Диска](https://yandex.com/dev/disk/rest/?lang=ru-RU).
Методы: `PUT resources`, `GET resources/upload` → PUT временного адреса,
`GET resources`, `GET resources/download`, `DELETE resources`.
