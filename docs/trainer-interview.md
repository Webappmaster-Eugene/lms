# Совместное собеседование

Вход: `/trainer/interview/new`, либо `/trainer/interview/new?taskId=<id>` из задачи.
Комната сохраняется в `interview-rooms`; приглашение — UUIDv4 в адресе
`/trainer/interview/<token>`. Только вошедшие активные пользователи могут создавать
комнату или вступать по приглашению. До восьми участников.

В комнате есть общий код JavaScript/TypeScript, условие выбранной опубликованной
задачи, список участников, длительность сессии и личная консоль. Шаблон и преамбула
копируются при создании. Эталоны, подсказки, ожидаемый вывод и тесты задачи в комнату
не копируются. Удаление или правка исходной задачи не меняет начатую сессию.

Код сохраняется после паузы в наборе (800 мс); остальные вкладки получают снимок
раз в две секунды. Это синхронизация снимков, а не посимвольное совместное
редактирование. Версия кода проверяется в PostgreSQL-транзакции под блокировкой
строки. При конкурентной записи API возвращает 409 и текущий снимок. Локальный
черновик остаётся в редакторе до явного выбора общей версии или своего черновика.
Новый ввод во время сохранения остаётся следующим несохранённым изменением.
Heartbeat обновляет присутствие каждые 15 секунд, не повышая версию кода.
Опрос приостанавливается в скрытой вкладке; уход со страницы отменяет запросы.

«Запустить» использует существующий изолированный браузерный раннер. Для TS
отдельный маршрут компилирует код через дочерний процесс песочницы. Свои примеры
можно запускать через `console.log` и API `test`/`expect`. Таймеры виртуальные:
для проверки задержек используется `__clock.tick(ms)`. Консоль и автозапуск
индивидуальны. Маршруты submit и проверки прогресса не вызываются.

Владелец может завершить сессию. Код остаётся доступен участникам для чтения,
новые участники, изменения и запуски запрещены. При удалении владельца его
комнаты удаляются существующим транзакционным хуком очистки пользовательских
связей. Прямая запись в коллекцию через REST запрещена, включая администратора.

API: `POST /api/trainer/interview` создаёт комнату; `POST /<token>` вступает или
обновляет присутствие; `GET /<token>` возвращает снимок участнику;
`PATCH /<token>` принимает `{version, code, language}` или `{version, end: true}`;
`POST /<token>/compile` принимает `{code}`. Все ответы имеют `Cache-Control:
no-store`. Запись из cookie-сессии требует Origin платформы; явные API-токены
проверяются без fallback на cookie. Лимиты: 10 созданий/минуту, 30 открытых
комнат владельца, 120 записей/минуту, 30 компиляций/минуту, общий лимит длины
кода тренажёра. Ограничение частоты действует в процессе приложения, как в
остальных маршрутах тренажёра.

Проверки: `tests/integration/trainerInterview.test.ts` — настоящая БД, авторизация,
доступы REST, конкурентные изменения, закрытие, компиляция, ограничения и удаление
владельца. `tests/components/InterviewRoom.test.tsx` — сохранность черновика и
разрешение конфликтов; `InterviewWorkspace.test.tsx` — интерфейс и запуск без
изменения прогресса.

Решение компилируется в отдельную строгую функцию. Служебный раннер и итоговый
вердикт остаются снаружи её лексической области; возвращаемое значение решения
не является результатом проверки. Публичный API содержит только средства
регистрации, утверждений и виртуальных часов. Проверочная программа регистрируется
до решения и выполняется после его инициализации. Для обычных задач зачёт учитывает
только проверки платформы; собственные проверки комнаты не начисляют прогресс.
Базовые методы встроенных объектов защищены; прототипы Array и Function допускают
добавление учебных полифиллов. Ошибки и номера строк решения проверяются отдельно.
