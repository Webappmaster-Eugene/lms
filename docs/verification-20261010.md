## Исправления по результатам проверки

- Пропущенные поля PATCH комментария берутся из свежей строки под блокировкой.
  Правка текста сохраняет новую отметку «решён»; отметка ментора сохраняет новую
  правку автора. Только администратор изменяет отметку. Удалённый комментарий
  нельзя восстановить поздней правкой.
- SDK-заголовки темы `Accept-CH`, `Critical-CH`, `Vary` ограничены админкой.
  Публичные страницы и ассеты не запрашивают тему через client hints;
  остальные SDK/security/cache-заголовки и `Vary: Cookie, Authorization` сохраняются.
- В down старой миграции interview_rooms внешний ключ снимается до
  `DROP TABLE … CASCADE`, чтобы повторное снятие ключа не ломало откат.

## Воспроизводимые проверки

```sh
pnpm smoke
pnpm test:integration
pnpm test:integration:runtime --build
```

После сборки job-образов `--build` можно опустить. Runtime-набор включает
17 проверок исполнения/изоляции, 19 проверок всех шести новых каталожных задач
и 6 проверок маршрутов LMS через настоящий HTTP gateway и Docker jobs, с записью
в отдельную одноразовую PostgreSQL. Никакие фиктивные вердикты не подменяют jobs.

Новые проверки профиля покрывают cookie-авторизацию, сессии и права, фактический
размер потока, rollback credentials, старый reset-token и гонку с logout.
Комментарии проверяются через REST с детерминированными барьерами; проверяются
уведомления, ответы, запрет воскресить удалённое и обе гонки текста/resolved.
Каталог сверяется после сохранения в БД по файлам, языкам, Go-коду и всем скрытым
проверкам. Миграции проходят up/down/up; длинные имена FK не скрывают настоящее
изменение `ON DELETE`.

## Go/frontend и ограничения проверки

Go, HTML/CSS, React и Next.js пока **не активированы на проде**: адрес и токен
runtime в работающем приложении не заданы, gateway не запущен. Подготовленные
образы не означают подключённый сервис. Новые задачи не публиковались до подключения.

401 относится к конкретному credential API **панели Dokploy**, SSH и LMS работают.
Значение apikey, выбранное из БД панели, API не принял. Для сохранения Environment
нужны действующий raw API key либо авторизованная панель; путь к локальному файлу —
лишь способ безопасно предоставить ключ. Прямая правка БД Dokploy и генерируемого
`.env` не использовалась. Kubernetes не менялся.

Замеры 12–18 секунд включали переход, загрузку документа, проверку гидратации
и готовность Monaco; это не время одного редактора. Во время загрузки Monaco
доступен textarea. HTTP-перехват QA отключает браузерный кеш, поэтому эти числа
не характеризуют обычные повторные переходы и не доказывают ускорение.
Обнаруженный лишний набор theme hints устранён, причина всей вариативности не установлена.

Next.js также дал один нестабильный timeout сложного 5-секундного сценария.
Отдельная инструментированная проверка прошла: холодный API-запрос включал
1,74 секунды компиляции, весь запрос — 2,06 секунды. Лимиты и проверки не ослаблялись;
точный этап прежнего timeout не установлен.

Финальные проверки исходников прошли: `pnpm smoke` (lint, typecheck, 3197 тестов
и Next build; 3 необязательных Redis-теста пропущены), `pnpm test:integration`
(1228/1228) и `pnpm test:integration:runtime` (17 + 25, без пропусков).
После исчезновения общего каталога зависимостей независимая установка с frozen
lockfile восстановлена в проверочном worktree; прерванные smoke/CMS-прогоны
повторены полностью. Версии зависимостей и lockfile не менялись.

Перед push коммит объединён с параллельными изменениями `fb85b42` (история обучения,
видео и ориентир main на экранах входа). Повторный `pnpm smoke` прошёл: 3231 тест,
3 необязательных Redis-теста пропущены, lint/typecheck/Next build успешны.
Объединённый CMS/API-набор: **1238/1238**, включая миграцию индекса истории.
В актуальном меню 15 пунктов: дополнительная «История обучения» идёт после

Результат последующего выката и повторной проверки хранится в локальных артефактах
