# Независимые решения Go и Python

Файлы написаны отдельно от `solutionCode*`. Тесты передают их серверному
`runSolution`, который вызывает HTTP gateway и настоящие Docker jobs. Используются
все канонические кейсы каталога, включая скрытые. Нет mock, skip или сверки текста
программы с эталоном для принятия решения.

| Задача | Отличие реализации |
| --- | --- |
| Go sum | Поток JSON tokens вместо декодирования массива |
| Go unique sorted | Сортировка исходного slice + `slices.Compact` вместо map |
| Go stable dedupe | Линейный поиск в готовом результате вместо map; максимум 64 строки |
| Go keyed counter | Сортировка событий и группировка соседей вместо агрегации map |
| Go snapshot | Копирование через append, правки исходного slice |
| Go fan-in | Индексированные buckets вместо сортировки; done channel вместо WaitGroup |
| Go worker pool | Буферизированная очередь индексов и явное ожидание завершений |
| Go context prefix | Отдельные producer/transformer с done channels вместо WaitGroup |
| Go ledger | Отсортированный slice счетов с бинарным поиском вместо map |
| Python Two Sum | Предварительные первые позиции и второй проход |
| Python unique substring | Deque + множество вместо таблицы последних позиций |
| Python intervals | Sweep по событиям открытия/закрытия вместо слияния интервалов |
| Python Top K | Min-heap по частоте вместо сортировки всех ключей |
| Python islands | Итеративный DFS и множество неизменяемых координат вместо BFS/mutable grid |
| Python anagrams | Частоты символов во frozenset вместо sorted string |
| Python brackets | Стек ожидаемых закрывающих символов вместо открывающих |
| Python subarray sum | Обратный проход по prefix sums и подсчёт будущих префиксов |
| Python RLE | `itertools.groupby` вместо изменения последней пары |

Дополнительно во время каждого запуска создаются три новых Go и три новых Python
программы с UUID в именах переменных, случайной эквивалентной арифметикой и новым
случайным вводом. Они отсутствуют среди заранее сохранённых исходников.
Негативные тесты демонстрируют: таблица открытых ответов проходит публичные
примеры, но отклоняется сервером на скрытых кейсах.

Проверки подтверждают независимость вердикта от эталонного текста. Конечный
набор тестов не доказывает корректность программы для абсолютно любого ввода.
В Go-задачах на concurrency поведение, завершение и порядок проверяются запуском;
конкретное использование каналов и отсутствие гонок требуют также ревью кода.
