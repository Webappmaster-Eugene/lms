# LMS MentorCareer: инструкции Codex

Отвечай по-русски. Работай до проверенного результата, учитывая текущий запрос.
Эти инструкции действуют и при открытии `107.lms`, и при открытии Git-репозитория `app`.
Определи репозиторий: текущая папка с `package.json` и `src/` либо её `app/`.
Все команды pnpm/git ниже выполняются из репозитория, не из родительской папки.

## Контекст и память

Перед изменениями прочитай `.codex/memory/MEMORY.md` и `.codex/context/CLAUDE.md`
относительно репозитория. Последний файл — полная синхронизируемая инструкция
Claude, а не сокращённый пересказ. Для архитектурных изменений дополнительно
прочитай `../expert_info/lms/project.md`, `conventions.md`, нужные `phases/`
и `checklists/`. Если внешние документы отсутствуют, используй копии в
`.codex/context/lms/`. Данные в коде и `package.json` приоритетнее устаревших
чисел и путей в документации.

Владелец разрешил локальные изменения, доступы, git-операции и необходимые
инструменты в проекте (2026-09-21). Не спрашивай повторно уже данное разрешение.
Push в `main` запускает выкат Dokploy: до push обязательны `pnpm smoke` и скилл
`deploy-check`. Изменения самого прода (перезапуск, деплой, правка `.env` на
сервере) требуют подтверждения пользователя. Не включай чужие изменения в
коммиты. Не запускай `force push`/`reset --hard` без конкретной необходимости
и разрешения. Не обходи ограничения управляющей среды.

## Скиллы и инструменты

Проектные скиллы находятся в `.agents/skills/`: `self-review`, `deploy-check`,
`prod-check`, `frontend-design`, `project-harness`. Вызывай их как `$self-review`.
Скиллы-адаптеры читают оригиналы в `.claude/skills/`: это единый источник
методологии. `$ARGUMENTS` в оригиналах означает текущий запрос или переданные
пути, не переменную shell. Недоступный инструмент не означает выполненную
проверку: назови точное ограничение. MCP из `.mcp.json` подключаются локальным
адаптером без переноса секретов в Git.

Роли `.codex/agents/` собраны из `../expert_info/lms/agents` с копией в
`.codex/context/lms/agents`. Делегируй только когда задача независима и это
оправдано; не запускай всех ревьюеров на каждое изменение. Роли наследуют
выбранную модель. Ревьюеры не редактируют проект; findings требуют severity,
confidence и сценария сбоя.

## Качество и зависимости

- Node 22+, TypeScript strict, ESM, одинарные кавычки, без точек с запятой,
  2 пробела, импорты через `@/`. `any`, non-null assertion и `console.log`
  запрещены линтером.
- Пакетный менеджер — pnpm 10 (обычно через corepack). `landing/` — отдельный
  npm-пакет со своим lockfile; не ставь его зависимости через pnpm.
- Server components по умолчанию; `'use client'` только при необходимости.
  Секреты и прямые вызовы Payload в клиент не попадают.
- Новая коллекция Payload имеет явный `access`; route handler проверяет
  `payload.auth()` и владельца объекта до записи.
- Изменение схемы = миграция (`pnpm payload migrate:create`) + экспорт из
  `src/migrations/index.ts`. Миграции применяются на старте контейнера, поэтому
  совместимость обязательна: схема expand-contract.
- Хук, пишущий в коллекцию с собственным хуком, передаёт `context: { skipHooks: true }`.
  Составные операции — в одной транзакции через `req`.
- Генерируемые файлы не редактируются: `src/payload-types.ts`, `importMap.js`,
  `src/lib/trainer/harness-source.generated.ts`, `public/monaco/**`.
- Результат клиентского прогона тренажёра не влияет на прогресс: источник истины —
  серверная проверка в изоляте.
- После изменений выполни self-review и относящиеся проверки: `pnpm lint`,
  `pnpm typecheck`, `pnpm test`. `pnpm build` требует `DATABASE_URL` и
  `PAYLOAD_SECRET`; без них отмечай пропуск явно.
- `pnpm codex:verify` запускает полный локальный набор: тесты harness, lint,
  typecheck, тесты, сборку приложения и сборку лендинга. Для изменения только
  harness достаточно `pnpm codex:test`, `pnpm codex:doctor` и `pnpm lint`.

## Завершение и продолжение

В итоговом ответе: результат, выполненные проверки, реальные ограничения.
Долгоживущие факты и исправленные заблуждения записывай в `.codex/memory/MEMORY.md`
со ссылкой на источник и датой. Ход незавершённой задачи — в `.codex/state/handoff.md`:
цель, сделано, следующий шаг, проверки, блокеры. Обновляй перед compaction/остановкой.
Не сохраняй токены, пароли, содержимое `.env` и полные логи в памяти.
SessionStart восстанавливает память, Stop проверяет drift и whitespace; это не
замена тестам. После изменения Claude-инфраструктуры: `pnpm codex:sync`.
